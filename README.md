# Bilibili 直播弹幕点歌助手

当前版本：`1.1.0`

这是一个运行在主播电脑本地的 Bilibili 直播弹幕点歌助手。观众在直播间发送弹幕点歌后，程序把歌曲加入本地点歌队列，并通过直播姬或 OBS 的网页源显示到直播画面里。

数据只保存在本机，不需要云服务器、云数据库、公网域名或固定月费。

## 项目结构

- `start.bat`：Windows 一键启动入口。
- `stop.bat`：Windows 兜底停止入口。
- `src/server.js`：本地 Node.js 后端，负责 HTTP 接口、SQLite 数据库、Bilibili 弹幕监听（含历史补偿、SC、礼物）、WebSocket 推送、Excel 导入导出（含完整 .xlsx 读写）、WBI 签名、Protobuf 解析、性能检测和优雅退出。
- `src/electron/main.js`、`src/electron/preload.js`：Windows 桌面版入口，负责打开管理页、管理本地数据目录和 GitHub Releases 自动更新。
- `scripts/create-icon.js`：生成桌面版红金配色图标。
- `public/admin.html`、`public/admin.js`：主播管理页（队列、SC、歌库、设置、主题、礼物冲刺、性能检测）。
- `public/overlay-queue.html`、`public/overlay-queue.js`：直播画面里的点歌队列板（两种风格）。
- `public/overlay-songs.html`、`public/overlay-songs.js`：直播画面里的歌曲展示板（多种排序）。
- `public/styles.css`：管理页和 overlay 共用样式。
- `data/song-request-data.db`：运行后自动生成的点歌 SQLite 数据库。
- `data/super-chat-data.db`：运行后自动生成的 SC SQLite 数据库。
- `data/gift-data.db`：运行后自动生成的礼物 SQLite 数据库。

## 怎么启动

桌面版方式：安装 `release/bilibili-live-song-plugin-setup-1.1.0.exe` 后，从桌面快捷方式或开始菜单打开“点歌助手”。桌面版会把数据库保存在系统用户数据目录，更新安装包不会清空歌库。

推荐方式：双击项目里的：

```text
start.bat
```

它会检查 Node.js，启动本地服务，并自动打开管理页。

如果提示没有 Node.js，需要先安装 Node.js 24 或更新版本：

```text
https://nodejs.org/
```

命令行备用方式：

```powershell
npm.cmd start
```

启动成功后打开管理页：

```text
http://127.0.0.1:3000/admin
```

如果 `3000` 被占用，程序会自动尝试 `3001` 到 `3019`。实际地址会打印在启动窗口里。

## 怎么退出

直播结束后，优先在管理页右上角点击"退出程序"。后端会关闭本地服务、断开实时连接、关闭数据库连接并释放端口。

如果页面打不开或启动窗口找不到，可以双击：

```text
stop.bat
```

它会扫描 `3000-3019`，找到属于当前项目的本地服务并停止。

## 直播画面地址

管理页的"直播画面"页会显示两个网页源地址。

点歌板：

```text
http://localhost:3000/queue
```

歌曲展示板：

```text
http://localhost:3000/songlist
```

按分类展示歌曲：

```text
http://localhost:3000/songlist?category=古风
```

如果服务实际运行在 `3003`，就把上面的端口换成 `3003`。

## 日常使用流程

1. 启动本地服务。
2. 打开管理页。
3. 在歌库里导入或新增歌曲。
4. 在设置里填写 Bilibili 直播间号或直播间链接，并启用 Bilibili 监听。
5. 在"直播画面"页复制点歌板和歌曲展示板地址，加入直播姬或 OBS 网页源。
6. 在真实直播间发送 `点歌 晴天`、`随机点歌` 或 `随机点歌 周杰伦` 验证队列变化。
7. 直播中使用管理页处理切歌、置顶、删除、清空队列等操作。

## 歌单导入

支持三种导入方式：

- 下载 Excel 模板 `.xlsx`，填好后导入。
- 从 Excel 另存为 CSV/TSV 后导入。
- 直接从 Excel 复制表格，粘贴到导入框。

推荐表头：

```text
歌曲名字 | 歌手 | 歌曲分类 | 备注 | 标签 | 是否可点 | 语言 | 来源平台 | 原始分组
```

`歌曲名字` 必填。`是否可点` 可以填 `是` 或 `否`。其他字段可以为空。

兼容的常见别名：

- 歌曲名：`歌曲名字`、`歌曲名称`、`歌名`、`曲名`
- 分类：`歌曲分类`、`类别`、`分类`、`分组`
- 歌手：`歌手`、`演唱者`、`原唱`
- 标签：`标签`、`歌曲标签`
- 是否可点：`是否可点`、`可点`、`是否启用`

不带表头时，默认按 9 列顺序读取。

## 性能与低占用

管理页有"性能检测"页，可以采样最近 5 秒的 CPU、GPU 和内存使用率。

前台 overlay 的主要性能风险来自透明网页源里的毛玻璃、发光、重阴影和大面积实时合成。当前提供"前台低占用模式"开关：

- 默认关闭，保留原视觉效果。
- 开启后，点歌板和歌曲展示板会关闭实时毛玻璃、发光和重阴影。
- 滚动动画保持原来的 CSS 顺滑滚动，不做低帧率步进。

这个开关在管理页"点歌板" → "玻璃质感效果"区域。

## Bilibili 连接说明

在管理页设置里填写 Bilibili 直播间号或链接：

```text
123456
https://live.bilibili.com/123456
```

不要填写主播 UID、昵称或个人主页 ID。

如果提示 `-352` 或接口失败，一般是 B 站风控、签名或网络问题，不是歌库或点歌逻辑问题。启动窗口会输出接口名、HTTP 状态、B 站错误码和可能原因。

未开播时，B 站公开弹幕长连不一定推送右侧聊天区消息；程序会额外低频读取最近聊天记录，捕捉 `点歌` 和 `随机` 指令。这类来源在管理页里会显示为历史补偿。

## 技术实现亮点

- **服务核心零依赖**：本地 HTTP 服务仅使用 Node.js 内置模块（`node:http`、`node:sqlite`、`node:zlib`、`node:crypto` 等）；桌面版打包需要 Electron 相关 npm 依赖。
- **完整 .xlsx 读写**：自实现 ZIP 解析和 OpenXML 生成，不依赖第三方 Excel 库。
- **Bilibili 协议**：自实现 WebSocket 帧、Brotli/Zlib 解压、WBI 签名、Protobuf 盲盒礼物解析。
- **三库分离**：点歌、SC、礼物流水独立 SQLite 文件，互不干扰。
- **事件驱动**：WebSocket 推送采用状态快照模式，前端断线重连后自动同步。

## 当前边界

- 已支持 Windows `.exe` 安装包；源码命令行运行仍需要安装 Node.js 24+。
- 第一版不自动播放音乐。
- 第一版不控制全民 K 歌。
- 第一版不下载、不转码音频。
- Bilibili 弹幕监听依赖平台公开接口和当前网络环境，稳定性需要继续实测。
- 启动会清空上次遗留的当前点歌和等待队列（设计选择：避免重启后状态不一致）。
- 数据库自动备份和恢复入口还没有完整做完。
- 日志查看、日志大小控制和长期运行内存曲线还没有完整做完。
