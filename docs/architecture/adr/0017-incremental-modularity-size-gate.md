# ADR-0017: 渐进执行源码规模门禁

## Status

Accepted — 2026-09-13。用户要求实施客户端模块化复审报告的批次 D。

## Context

[复审报告](../../client-modularity-reassessment-2026-09-13.md)将普通人工维护源码纳入 600/800 行规则，现有模块化规范仍只有生产 JavaScript 的 800 行软审查线。既有 CSS、HTML、测试及大型状态工厂需要逐步收敛，不能为通过数值门禁分散资源、事务或授权状态，也不能删测试断言。

## Decision

- 用已有 Node 测试链执行无依赖的物理行数门禁。具体扫描范围、计数及格式化口径以[模块化规范](../engineering/modularity-standard.md)为唯一规则来源。
- 601–800 行需要逐文件评估；新普通源码不得超过 800 行。存量超限用当前工作区行数冻结，按明确职责渐进提取，不新增独立职责。
- [机器基线](../engineering/modularity-baseline.json)记录文件、类别、上限、所有者、原因、整改/撤销条件、复审期限及保护测试。禁止通配目录例外、自动重新生成预算和无理由提高存量上限。机器校验不代替评审。
- 测试采用单独的场景与整合契约政策；默认行数上限相同，只允许经评审的逐文件放宽。所有测试和 HTML 均不整体豁免。
- 接受主题预设 JSON 的纯数据例外，以及帮助正文 HTML 的静态内容例外。后者是对静态数据条款的明确扩展；不延伸到业务表单。两者仍有上限及复审期限。
- 长函数、复杂度和嵌套规则先作为明确的评审义务；[函数债务](../engineering/modularity-debt.md)给出已知项及处理条件。此批次不宣称全面函数合规，不为数字拆分大型状态工厂或改写历史 SQL。

## Alternatives And Consequences

继续只写软审查线无法阻止新增超限。立即把所有存量卡死会诱发机械切文件或删除测试。采用冻结基线使现有代码可验证，同时要求新增职责有清晰归属。

扫描器读取存储文本，不增加 Prettier 或 AST 依赖；格式化和语义职责仍需要人工评审。复审期限到期会使门禁失败，届时必须先检查当前职责、规模与退出条件再续期。历史报告保留历史计数，当前基线不从旧表直接复制。运行时与打包内容不变。

## Verification

[modularity-size.test.js](../../../test/modularity-size.test.js)使用临时源码树验证阈值、换行、源码类型、未跟踪文件、精确例外、增长、过期和无效登记，并运行当前仓库基线。`verify:architecture` 和默认测试发现均包含此测试。
