# ADR-0017: 渐进执行源码规模检查

## 状态

已采纳（2026-09-13，落地客户端模块化复审报告批次 D 方案）

2026-10-04：文件行数硬上限、逐文件额度冻结及到期登记政策已由 [ADR-0023](0023-purpose-aware-file-size-review.md) 替代。以下保留原采纳结论，现行规则见 [文件规模评审](../engineering/modularity-standard.md#file-size-review)。

## 背景

[模块化复审报告](../../reports/2026-09-13-client-modularity-reassessment.md) 将人工维护的常规源码纳入 600/800 行关注范围，而当时规范仅覆盖生产 JavaScript 的 800 行软评审线。既有 CSS、HTML、测试及大型状态工厂需要逐步收敛，但不能为了凑行数而把资源、事务或授权状态强行拆散，也不能删减测试断言。

## 决策

- 基于现有 Node 测试链路执行不引入第三方依赖的物理行数检查，扫描范围、计数方式与格式化口径以 [模块化规范](../engineering/modularity-standard.md) 为单一事实来源。
- 601–800 行须逐文件评审，新增普通源码不超过 800 行；既有超限文件按当时工作区行数冻结，按独立职责渐进抽离，不再向其中堆叠新职责。
- [机器基线](../engineering/modularity-baseline.json) 记录文件路径、类别、上限、归属人、保留原因、退出条件、复审期限与保护测试。禁止按目录通配豁免、自动重算行数上限或无理由放宽存量额度；机器检查不能替代人工评审。
- 测试文件采用独立的场景与集成规范，默认行数上限相同，仅允许经评审的逐文件放宽；不对测试或 HTML 整体豁免。
- 接受主题预设 JSON 的纯数据例外及帮助正文 HTML 的静态内容例外（不延伸至业务表单），二者仍受上限与复审期限约束。
- 长函数、复杂度与嵌套深度先作为明确评审义务，在 [模块化债务](../engineering/modularity-debt.md) 登记已知项与处理条件；本阶段不要求全库函数一次达标，也不为凑数字强行拆分大型状态工厂或改写历史 SQL。

## 备选方案与影响

继续仅靠文字软规范无法阻止新增大文件；若立刻卡死全部存量，则会诱发机械切分文件或删减测试。冻结基线使存量规模变得可验证，同时推动新增职责落在清晰边界内。

扫描器直接统计磁盘文本，不增加 Prettier 或 AST 依赖，格式化与语义内聚仍依赖人工评审。复审期限到期将触发检查失败，续期前必须先复核职责、规模与退出条件。历史报告保留原计数快照，基线不从旧表直接抄录；运行时行为与安装包内容不变。

## 验证

[modularity-size.test.js](../../../test/engineering/modularity-size.test.js) 使用临时源码树验证阈值、换行符、源码类型、未跟踪文件、精确例外、增长、过期与非法登记，并校验当前仓库基线；`verify:architecture` 与默认测试发现均包含该套件。
