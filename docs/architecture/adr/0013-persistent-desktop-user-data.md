# ADR-0013: 桌面用户数据独立于安装目录持久化

## Status

Accepted

## Context

LIRA 打包版曾把 Electron `userData`、五个 SQLite 数据库、认证快照和缓存统一
放在 `<安装目录>/data`。NSIS 升级会替换安装目录，旧卸载钩子还会清理
`%APPDATA%/LIRA`，因此已经成功导入的歌曲可能在软件更新后消失。

用户数据必须跨普通升级保留；迁移不能覆盖已经初始化的新目录，失败时不能让应用
以空数据库继续启动。旧版卸载器的行为已经写进已发布安装包，无法由新版代码修改。

## Decision

打包版使用 `%APPDATA%/com.aurorawhisperer.lira/data` 作为稳定 `userData` 和业务数据根；
开发版继续使用仓库根 `data/`。新路径避开旧卸载器固定删除的
`%APPDATA%/LIRA`。

迁移有两道兼容桥：

```mermaid
flowchart LR
  A[旧版安装目录 data] -->|新安装器 customInit| B[同卷临时目录]
  B -->|复制成功后 rename| C[%APPDATA%/com.aurorawhisperer.lira/data]
  C --> D[新版 Electron 与内嵌服务]
  A -. 手工替换等场景 .->|启动前原子迁移| C
```

- 新安装器在调用旧卸载器前，将旧目录完整复制到新路径旁的临时目录；成功后重命名
  发布，失败则中止安装，旧目录不动。
- 新版 Electron 启动时执行同样的一次性兼容迁移，覆盖未经过 NSIS 的手工替换场景。
- 新路径一旦存在即为权威数据，旧目录不再覆盖它。
- 新卸载器不删除持久化目录。清库仍只能通过应用内已有的显式操作完成。

## Alternatives Considered

- **继续使用安装目录并在每次更新时备份恢复**：每次升级都依赖安装器搬运，安装路径
  变化和失败窗口更大，拒绝。
- **改回 `%APPDATA%/LIRA`**：符合 Electron 常见默认值，但第一次升级会被已发布旧
  卸载器删除，无法安全过渡，拒绝。
- **只在新版首次启动迁移**：更新过程可能已经删除旧安装目录，启动时没有源数据可迁，
  拒绝。
- **依赖云端歌单恢复**：离线用户和未完成同步的数据不受保障，且不能恢复其他本地
  设置与历史，拒绝。

## Consequences

### Positive

- 数据生命周期与程序文件生命周期分离，普通更新不再删除歌单。
- 整目录迁移保留数据库、认证快照、Chromium 分区和用户上传资源的现有布局。
- 不改变数据库 schema、文件名、HTTP/IPC/WS 契约或 renderer 权限。

### Negative

- 显式卸载后会保留用户数据，需要用户通过应用内清库或手工删除才能彻底清除。
- 首次迁移会按数据目录大小增加一次复制时间和等量临时磁盘占用。
- 已被旧更新删除且没有备份或云端副本的数据无法由本变更恢复。

## Failure Modes And Mitigations

- 复制失败：不发布目标目录并中止升级/启动，保留旧源。
- 迁移中断：只留下可识别的临时目录；下次迁移先清理该临时目录后重试。
- 新旧目录同时存在：新目录优先，避免陈旧源覆盖较新的用户数据。
- 旧卸载器执行：新路径不位于其删除范围内。
