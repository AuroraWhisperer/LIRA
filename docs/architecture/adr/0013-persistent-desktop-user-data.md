# ADR-0013: 桌面用户数据独立于安装目录持久化

## 状态

已替代（2026-09-13 由 [ADR-0015](0015-install-local-desktop-data.md) 替代）

现行方案改为将客户端全部数据保存在用户选定的安装目录内（有 D 盘时新装默认优先 D 盘），但“跨常规升级保留用户数据”的核心要求仍然有效。以下为当时的历史方案记录。

## 背景

LIRA 打包版曾把 Electron `userData`、五个 SQLite 数据库、认证快照与缓存统一放在 `<安装目录>/data`。NSIS 升级会替换安装目录，旧卸载钩子还会清理 `%APPDATA%/LIRA`，导致用户已导入的歌单在软件更新后丢失。

用户数据必须跨普通升级保留；迁移不得覆盖已初始化的新目录，失败时也不得让应用以空数据库继续启动。旧版卸载器逻辑已固化在已发布安装包中，新版代码无法事后修改。

## 决策

打包版采用 `%APPDATA%/com.aurorawhisperer.lira/data` 作为固定的 `userData` 与业务数据根目录；开发版继续使用仓库根目录 `data/`。新路径避开旧卸载器固定删除的 `%APPDATA%/LIRA`。

迁移设置两道兼容保障：

```mermaid
flowchart LR
  A[旧版安装目录 data] -->|新安装器 customInit| B[同卷临时目录]
  B -->|复制成功后原子重命名| C[%APPDATA%/com.aurorawhisperer.lira/data]
  C --> D[新版 Electron 与内嵌服务]
  A -. 手工替换等场景 .->|启动前原子迁移| C
```

- 新安装器在调用旧卸载器前，将旧目录完整复制到新路径旁的临时目录；复制成功后原子重命名为正式目录，失败则中止安装并保持旧目录不动。
- 新版 Electron 启动时执行同样的一次性兼容迁移，覆盖未经 NSIS 的手工替换场景。
- 新路径一旦存在即作为权威数据，旧目录不再覆盖新路径。
- 新卸载器不删除持久化目录，清库仍只能通过应用内显式操作完成。

## 备选方案

- **继续使用安装目录并在每次更新时备份恢复**：每次升级都依赖安装器搬运，路径变化与失败窗口更大，故否决。
- **改回 `%APPDATA%/LIRA`**：虽符合 Electron 常见默认值，但首次升级会被已发布的旧卸载器删除，无法安全过渡，故否决。
- **仅在新版首次启动时迁移**：升级过程中旧安装目录可能已被删除，启动时无源可迁，故否决。
- **依赖云端歌单恢复**：无法保障离线用户与未完成同步的数据，也不能恢复其他本地设置与历史记录，故否决。

## 影响

### 正面影响

- 数据生命周期与程序文件生命周期解耦，普通更新不再误删歌单。
- 整目录迁移保留数据库、认证快照、Chromium 分区与用户上传资源的既有布局。
- 不改变数据库表结构、文件名、HTTP/IPC/WS 接口约定或渲染进程权限。

### 代价

- 显式卸载后会保留用户数据，彻底清除需通过应用内清库或手工删除。
- 首次迁移会按数据目录体积增加一次复制耗时与等量临时磁盘占用。
- 已被旧版更新误删且无备份或云端副本的数据无法由本变更找回。

## 故障与应对

- **复制失败**：不启用目标目录并中止升级或启动，完整保留旧源目录。
- **迁移中断**：仅遗留可识别的临时目录，下次迁移先清理该临时目录再重试。
- **新旧目录并存**：以新目录为准，防止旧数据覆盖较新的用户数据。
- **旧卸载器执行**：新路径位于其清理范围之外。
