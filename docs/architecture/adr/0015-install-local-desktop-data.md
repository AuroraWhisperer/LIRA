# ADR-0015: 安装目录保存桌面数据

## Status

Accepted — 2026-09-13，来自用户明确要求；替代 ADR-0013 的 AppData 路径决策。

内部浏览器与缓存布局随后由 [ADR-0016](0016-separated-client-data-lifecycles.md) 细化；安装级数据保留与恢复规则继续有效。

## Context

用户要求客户端数据跟随每个人实际选择的安装目录，首次安装有 D 盘时优先使用 D 盘，无 D 盘时保留原默认安装位置。返回的 Windows 10 诊断报告显示，安装器在旧版仍运行时复制 Chromium Cookies，得到共享冲突 32、robocopy 返回码 9；`customInit` 发生在标准安装器的退出检查之前。这是已经确认的故障，不是缺少 Electron 文件的证据。

## Decision

- 程序与数据使用同一安装目录：首次安装检测到 D 盘时默认 `D:\LIRA`，未检测到则保留 builder 原默认目录。升级沿用本机已有路径，显式 `/D` 和目录页选择优先，不限制盘符。
- 数据库、配置、加密登录资料、机器授权资料、上传资源及 Chromium 分区保持在 `data/`；运行日志在 `logs/`；更新缓存和已下载安装器在 `updates/lira-updater/`；崩溃转储在 `data/Crashpad/`。开发模式保持仓库 `data/`。
- 安装器先确认旧 LIRA 退出，再完整备份到新安装目录的同级 `.lira-data-backup` 目录，成功后才执行旧卸载器。恢复成功后才启动新版；升级调用卸载器时保留数据、日志和更新缓存。
- 根据用户后续明确要求，普通卸载删除程序、`logs/` 和 `updates/`，默认保留完整 `data/`。卸载页提供默认不勾选的“同时删除用户数据”；仅交互勾选并再次确认后，才删除当前安装数据及当前用户已知的旧版 AppData 数据，防止重装重新导入。拒绝确认继续卸载但保留数据；静默卸载保留数据，升级始终保留三个运行目录。手工备份、同级安装恢复备份与云端数据不在清理范围内。
- `.partial` 只表示未发布副本，不能用于恢复；已发布备份不自动覆盖。有原数据与备份冲突、目标目录冲突或复制失败时中止并留下可报告的信息。
- 历史 AppData 目录仅作为本地数据不存在时的兼容来源，完整复制后使用本地目录，保留历史源。已有本地数据不被历史副本覆盖。
- 保留 appId、更新源、数据库结构、会话分区和 `safeStorage` 加密。机器绑定无需把授权文件保存在 C 盘。

## Consequences

用户可以在安装目录统一备份、管理数据，普通升级保留数据，卸载默认保留数据并允许用户显式清除。升级备份需要等量额外磁盘空间；旧数据被锁住时需先退出旧客户端。中断后若恢复备份与活动数据同时存在，需要根据报告人工确认，不能猜测并覆盖。

Windows 注册表、安装器解压及诊断使用的系统临时文件仍由系统路径管理；该决策约束客户端持久存储，无法保证 Windows 自身完全不写系统盘。卸载保留的 `data/` 包含用户资料；选择删除时会清理 `%APPDATA%/com.aurorawhisperer.lira` 与 `%APPDATA%/lira` 这两个已知兼容来源，其他应用目录不受影响。删除不会跟随目录链接，失败时报告未清理的路径并保留卸载程序用于重试。远端 Windows 10 的最终安装结果需要实际用户反馈。
