# ADR-0007: 渐进收敛显式模块边界

## 状态

已采纳（注：下文所述的 Admin 单一桥接层已于 2026-11-06 彻底退役，现行收敛进度见 [遗留边界登记表](../engineering/legacy-boundaries.md)）

## 背景

LIRA 虽已按目录划分为模块化单体，但部分边界仍依赖宽泛的编排对象、浏览器全局对象、直连 SQLite 句柄以及被大量模块依赖的工具聚合文件。由于既有行为测试覆盖充分，一次性重写回归影响面过大，也不符合本地单机桌面应用的定位。

## 决策

继续保持模块化单体形态，通过渐进式边界收敛逐步降低耦合：

- 组合根只负责装配运行时实例、端口与适配器。
- 领域服务通过专用存储接口（store/repository）访问持久化层。
- Admin 遗留的全局对象先收口至单一桥接层，新代码一律使用 ES modules。
- 播放器工厂只接收实际需要的依赖，移除泛化的 `sharedDeps` 对象。
- 通用工具按单一主题拆分，并用结构回归测试守护依赖方向。

每次迁移均保持 HTTP、WebSocket、IPC、数据库与页面行为兼容，并由既有测试套验证。

## 影响

### 正面影响

- 模块依赖从源码直接可见，改动影响范围更收敛。
- 领域服务可借助轻量假存储执行更快的单元测试。
- 遗留全局对象的清理有了明确收口点，无需推倒重来。
- 架构边界由自动化架构适应度函数持续保护。

### 代价

- 迁移过渡期内会同时存在新接口与受控兼容适配器。
- 装配代码会增加少量显式参数和门面文件。
- 旧测试中依赖源码文本或全局对象的断言需要同步调整。

### 中性影响

- 运行进程、监听端口、数据文件、部署方式与第三方依赖数量保持不变。

## 备选方案

**一次性重写前端或引入前端框架**

- 否决：回归影响面过大，且当前原生 JavaScript 架构并无框架级刚需。

**引入通用依赖注入（DI）容器**

- 否决：现有规模下显式工厂参数更直观透明；未真正承担服务解析职责的容器只会徒增间接层。

**继续直接传递数据库上下文对象**

- 否决：表结构会持续泄漏到领域层，无法建立稳定的持久化边界。

**拆分为微服务**

- 否决：本地单用户桌面应用不需要额外的网络边界和部署复杂度。
