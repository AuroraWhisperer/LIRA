# ADR-0009: 首次启动配置引导

## Status

Proposed

## Context

LIRA 目前把 Bilibili 登录、直播间号、歌单导入、音乐平台登录和 AI 配置分散在不同页面。新用户需要自行发现这些入口，容易在未登录、未填写房间号或没有歌库的情况下开始直播。

用户需要一个首次启动时出现的多步骤配置向导：当前步骤必须满足可验证条件后才能进入下一步；完成后不再自动出现，但可以从使用文档重新打开。LIRA 是本地模块化单体，已有 Electron 登录窗口、加密 Cookie 快照、设置存储和 Admin 页面组合，不能通过引导层复制或读取账号凭据。

## Decision

在现有 Admin 页面中增加一个首次启动引导控制器和遮罩层，不新增进程、HTTP 路由、IPC 通道或前端构建步骤。

引导使用现有能力：

- Bilibili 状态和扫码登录使用 `window.bilibiliAuth`。
- QQ 音乐和网易云音乐状态、登录使用 `window.musicAPI`。
- 直播间号和引导状态使用现有 `POST /api/settings`；服务端仍通过设置白名单和 `normalizeRoomInput` 处理输入。
- DeepSeek 配置使用现有 `/api/ai/config` 和 `/api/ai/test/deepseek`，API Key 只提交给现有密钥存储，不进入 WebSocket 全局状态或引导日志。
- 歌单导入复用点歌页已有的「导入导出」标签页和导入接口，引导只负责说明入口和操作顺序，不复制文件解析逻辑。

引导步骤固定为：

1. 欢迎与运行模式说明。
2. Bilibili 登录和直播间号：必做。下一步要求桌面环境、Bilibili `loggedIn === true`、房间号通过现有接口保存且直播连接状态已刷新。
3. 导入歌单：说明进入「点歌 → 导入导出」，选择 XLSX/CSV/TSV 文件或粘贴表格，再点击「导入歌库」。
4. 音乐平台登录位置：用户选择需要的平台。QQ 音乐、网易云音乐在 LIRA「播放」页顶部对应平台内置登录；全民 K 歌必须在全民 K 歌宿主客户端登录，LIRA 只读取本机播放状态，不提供全民账号登录。此步骤只做位置说明，不强制用户登录平台。
5. AI 弹幕姬：可选。用户开启 AI 时必须填写并测试 DeepSeek 配置；不启用时可以跳过。
6. 说明文档位置：告诉用户在「百宝箱 → 使用文档」查看完整功能说明、导入/登录细节和常见问题；该页面也可以重新打开首次启动引导。
7. 完成：显示仍未完成的可选项，写入完成版本和时间。

闸门由纯函数计算，按钮状态由 DOM 控制：未满足条件时“下一步”禁用；异步保存和连接测试期间显示进行中状态并禁止重复提交；失败保留当前步骤和可理解错误。用户可以点击“稍后设置”跳过 AI，不能跳过 Bilibili 基础配置、歌单导入说明、音乐平台登录位置说明和说明文档位置。已完成的引导不会因普通页面刷新再次出现。

## State And Persistence

在 `src/storage/settings-store.js` 增加以下普通设置键，沿用现有字符串设置格式：

- `onboardingVersion`: 当前引导契约版本，例如 `1`；空值表示从未完成。
- `onboardingCompletedAt`: ISO 时间字符串；仅在完成步骤后写入。
- `onboardingSkippedOptional`: 逗号分隔的可选步骤 ID（当前只有 `ai`），便于重新打开时显示未完成提醒。

引导当前步骤只保存在浏览器内存，不写入设置，避免异常退出后产生错误的“已完成”状态。清空业务数据库时保留设置的现有行为不变；“重新开始引导”只清除上述三个键，不清除账号 Cookie、歌曲、队列或 AI 密钥。

## Consequences

### Positive

- 新用户按可验证路线完成最小可用配置，减少“能打开但不能直播”的情况。
- 复用现有登录和密钥边界，凭据仍由 Electron 分区、`safeStorage` 和现有服务持有。
- 不改变现有公共 URL、API、IPC、WebSocket 或数据库表结构。
- 纯函数闸门可在没有 Electron 的 Node 测试中稳定验证。

### Negative

- 首次启动会增加一个遮罩层和若干状态轮询/刷新请求。
- Web 模式无法提供桌面扫码登录，必须显示受限状态并允许用户进入后台处理，而不能假装登录成功。
- 歌单是否已导入由用户确认，向导不复制导入解析逻辑，也不替用户修改歌库内容。

## Alternatives Considered

- **独立 Electron 设置窗口**：会复制 Admin 表单和状态逻辑，增加窗口生命周期与 IPC 面积，拒绝。
- **只做静态产品导览**：无法验证登录、房间号和 AI 测试，不能满足“完成当前操作才能下一步”，拒绝。
- **新增 onboarding HTTP API**：现有设置 API 已有白名单、鉴权和广播机制，新增端点没有实际边界收益，拒绝。
- **把引导状态放 localStorage**：服务端和多个窗口无法共享，卸载/迁移行为也不一致；只用于临时当前步骤，不用于完成状态。
