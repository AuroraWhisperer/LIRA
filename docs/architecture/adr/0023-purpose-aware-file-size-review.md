# ADR-0023: 按文件类型、职责与用途评审规模

## Status

Accepted — 2026-10-04。用户要求灵活判断文件规模，不强行为行数拆文件。替代 [ADR-0017](0017-incremental-modularity-size-gate.md) 的硬上限、精确额度冻结与到期登记政策。

## Context

统一的 600/800 行门禁把业务逻辑、CSS、测试与数据按同一种复杂度处理。单一页面样式的小幅增长也需要重新登记，容易诱发机械拆分，分散级联关系或状态所有权。

## Decision

- 行数只提供审查信号。具体类型、提示线和判断方法统一维护在[模块化规范](../engineering/modularity-standard.md#file-size-review)，不把阈值当成自动拆分或拒绝条件。
- 对本次变更涉及的较大文件，在正常审查中说明用途、职责内聚性、保留或拆分理由及验证；无需单独的行数批准、逐行额度或到期登记。
- 现有检查命令保留，输出按类型分类的提示，扫描成功即可通过。计数与报告行为有回归测试；依赖、安全、存储、生命周期和静态内容边界继续独立验证。
- 旧基线保留为标明历史状态的快照，检查器不再读取。已知语义债务在相关修改时复核，不因数字变化自动新增或消失。

## Alternatives And Consequences

仅提高上限仍会把不同用途套进同一数字；完全删除报告则失去低成本的定位线索。采用提示加语义审查，允许完整样式、场景和数据自然组织，同时要求审查真实维护问题。机器不能证明内聚性，短文件也不能据此豁免边界规则。

本次不批量拆分现有实现，不改变运行时、数据格式或外部契约。服务端采用同样原则，在各自仓库维护本地检查，避免跨仓运行时依赖。

## Verification

[规模报告测试](../../../test/engineering/modularity-size.test.js)覆盖物理行计数、不同文件用途、未跟踪源码、超过提示线仍成功及静态内容边界；架构与文档检查继续运行。
