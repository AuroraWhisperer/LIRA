# ADR-0023: 按文件类型、职责与用途评审规模

## 状态

已采纳（2026-10-04）

改为按文件实际职责灵活评估规模，不再为了满足行数上限强行拆分文件；替代 [ADR-0017](0017-incremental-modularity-size-gate.md) 的硬上限、逐文件额度冻结与到期登记机制。

## 背景

统一的 600/800 行硬性限制将业务逻辑、CSS、测试与纯数据按同一种复杂度对待，单一页面样式的小幅增长也需要反复登记续期，容易诱发机械拆分，反而打散层叠顺序或状态归属。

## 决策

- 行数仅作为评审信号：具体文件分类、提示线与判断口径统一维护在 [文件规模评审](../engineering/modularity-standard.md#file-size-review)，不把阈值当作自动拆分或拒绝合入的条件。
- 变更涉及较大文件时，在常规评审中说明文件用途、职责内聚性、保留或拆分理由及验证即可，不再单独设立行数审批、逐行额度或到期登记。
- 保留现有扫描命令，按文件类型输出提示信息，扫描完成即返回成功；计数与报告逻辑保持回归测试，依赖方向、安全、存储、生命周期与静态内容边界继续独立校验。
- 旧基线文件保留为历史快照，扫描器不再读取；已知语义债务在相关改动时复核，不因行数波动自动新增或消除。

## 备选方案与影响

仅提高硬上限仍会用同一标尺衡量不同用途的文件；完全移除报告则会失去低成本的定位信号。采用“行数提示 + 人工语义评审”的方式，既允许完整样式表、测试场景与数据文件按业务逻辑自然组织，又要求在评审中关注真实的维护性问题。自动化扫描无法判定代码是否内聚，短文件同样必须遵守架构边界规范。

本次调整不批量拆分现有代码，不改变运行时行为、数据格式或外部接口；服务端遵循相同原则，在各自仓库内独立检查，避免跨仓运行时依赖。

## 验证

[modularity-size.test.js](../../../test/engineering/modularity-size.test.js) 覆盖物理行计数、多文件类型、未跟踪源码、超提示线仍成功以及静态内容边界；架构与文档检查继续运行。
