# ADR-0018: 统一日志事件与两端诊断入口

## Status

Accepted — 2026-09-14。用户要求按专项报告开始调整；先实施阶段 A1 的源头降噪和本地适配器容量保护。统一分流轮转、故障上下文、诊断页面、服务器仓库及生产部署仍按后续计划推进，当前未部署。

## Context

客户端已有 desktop/terminal/AI 日志，但格式、脱敏和保留行为不统一；terminal 与 AI 初始化覆盖旧记录。服务器有 JSON console logger、PM2 和管理操作审计，却缺少管理员可查的运行问题与客户端报告。

目标是让用户保存/提交诊断、让管理员统一排查与追踪修复。保持安装级 logs、Electron 安全、现有租户/凭据/礼物隐私规范以及两边模块化单体的边界。

现状证据、数据分类、目录、接口职责、风险和验收维护于 [设计规格](../../../specs/client-server-logging-design.md)；正常增长、精简、具体配额及已核实的宝塔/PM2 部署配置见 [专项报告](../../reports/2026-09-14-log-volume-and-signal-report.md)。本 ADR 不重复定义字段或限额。

## Proposed decisions

1. **格式统一，写入按宿主管理。** 使用版本化 JSON Lines 与相同的事件、严重程度、关联语义；两个仓库保留各自适配器与组合根，不跨仓库 require 源文件。先增强现有 logger，不新增运行依赖、服务或框架。
2. **诊断与审计分离。** INFO/WARN 写 runtime，ERROR/FATAL 核心只写 errors 一份，界面合并时间线；成功请求主要计数汇总，access 只保留必要例外摘要。独立 SQLite 诊断库保存受保护的问题摘要/样本。管理员修改的低频问题状态在 admin.db 的独立表与审计同事务提交，避免高频诊断写入争用身份库。audit_logs 及其已有事务与保留策略不作为诊断缓存调整，处理状态也不是可丢弃索引。
3. **权限先于汇总。** 服务器运行诊断第一版仅 super_admin 访问；Device 上报身份由认证边界推导；摘要经过双端白名单与脱敏，私有报告文件按租户隔离。客户端本地默认可查/可导出，自动摘要经用户开启，原生 dump 不自动发送。
4. **先减少产生，再限制保留。** 正常无变化不逐条落盘；关键结果保留、高频活动汇总，有界内存线索在首次故障时按相关范围保存。重复错误保留增量、原因变化与恢复。单条/日写入/文件数/目录/内存/索引/导出均有限额，正常写入有界异步化，过载明确记录不完整；fatal 尽力写安全证据并退出，不把异常吞掉继续业务。保留旧日志只读，沿用既有 Crashpad 路径；部署侧日志与审计归档各自有容量责任。
5. **界面围绕问题处理。** 客户端在“本地数据”增加查看/导出；服务器新增“问题与日志”，按稳定异常特征聚合，支持处理、解决和复发，同时保留原审计入口。近期文件查询有明确扫描预算，不承诺无限全文检索。
6. **部署跟随实际所有者。** 新应用日志使用可配置的专用目录，保留本机现有 PM2 文件路径，部署侧复用已有 logrotate 并补齐轮转责任；诊断库与租户报告沿用实际 admin/data_dir 路径所有者。Nginx 原生错误内容须独立验证秘密保护，不能把 path-only access 格式误当成对所有代理日志的脱敏。

## Alternatives considered

- 仅把文件夹入口和 PM2 日志挂到 Admin：开发量小，但缺少页面报错、跨端关联、问题处理和权限/脱敏投影；无法覆盖目标。
- 把所有日志写入现有 admin.db：查询容易，但会让高频诊断与身份/授权/审计共享写入压力和清理风险。
- 立即部署集中式日志集群或第三方错误 SaaS：有现成功能，但增加依赖、运维及诊断数据外发边界；当前没有容量证据支持立即引入。
- 将所有客户端日志持续上传：管理员上下文更丰富，但增加带宽、隐私和滥用成本；采用有限错误摘要及主动报告。
- 只做轮转或只保留 ERROR：前者仍会产生大量无用写入，后者缺失关键过程；采用源头聚合、低频关键结果与有限故障上下文。

## Consequences and trade-offs

正面：重启前故障可保留，跨端编号可关联，管理员能区分运行故障与管理操作；保持现有平台和目录结构。

代价：需要维护两个小适配器、文件轮转/有界索引、双端 fixture 和诊断授权协议。汇总与上下文缓冲需要有界状态和明确计数语义；日志与索引不是同一事务，必须幂等恢复并显示采集延迟。

局限：完全停机时同机 Admin 不可用；过载/断电不能保证日志无损；正常历史细节超过内存窗口可能不可恢复；没有上报的设备不能纳入完整故障率；分组不是根因证明。有限磁盘不能承诺无限审计历史；外部探活、原生 dump 与大型检索平台按后续真实需求接入。
