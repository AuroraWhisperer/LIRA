## 弹幕外观与事件的交付边界

现行链路为：B 站 → LIRA Server 事件流 → Electron 单一按需订阅 → 本地场景输出。弹幕外观配置由 `src/server/danmaku-appearance.js` 与按账号隔离的本地存储共同维护，场景负责布局与样式选择，公共弹幕队列（feed）负责消息生命周期。礼物图片复用礼物目录维护的共享磁盘缓存与资源接口；场景只映射经过校验的合法来源，样式通过前端共享图片入口加载（详见 [礼物缓存](../../reference/backend/overtime.md#15-服务器全局礼物目录联动) 和 [叠加层参考](../../reference/frontend/overlays.md)）。新增本地样式时，只需同步客户端 Node 与浏览器两端的校验、参数控件、渲染逻辑及资源文件，无需在服务端镜像同步样式或 OpenAPI。

交付验收需覆盖：桌面端显式保存、重启恢复、账号切换与迟到请求处理、多场景共享参数、保存时不重播历史消息，以及本地场景实际渲染效果。仅预览正常不算交付完成；禁止重新接回远端样式 `PUT` 接口来绕过本机配置。首次升级时迁移承接旧配置，此后服务端下发的外观快照不得覆盖本机值；遇到未知云端样式时不得阻断正常弹幕事件。

服务端 ADR-0118 已下线旧 `/overlay` 页面、预览、静态资源及网页复制入口，但服务端事件订阅、Device/Streamer 设置接口与 `overlayUrl` 凭证格式仍保持兼容（不可再将该字段当作直播画面地址使用）。仅当需求明确涉及远端事件或上述兼容接口时，才同步修改服务端协议与测试。[ADR-0020](../adr/0020-shared-danmaku-source.md) 规定的公共渲染核心（renderer core）源码快照校验保持不变，但不扩展为所有样式的强制同步镜像。完成报告需明确区分源码验证、打包产物与实际运行版本。
