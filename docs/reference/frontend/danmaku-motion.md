# 固定弹幕动效

本页维护客户端内置固定弹幕的动效职责、逐款设计与作者约束。适用于本地预览及使用同一 feed 的客户端组件；OBS 和哔哩哔哩直播姬均属于浏览器源消费场景。服务器有独立的 feed 与发布流程，本页不表示服务器实现已同步。消息结构和其他展示行为见 [overlays.md](overlays.md)。

## 设计目标

观众应先读懂弹幕，再感受到样式。新消息出现自然，已在阅读的消息平稳让位，动画结束后画面安静。动效表达样式的材质和节奏，不靠大幅跳动、文字缩放或每条消息的复杂表演制造区别。

「各样式独立」指各样式拥有自己的视觉决策：入场方式、时长、缓动及装饰编排。「公共」指位置计算和执行机制只有一份：排序、高度测量、目标位置、同批移动同步、打断续接、越界淘汰、减少动态效果和销毁。不能为了某款效果在公共 feed 内增加样式名称分支，也不能为每款复制列表控制器。

## 逐款设计

滑动时长为「基准 + 本次最大位移的 CSS 像素数」毫秒，不超过上限。同一批新旧消息共用本款时长和曲线；上下方向沿用用户设置。入场与列表移动同时开始，不排队等待。表内横移独立于纵向列表移动，不改变最终排版。

## RIPPLOID 分层动效

RIPPLOID 的普通聊天、普通礼物、购买大航海和 SC 共用细线、票券与可配置强调色，但分别拥有内部时间轴。聊天在 700ms 内擦除揭示正文，再让当前房间粉丝牌／大航海徽标、昵称、细线和箭头分层落位；左侧竖线随正文实际高度延伸，箭头始终锚定灯牌所在行。礼物在 2000ms 内展开 GIFT 名称框、价格与签名票券，名称由强调色条带揭示，细框和双箭头短促闪烁，橙色转场层自身持续 600ms；上舰在 1600ms 内依次显示 NEW／MEMBER、购买身份、短促闪烁的发送者与连续渐变显色的头像，橙色转场层自身持续 550ms。SC 的完整时间轴为 1900ms，标题闪烁后由独立白边与强调色 SVG 路径组成连续曲线撕裂层，自上而下露出稳定留言卡；撕裂路径和开场剪影不使用折线锯齿。

这些内部动画只作用于 `append()` 新增的 live entry。礼物、上舰和 SC 根节点分别重新声明完整的 `--danmaku-enter-animation`，让根标记持续到自身所有图层结束；公共 feed 仍在根动画结束时清除 `data-live-entry`，不增加样式分支。稳定内容是无动画的默认 CSS 状态，`render()` 快照和减少动态效果直接显示完整内容。图形与关键帧由 `danmaku-ripploid.js` 和 `danmaku/ripploid.css` 维护，消息字段与配色见 [overlays.md](overlays.md#ripploid-固定弹幕)。

## 幽灵便笺分层动效

幽灵便笺的根标记 `spookyEntry` 持续 1250ms。昵称、正文、衬纸、贴纸独立显现；礼物、上舰和 SC 的头像先出现，面板再向右展开，最后显现头部。正文不旋转或缩放，不占用公共列表的 `top`；SC 使用独立通栏正文，长内容通过公共适配保持头部可见。`render()` 快照直接显示稳定内容，`append()` 才播放入场，结束后不保留循环贴纸动画。系统减少动态效果时全部静止。框、主题切换和身份处理见 [overlays.md](overlays.md#幽灵便笺固定弹幕)。

## 手账风分层动效

手账风以原片的轻便纸张和各身份配色为依据，根标记 `notebookEntry` 持续 740ms。聊天头像透明度在约 500ms 完成，旋转约 420ms 回到持续摆动轨迹，竖直入场约 600ms；纸张延迟 150ms 后在 450ms 内从右侧 10px、3° 轻倾和 0.975 倍回正。昵称在 320ms 后用 300ms 显现，正文在 420ms 后用 320ms 显现。纸张自身的微小倾斜/缩放留在内部图层，不占用 feed 的位置或根 transform；可读文字出现时纸张已接近稳定。

最新聊天纸张约 2333ms 一轮、上下差约 4 个逻辑像素。旧消息通过样式层暂停纸张和对应基础浮动，保留暂停时的位置；头像内层的摆动约 4233ms 一轮，舰长／提督／总督的轻缩放分别约 4933／4100／3300ms，普通头像没有缩放循环。各数值是视频拟合而非原作者源码参数。静态表情只随内容图层进入，自身不加动画。

内部入场只在 `[data-live-entry]` 存在时播放；快照直接显示完整内容，根标记结束后不残留入场填充。礼物和 SC 使用 200ms 淡入，开通纸张延迟 120ms 后在 280ms 内淡入，继续保留分开的头像和文字层。`prefers-reduced-motion: reduce` 停止所有内部入场和循环，公共 feed 负责同步取消列表移动。样式不创建额外 JS 时间循环，也不修改共用消息控制器。

## 仿推特 3.0 分层动效

仿推特 3.0 的根标记 `twitterPostShell` 持续 1100ms，只负责让新帖子外壳快速淡入；头像、昵称骨架、正文、金额、大航海阶梯和四组操作分别在内部图层交叉显现。操作从下方 18px 就位，爱心在最后完成显色、圆环和少量粒子，不生成点赞数或交互状态。普通聊天、礼物、大航海和 SC 共用这一节奏，内部动画不占用列表 `top`，不改变正文尺寸，也不重排已经稳定的消息。

这些图层只作用于 `append()` 新增的 `[data-live-entry]`。共享 feed 继续测量不同高度的卡片、同步移动、处理动画中追加和淘汰；`render()` 快照直接呈现完整帖子。`prefers-reduced-motion: reduce` 时公共 feed 清除 live entry，样式同时停用内部动画并移除骨架、圆环和粒子。矢量结构及 SVG 操作图标由 `danmaku-twitter.js` 创建，样式与关键帧由 `danmaku/twitter.css` 维护；消息和房主资料边界见 [overlays.md](overlays.md#仿推特-30-固定弹幕)。

## 星语装饰动效

「装饰图案」在客户端弹幕姬、画布中选中星语后的参数区和独立预览共用，选定图案即使用对应轻动画。四角星保留缩放闪烁；爱心双拍轻跳；圆角方块轻弹、轻微挤压回正；五角星缓慢转动；小花轻旋呼吸；月牙轻浮摇曳；蝴蝶结左右轻摆。昵称两侧和金额旁的装饰按各自周期错开相位，动画只作用于装饰伪元素，不带动文字或列表排版；切换不清空或重播消息。系统减少动态效果时所有图案静止完整显示，关闭后恢复所选动画。客户端和服务端星语主题同步维护这一行为。

## 实现契约

- 样式文件 `public/css/overlays/danmaku/<style>.css` 同时维护本款关键帧与 `--danmaku-enter-animation`、`--danmaku-move-base-ms`、`--danmaku-move-max-ms`、`--danmaku-move-curve`。雪狐保留已有内部装饰编排，只声明移动参数。这些是内部 CSS 接口，不是新用户设置或持久化字段。
- `danmaku-feed.js` 读取根节点继承的移动参数；未定义时使用原来的 420 / 760ms 和 `[0.3, 0.1, 0.2, 1]`。连续消息在当前位置和速度上续接，同批消息保持间距。
- 移动完成只用最近一次已测高度、间距和内边距淘汰完全越界的旧节点，不重新适配所有卡片。若已有内容或尺寸变化等待布局，先完成该次测量再清理；追加、区域/节点 resize 和效果更新仍走完整适配。
- 两个移动时长属性使用不带单位的毫秒数，曲线是四个逗号分隔的数值；入场属性使用完整 CSS animation 简写。样式只调本款声明，不能修改公共默认来间接调整其他样式。
- `motion.css` 负责公共接入与降级、边缘遮罩和仍被旧入口/随机样式消费的兼容动画。固定样式专属入场留在自己的文件。
- 新整条入场只用于 `append()`：节点标记 `data-live-entry`，结束时移除标记；`render()` 快照不播放这套新入场。节点重排、图片加载、区域缩放和后续消息到达不重播旧节点入场。雪狐、月渡花汀的既有内部装饰保持原规则。
- 列表沿用相对 `top` 移动以保持现有文字栅格效果。新增整条入场只使用透明度或横向独立 `translate`；不占用列表的 `top`，不修改纵向坐标、宽高、字体大小、字重和正文滤镜，也不覆盖组件的 `transform`。已有装饰动画不被公共层重新编排。
- 关键帧完成后交还普通 CSS 状态，不残留无期限的填充动画。`prefers-reduced-motion: reduce` 时直接显示完整内容，停止整条入场与列表移动，既有装饰遵循自身降级。

## 维护与体感验收

1. 先说明本款视觉气质、希望观众注意什么及动效的理由。默认动作已合适时可复用公共执行机制；仅参数不同时不要新建 JS 控制器。
2. 实际播放第一条、常速连续消息、动画未结束时追加、短时间多条、长正文、表情、礼物和 SC。查看入场中间帧与稳定帧；截图或代码检查不能单独证明顺滑。
3. 检查向上/向下、实际画布缩放及文字清晰度。旧消息不瞬移，不被新消息穿过，字形不忽胖忽瘦，顶部/底部边界不闪断；密集时不积压一长串表演。
4. 在浅色、深色背景检查半透明入场阶段，正文不能长时间不可读。保留既有造型、配色、层次和留白，不借动效任务重新设计外观。
5. 行为测试维护公共不变量，逐款真实播放负责审美；记录看到的效果、修正和环境限制。不能以「测试全绿」代替人眼验收，也不能把隔离浏览器结果写成真实直播验收。
6. 新样式将动效随自身 CSS 交付，扩展已有 `test/danmaku/danmaku-feed-motion.test.js` 行为覆盖；改公共机制时回归月渡花汀等既有消费者。

浅色背景检查用于发现动效是否加重原有对比问题，不意味着浅色线稿适用于所有背景。星语、绿萌等既有白色/浅色素材在浅底仍有对比限制，应结合实际直播底图与已有正文色设置选择；本轮不重做它们的配色与素材。

## 可直接复用的制作提示词

> 为 LIRA 的「样式名称」设计并实现固定弹幕动效。先阅读本页与该样式现有 CSS、素材和真实预览，保留它的配色、排版与视觉气质。用一句话说明入场想传递的感受，再确定入场方式、时长、列表移动节奏和边缘退出方式。样式文件拥有视觉参数和专属关键帧；排序、测量、动画打断续接、同批间距、淘汰与销毁继续复用公共 feed。普通消息以清晰易读为先，礼物和 SC 使用同一视觉语言；不让文字缩放、旋转、模糊，不给每条消息增加冗长表演，不在公共模块按样式名称堆分支。只有现有机制无法表达明确需求时才扩展公共接口，并说明边界。完成后实际播放常速和密集消息，检查短长文本、表情、礼物、SC、上下滚动、画布缩放和减少动态效果；保留中间帧及实时证据，依据看到的结果集中修正。报告具体改善、已执行验证与限制。月渡花汀已有动效保持原样。
