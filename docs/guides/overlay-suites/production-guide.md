# 如何制作一套完整的直播视觉主题

本文把「月渡花汀」的经验整理为后续制作建议，章节顺序便于执行，并非当时对话的逐步重放。实际发生的试做、否定、纠正与认可见 [调试复盘](iteration-history.md)；当前状态见 [入口](README.md)，文件出处见 [来源索引](sources-and-history.md)。

## 1. 先整理已知的风格和用途

把已确认的用途、参考和画风写成一份简短需求卡，尚未确定的部分留待样片比较。下表按月渡花汀最终版本回填，包含后来才出现的纸伞和 2K 目标，并非最初需求原文：

```yaml
主题名: 月渡花汀
视觉主线: 银蓝折扇、月色山水、白山茶；感谢扩展为山水纸伞和花汀
画法: 工笔细线、矿物水彩、水墨与绢纸质感
主色: 月白、雾蓝、银蓝、靛青；极少量淡金
背景密度: 中等；远景低对比，前景只保留必要装饰
主体留白: 为直播主体、昵称、信息和组件搭配留空间
组件: 静态/动态背景、弹幕、礼物许愿、时钟、全屏感谢、开播
目标画布: 2560×1440（已确认的动态背景输出；其他部件按各自契约）
动态信息: 昵称、头像、身份、礼物、数量、金额、进度、时间、SC
参考用途: 视频看结构和时间顺序；开播成品看配色和材质
禁止项: 不加入人物模型；不把姓名、计数或时间烘焙进装饰图
```

月渡花汀最初图像提示词使用 `#F3F5FA`、`#DDE5F3`、`#8FA9D0`、`#627AA9`、`#253353`。这些是美术方向锚点，不是要求所有像素和全部组件严格共用的一组 CSS token。大面积背景要比装饰和文字淡；身份色允许舰长霁蓝、提督藕紫、总督胭脂红。

先做一张 16:9 概念图，核对画风、密度、留白及核心物件。概念图只能证明方向，不能证明已经有动画。月渡花汀曾从过空改成过满，最终收敛到中等密度；不要把最后生成的最繁密原画直接认作最终构图。

已经有认可版本时，以它作为下一轮基线。先说明这次改哪几个问题、保留哪些部分；拿不准密度、颜色或节奏时，用已有版本作对比。若反馈改变了结构或动作顺序，应同步更新需求卡与预览，不能继续按被否定的方案制作。

## 2. 把整图拆成可以制作和运动的部件

| 部件 | 美术素材 | 程序或实时内容 |
| --- | --- | --- |
| 背景 | 无运动物体的完整底景、月亮、柳叶、灯笼、雾、花瓣 | 枝节摆动、逐叶跟随、水纹、倒影、循环合成或视频播放 |
| 开播 | 折扇、山水、四组花枝、鸟身与两翼、流苏、标题 | 扇片开合、绢带形变、飞鸟、文字、15 秒时间线 |
| 时钟 | 复用折扇、白山茶、流苏、裁切的圆形山水 | 本地时间、日期、秒数、12/24 小时、深浅交替 |
| 弹幕 | 笔刷遮罩、纸面/滚轴、花枝、上任山水、原有身份徽章 | 头像、昵称、正文/表情、礼物/金额、SC、消息队列 |
| 礼物许愿 | 贴圆花饰、横向水墨底、折扇起点 | 礼物图标、名称、已收/目标、进度填充、移动端点 |
| 全屏感谢 | 左右山水纸伞、底部花汀、四角花枝、字体 | 上任/收礼数据、入退场、花瓣、水纹、透明输出 |

每张原画只承担一个明确职责。花枝图集的各组之间留透明间隔；飞鸟身体和两翼分开；需要开合的扇面必须正面、共轴、轮廓完整。月亮将来要消失，就不要把它同时画死在背景里。

图像工具负责生成绘画素材，CSS、Canvas 或离线合成负责动作。月渡花汀使用过 LiraHub `gpt-image-2.5-flare`；这是历史制作记录，不表示新环境一定提供同名工具。复用素材通常不需要再调用图像生成。

## 3. 保留原图，清理透明边缘，再做适配

1. 原始 PNG、完整提示词、模型记录放到本轮 `tmp/<主题>-<部件>/source/`，不要只保留压缩后的 WebP。
2. 裁切透明空白和图集，记录尺寸、坐标、锚点；保留羽毛、花瓣、柳叶的柔和 alpha。
3. 在深、浅底色检查白边、杂点、绿边和孔洞。早期开播有绿幕原画，须按当时抠图脚本处理；新生成优先要求真实透明背景。
4. 保存运行时 WebP 和 sidecar 来源记录；需要继续精修的图保留无损版本。
5. 用真实显示尺寸看线条和文字，不只看放大的原画。礼物许愿已有 416px / 720px 验收记录，时钟已有小尺寸与双底色记录，可作为同类修改的起点。

降低锯齿不能只把录屏放大。当前动态背景保留原尺寸叶片和柔和 alpha，用 3840×2160 合成缓冲后缩到 2560×1440，RGBA 原始帧分别编码，避免 JPEG 中间帧。其山水原画仍只有 1672×941；成片为 2K 不等于原画具有原生 4K 细节。

## 4. 各部件怎样做

### 静态与动态背景

静态版来自 `tmp/opening-moon-fan/source/landscape-v2.png`，通过 `tmp/moonlit-background/grade.py` 调成浅银蓝。原图有细节，但原色过浓；壁纸要让直播主体和前景组件更容易看清。

动态背景最终做法是“新底景 + 分离素材 + 独立动作 + 合成成片”：

- 底景不含月亮、悬挂柳枝、前景灯笼、落花和固定圆形水纹。
- 月亮渐现、停留、完全隐去后恢复；19 条分节柳枝带动独立叶片，枝梢延迟跟随。
- 水面逐帧绘制波峰、倒影和扩散水纹；三盏灯笼绕悬挂点摆动，雾和花瓣分别循环。
- 周期统一在 24 秒闭合，输出 1440 帧，帧时刻为 `n / 60`、`n = 0..1439`；检查 0 秒与 24 秒状态，不重复编码末帧。
- 当前产品使用一条 2560×1440 VP9 WebM，MP4 用于观看。六层透明循环是之前 1080p 合成阶段的调节材料，不能标成六层原生 2K 成片。

用户明确否定过“只扭曲旧截图”和“动作轻到看不见”。应以可辨识的独立物体运动兑现需求，同时保持固定机位和浅淡画风。

实现中还要沿用视频延迟加载、静态回退、页面隐藏暂停、销毁释放和减少动态效果模式。当前正式播放入口是 [background-moonlit.js](../../../public/js/overlays/background-moonlit.js)，旧 30fps Canvas 背景不再是最终方案。

### 开播动画

先形成“开扇 → 文案显现 → 停留 → 文案消失 → 收扇 → 留景”的完整循环。最终约 15 秒：

| 时间 | 动作 |
| --- | --- |
| 0–3.7 秒 | 扇面展开，花枝、绢带与文案进入 |
| 3.7–约 9 秒 | 信息稳定，花枝、白鹤、流苏、水面等继续运动 |
| 9.2–10.8 秒 | 文字渐隐 |
| 10.2–13.2 秒 | 折扇收拢 |
| 13–13.8 秒 | 扇子下移淡出，前景依次退出 |
| 13.8–15 秒 | 短暂留景，衔接下一轮 |

当前是 22 片共轴扇面，早期提示词里“切成二十片”只是原画结构要求。Canvas 绘制与时间线由 [opening-moon-fan-art.js](../../../public/js/overlays/opening-moon-fan-art.js) 拥有，加载、暂停和销毁由同目录 `opening-moon-fan.js` 拥有。不要增加第二条帧循环。

默认书法标题可以是图片；自定义标题和副标题继续可编辑。动画预览无声不代表产品不支持原有音乐设置。

### 时钟

复用开播的扇、花、流苏和山水，重新构图成圆形读数区，外围透明；不照抄参考图中用途不明的三个圆圈。时钟是实时 DOM 文本，装饰才是图片。

浅色版深字、深色版月白字；支持固定浅色、固定深色、自动交替，默认 30 秒。保留日期、秒数和 12/24 小时设置。切换配色只改变外观，不能把时间改成预渲染数字或另开计时来源。

### 弹幕、消息内上任、礼物与 SC

以最后明确修正和当前 CSS 为准。以下精确时长是当前实现值；用户原话明确过 0.5 秒等待、动作放慢与先后方向，并未逐项指定所有毫秒数：

- 普通消息先显示对应身份的**小深色底框**，该底框一直保留；约 0.5 秒后，用约 1.6 秒从左向右刷入墨色。
- 普通观众灰色，舰长蓝、提督紫、总督红；身份图标用项目现有 B 站图片，不能自行重画成另一套符号。
- 消息内上任先由上到下显现背景与头像（约 1.45 秒），再从左到右显现称谓和三只鸟（延后约 1.5 秒、持续约 1.55 秒）。
- 礼物与 SC 先用约 1.4 秒从**右向左**展开素纸及内容，展开到哪里显示到哪里；之后边线、笔刷和花枝再用约 1.2 秒从**左向右**刷入。
- 礼物显示头像、昵称、礼物、数量和价值；SC 使用留言内容。长文本由布局处理，花饰固定尺寸，不能拉长整张插画。
- 连续来消息时平滑接续滚动，不靠重复创建动画和节点制造动效。

“礼物无头像”只适用于全屏感谢样片，不能套用到这里。卷轴淡山水暗纹和绢面微光的进一步设计仍是提案预览，不在已接入的 v6 规则中。

### 礼物许愿

最终 v4 是古风白山茶、墨蓝枝叶、如意云纹和绢带贴圆环绕，不是稀疏的小花冠。圆框保持紧凑，横向墨条足够长，白色名称和计数始终有深底衬托。

起点固定银蓝折扇，0 进度也显示；移动端点在 0 时隐藏。超过目标时计数如实显示，进度视觉封顶；收礼更新复用同一张卡片，平滑推进，不重启动效。数据、计数与身份沿用现有礼物许愿链路。

### 全屏上任 / 礼物感谢

采用最新「月伞花汀」样片：两侧大幅斜置山水油纸伞，底部贯穿的月色花汀，四角花枝，中央透明。旧版玉饰第一层、两侧架子和侧边绢带已经被后续方向替代。

- 上方花体：上任 `new member`；礼物 `new presents`。
- 上任包含头像、昵称、称谓；最终去掉“新”，显示“舰长上任 / 提督上任 / 总督上任”。称谓用文楷，“上任”略小错落，昵称用清楚的宋体层级。
- 礼物显示昵称、礼物名和数量，不显示送礼人头像。
- 单次 9.6 秒，约 0.18 秒纸伞入场、右侧晚 0.14 秒；0.4 秒花汀进入、0.6 秒花枝跟随、0.9–1.75 秒文字显现；约 8 秒文字先退，9.6 秒画布完全透明。
- MP4 的深蓝底只是观看背景。透明交付以交互 HTML 和透明 PNG 为证；当前最终月伞版没有一条已归档的透明 WebM，不得拿旧版透明视频顶替。

当前仍是演示数据样片。接入真实事件是另外的实现任务，需要核对礼物队列、触发门槛、配置、头像和生命周期；本指南没有代替用户决定或实现这些业务变更。

## 5. 先看完整组合，再接入产品

每个部件交付“美术静帧 + 可播放完整样片 + 可编辑源素材”。月渡花汀的感谢和动态背景都曾因只展示局部或未展示完整组合而被要求重新交付；因此，全屏感谢要一次看到上方英文、左右装饰和下方信息，动态背景要交合成后的完整画面。

接入时先查已有 owner、注册表、renderer 和预览流程。套装用显式 `component + style` 关联：同一主题在不同部件中可能是 `moonlit` 或 `moonlit-fan`，不能靠中文名猜。套装是组件分类入口；各部件保留自己的数据与参数。

静态方向 → 完整动效 → 产品预览 → 持久化/输出，验证随实际改动选择。美术微调不自动扩大为全仓验证；新增枚举、生命周期或跨端协议变更则需要相关契约检查。

## 6. 验收和归档

| 本次改动 | 最有用的证据 |
| --- | --- |
| 原图/透明边缘 | 真实显示尺寸、深浅底的静帧，必要时 alpha 检查 |
| 循环/入退场 | 完整播放至少一轮并跨越接头，记录开始、中段、结束 |
| 时钟/进度/消息 | 真正的 renderer 与测试数据；更新后无重复节点和事件 |
| 产品接入 | 添加、保存、重开、输出；涉及桌面特权能力时用 Electron 正常授权路径 |
| 分辨率/编码 | 实际解码尺寸和帧率；素材源分辨率、合成缓冲、输出尺寸分别记录 |

OBS 和哔哩哔哩直播姬都是直播软件，B 站是直播平台。浏览器源测试能覆盖 overlay；普通浏览器不能证明桌面预加载和 IPC 正常。报告写清楚实际检查过什么，未实播就保留未实播说明。

归档至少包含：brief、参考图、原提示词、原始图、裁切/处理脚本、动作源码、字体许可、完整样片、关键检查结果、版本状态、原路径及校验值。进行新一轮制作时，在 `tmp/` 工作；阶段结束后建立新的日期快照，避免覆盖已确认版本。具体目录约定见 [归档说明](../../../archive/moonlit-suite/README.md)。
