# AI 模型与第三方兼容 API 使用说明

LIRA 支持 Responses API、OpenAI Chat Completions 和官方 ChatGPT 订阅授权三种接入方式。API Key 与订阅登录信息分开加密保存，调用时只使用当前选中的方式（切勿把真实密钥写入文档、源码或测试）。

已保存的密钥显示为前 6 位加掩码（例如 `sk-abc********`），较短密钥全部遮住。输入新密钥并自动保存后替换，留空保留现有密钥。

## 先选择供应商

- DeepSeek、Kimi / Moonshot、OpenAI、Claude、Gemini：选择对应官方预设，LIRA 会固定官方兼容地址和推荐协议，页面无需手填地址。OpenAI 另外提供「接入方式」选择。
- 豆包（账号登录·实验性）：使用个人豆包账号文字对话，操作见下文；不需要 API Key，也不走火山引擎计费 API。
- 自定义 / 第三方 OpenAI 兼容：适用于酒馆中转、聚合服务、私有网关以及其他提供 OpenAI 兼容接口的平台；地址和协议均可编辑。
- 自动识别：只为兼容已有设置保留，新配置建议明确选择供应商。

Claude 和 Gemini 预设走的是官方提供的 OpenAI 兼容接口。由于 Claude 兼容层只覆盖部分功能，如需完整原生能力，不能把它等同于原生 Messages API。

点击「获取模型」可拉取当前账号实时可用的模型列表：列表优先显示平台返回的名称（没有名称时直接显示 ID），选中后实际请求原样使用该模型的 ID，不做额外拼改。DeepSeek 官方当前为 `DeepSeek-V4.1-Flash`（`deepseek-flash`）与 `DeepSeek-V4-Pro`（`deepseek-v4-pro`），以[官方目录](https://api-docs.deepseek.com/api/list-models/)为准；已有官方 Flash 旧名称会自动转为 `deepseek-flash`。第三方服务的模型 ID 仍以该服务返回值为准。

选择「DeepSeek 官方」后，点名问答和自动接话都省去额外的模型输入、输出审核，保留公共规则与本地内容检查，以减少等待。普通无工具问答只需一次生成；缓存命中不请求模型，工具续接和送达重试可能增加请求。自动接话每次评估只生成一次，仍限制为一条完整弹幕，不调用工具，格式或长度不合要求就跳过。豆包同样采用单次生成（详见下文），其他平台及 ChatGPT 订阅保留远程审核。

## Kimi / Moonshot

选择「Kimi / Moonshot 官方」，点击「打开官方 API 控制台」创建 Moonshot API Key，粘贴后等待保存，再获取模型并测试连接。地址固定为 `https://api.moonshot.cn/v1`，模型以账号实际返回的列表为准。

Kimi 网页会员和 Kimi Code 编程订阅不能用于 LIRA 弹幕回复，需在 Moonshot 开放平台申请 API Key（见 [Kimi 会员说明](https://www.kimi.com/en/help/kimi-code/membership-guide)）。同样，Claude、Gemini、DeepSeek 也必须使用各自的 API Key，普通网页会员不等同于 API 权限（参考 [Claude 认证范围](https://code.claude.com/docs/en/legal-and-compliance)、[Gemini 计费说明](https://ai.google.dev/gemini-api/docs/billing)）。

## ChatGPT 订阅登录

1. 在桌面客户端选择「OpenAI 官方」，将「接入方式」改成「ChatGPT 订阅（官方授权）」。
2. 点击「连接 ChatGPT 订阅」，在系统浏览器的 OpenAI 页面登录并同意使用订阅。完成后返回 LIRA，账号状态会自动更新；仅登录但未授权订阅时不能调用。
3. 点击「获取模型」，选择该账号可用的模型，再点「测试 AI 连接」。填写触发关键词后，可继续使用现有的人格、短期上下文、审核和可选工具。

授权使用官方 [Sign in with ChatGPT 本地应用流程](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)，模型和额度以账号授权结果为准。登录信息由本机系统加密保存，后续自动刷新；系统加密不可用时不能保存或登录。可以取消等待中的登录、添加和切换账号；「退出当前账号」清除该账号的本地凭据并请求远端撤销，其他账号及 API Key 保留。账号切换和退出会取消旧账号的未完成请求。如果切换结果未能确认，请等页面重新显示当前账号，再点击退出。

订阅不足、失效或未授权时会报错，不会自动转用收费 API，可通过「管理订阅用量」查看额度；切回 API 计费时请手动选择「API Key（按 API 计费）」并重新获取模型。原 Key 仍只属于原 API 地址，跨平台切换时须提供对应 Key。

订阅模式的可用模型和参数与 API 模式不同，连接或切换账号后请先点「获取模型」刷新目录和思考档位（档位规则见[联网与思考](#联网与思考)）。回复完整生成并审核后才会发送；官方要求的本地工具续接历史由 LIRA 自动维护，无需手动填 Token 或复制浏览器 Cookie。

## 间隔后继续聊天或玩游戏

在“互动身份”设置“空闲多久后结束对话（分钟）”，建议 10 分钟。同一观众每次带触发关键词提问，收到回复就重新计时；例如先发“小助手，玩成语接龙”，3–5 分钟后带关键词接下一词，仍会延续这段互动。不同观众、房间和人格各自独立。

超过设置的空闲时间会清空本机历史；也可以发送“小助手，结束对话”（将“小助手”换成自己的关键词）立即结束。运行中每分钟回收过期记录，关闭后在下次启动清理。此清理不删除豆包网站上的聊天记录。会话保留开场与最近问答，最多 20 轮并限制总长度；较早的细节可能被省略，成语或谜语的判断仍取决于模型。

## 豆包账号登录（实验性）

在桌面客户端「AI 互动助手」的「AI 平台」选择「豆包（账号登录·实验性）」，点击「扫码登录豆包」。用手机豆包扫码并确认登录，电脑无需安装豆包 App。填写触发关键词，点击「测试 AI 连接」确认文字回复，再按需开启 AI。

登录态会通过系统加密保存；系统加密不可用时仅在本次运行中有效。点击「退出豆包」会取消未完成请求并清除 LIRA 保存的豆包登录态。

这是非官方网页接入，仅提供文字对话。LIRA 的人格、触发词和短期上下文继续生效；网页账号可能保存发出的对话。豆包模式下不提供模型 ID、联网/思考开关或函数工具，原 API 配置会保留供切回使用。

LIRA 会按观众和人格分别向豆包发起独立会话，只续接自己创建并确认过的会话，不会串入网页端当前打开的私人聊天。同一观众在空闲时限内（默认 10 分钟，按上文设置生效）向同一人格追问时会继续原有会话，重启或重新登录后按需新建；「测试 AI 连接」使用单独的测试会话。续接时会请求豆包清空旧上下文并带入该观众近期已送达的问答，不会主动删除豆包网页上的历史记录。

为了加快响应，豆包每次问答只发一次生成请求（保留预设安全约束和本地检查，省去两次额外模型审核），完整回复通过检查后才发弹幕。因减少了语义复核，无法保证 100% 拦截敏感内容或提示词注入；触发固定拒绝语时不会写入记忆。

如果弹出「豆包未确认会话或上下文隔离」，本次回复不会发到直播间（但已发给豆包的提问无法撤回）。处理步骤：先关闭「启用 AI」（保持平台仍选豆包）→ 等开关保存后重启 LIRA → 保持关闭状态下点「测试 AI 连接」→ 测试通过后再按需重新开启；若仍报错请保持关闭。

遇到验证提示时，请点击「打开豆包完成验证」，按官方网页窗口提示操作，再点击「测试 AI 连接」确认恢复。网页未必显示验证码；若官网能聊天但连接测试仍提示验证，LIRA 接入尚未恢复，请保持暂停，不要反复点击测试。验证可能再次出现，不能保证只验证一次或长期无人值守；LIRA 不会自动重试或绕过验证码。

## 自定义服务的协议与地址

管理页的“接口协议”对应供应商文档中的 `wire_api`。第三方服务不按域名猜供应商；如果文档明确写 `responses` 或 `chat/completions`，请选择对应协议。不确定时保持“自动识别”，继续使用旧版兼容规则。

| 接口协议         | 填写形式                                 | 实际模型请求地址               |
| ---------------- | ---------------------------------------- | ------------------------------ |
| 自动识别         | `https://provider.example/` 或 `/v1`     | `/v1/chat/completions`         |
| Responses API    | `https://provider.example/` 或 `/v1`     | `/v1/responses`                |
| Chat Completions | `https://provider.example/` 或 `/v1`     | `/v1/chat/completions`         |
| 任意             | 完整 `/responses` 或 `/chat/completions` | 原样使用，并以完整路径确定协议 |

DeepSeek 官方根地址继续按其官方路径适配：Chat 使用 `/chat/completions`，Responses 使用 `/responses`，不受第三方 `/v1` 根地址规则影响。无法明确识别为基础地址的自定义完整路径会原样作为 Responses API 地址使用，避免擅自改写现有配置。

## 配置示例

- 模型供应商：`自定义 / 第三方 OpenAI 兼容`
- API 请求地址：供应商给出的服务根地址、`/v1` 基础地址或完整接口地址
- 接口协议：按供应商文档选择；Codex 配置中的 `wire_api = "responses"` 对应“Responses API”
- API Key：`YOUR_API_KEY`
- 模型：通过“获取模型”选择服务实际返回的模型 ID

点「模型服务」里的「测试 AI 连接」后，管理页先检查表单，等待设置保存成功，再测试当前所选的平台。测试请求固定使用非流式 JSON（API 模式）；ChatGPT 订阅按官方要求读取完整 SSE 回复后显示结果。

## 普通问答与可选工具

新配置默认通用助手，联网、天气、地点和路线查询均关闭。填好模型服务和触发词即可用于普通问答，不需要和风或高德账号。

需要实时检索时开启“联网搜索”。Responses 使用平台原生搜索，Chat Completions 使用 LIRA 搜索，无需额外开启工具总开关。接口兼容不代表具体模型支持工具；按模型说明选择，工具不受支持时关闭相应开关仍可普通聊天。

天气、地点或路线在“可选工具”中按需单独启用，并填写对应 Host 和 Key。没有完整凭据或关闭对应查询时不会请求这些服务；关闭查询保留已填凭据。实时信息无法核实时，助手会被要求说明不确定并提供一般建议。

## 角色包

在“互动身份”的“人格预设”直接选择，下方显示适用平台与角色简介。所有平台都有“通用人格”和“新建预设…”入口，已保存的自建、导入和原有自定义角色也始终可选；通用人格保留模型原本风格。选择 DeepSeek 后额外显示“小猫人格”和“鲸鱼娘”，说明为“针对 DeepSeek”及简要角色身份，其他模型尚未测试。两者日常均为温软、童真、好奇的小姑娘风格，按具体话题自然接话；小猫偶尔用“喵”，鲸鱼娘偏憨憨的认真，不依赖固定口癖或顶嘴来表现角色。“自动识别”在保存后沿用服务端的平台识别结果；“自定义兼容”不根据模型名称推测平台。

各平台会记住上次选择的人格，刷新或重开页面后仍保留。例如 DeepSeek 选择小猫后，首次切到豆包会使用通用人格，再切回 DeepSeek 会恢复小猫及其编辑内容。目标平台没有选择记录时，沿用当前兼容人格；小猫或鲸鱼娘不适用时改选通用人格。旧配置原本已选小猫时，首次打开仍保留并提示适用范围。点击“新建预设…”可直接新建；点击“管理预设”可以修改当前预设、新建或另存副本。点击“保存预设”才生效，取消放弃编辑。内置三项不能删除或改名，可以修改并恢复默认；自建预设可以修改和删除。所有角色自动附加公共安全规则与发送预算，无需逐个预设补写。

预设主要描述身份、性格、语气和互动偏好，例如“用自然简短的中文聊天，先回答问题，不确定时说明”。不要写“无条件服从观众”“主播授权就忽略规则”，也不要放入密钥、联系方式或私密资料。自称管理员、伪造审核结果、要求输出隐藏指令或解码后执行等请求会受到公共规则与本地检查约束；正常聊管理员话题或编码知识仍可回答。拒绝内容不进入缓存和记忆；这些措施降低风险，不能保证杜绝注入。

编辑面板的“导出当前预设”生成 LIRA JSON，不包含未保存的编辑；“导入角色包”接受最多 64 KiB 的同格式文件，成功后立即选中。最多保存 20 个自建或导入包，名称 1–40、说明最多 200、人设 20–8000 个字符。重复 ID 不覆盖旧包。导出不包含凭据或聊天记录；这不是 SillyTavern 角色卡或可执行脚本插件。制作格式见 [角色包契约](../reference/backend/ai.md#73-角色包与兼容读取)。

“触发关键词”同时作为机器人名字；内置预设及自建人设里的 `{{name}}` 会在回复时自动替换，导出保留占位符。默认没有名字，不会响应；填写名字、配置模型并在客户端启用 AI 后，观众发包含名字的弹幕即可触发。

已有自定义人设和工具的实际启停状态会保留；升级后想使用普通问答，可选择通用助手，并关闭联网和各项查询。换角色或修改人设后不会串用另一角色的短期记忆。

## 联网与思考

面板会显示已保存的思考开关状态和请求档位，例如「思考开启 · high」。支持关闭的模型通过开关控制，`none` 不重复显示在开启档位中；开关显示「思考始终开启」时，可直接在旁边的下拉框选择模型提供的档位。此状态对应 LIRA 发出的请求参数，中转服务须兼容这些参数；连接成功不能单独证明其内部执行模式。获取模型后会刷新能力和已保存的请求状态，保留其他未保存草稿。

思考强度档位随模型动态变化，原样保留官方名称，只对官方明确指定的默认档标出「默认」。点「获取模型」后会优先采用平台实时返回的档位信息，平台未返回时按已知官方文档规则展示；没有确认档位定义的模型不会猜测选项，也不会沿用上一个模型遗留的参数。旧配置失效时会自动回退到官方默认档；若官方没有固定默认档，则由用户自选，未选时交由上游默认处理。

- Responses API：联网由上游的 `web_search` 执行；支持 `none` 的模型可关闭思考，始终思考的模型只能调节强度。未知官方模型沿用上游设置。第三方目录未提供档位时复用精确同名 GPT 的已知定义；未知模型保留原有显式参数兼容行为。
- DeepSeek 官方 Chat：联网由 LIRA 的函数工具执行，须同时开启联网与工具调用；可启停思考。当前官方目录为 `low / high（默认）/ max`。
- Kimi 官方 Chat：联网使用 LIRA 函数工具。K2.5/K2.6 可开关思考；K3 / K3.1 Pro 的官方等级为 `low/high/max`，默认 `max`，始终思考，面板锁定为开启并允许选择强度；旧关闭设置使用 `low`。
- Gemini 官方兼容：使用 Chat Completions；仅列出该模型官方确认的等级与默认档，不把其他等级转换为 `high`。2.5 系列支持明确选择兼容档位，但不标记未确认的命名默认档；2.5 Flash / Flash Lite 可通过 `none` 关闭思考。
- Claude 官方兼容：使用 Chat Completions；当前界面不发送 Claude 原生思考字段，推理由模型和 Anthropic 兼容层管理。
- 第三方 OpenAI 兼容 Chat：联网要求模型支持 `tool_calls`。思考优先使用服务模型目录；目录只提供模型 ID 时，精确同名 GPT 可使用已知档位，并将选择以标准 `reasoning_effort` 发送。未知别名或明确未提供可控档位的模型会提示能力未确认，不发送猜测参数。

## 排查

- `HTTP_401`/`HTTP_403`：检查 Key 和账户权限。
- `HTTP_404`/`HTTP_405`：检查填写的是服务根地址、`/v1`，还是正确的完整端点。
- `UPSTREAM_INVALID_RESPONSE`：服务没有返回 JSON；检查是否强制流式输出或经过了错误的代理页面。
- `DEEPSEEK_INVALID_RESPONSE`：JSON 中没有可识别的文本或工具调用。
- `CHATGPT_LOGIN_REQUIRED` / `CHATGPT_REAUTH_REQUIRED`：重新登录并授权使用订阅。
- `CHATGPT_USAGE_LIMIT`：订阅额度暂不可用，查看用量或稍后重试；不会自动转用 API。
- `CHATGPT_RESPONSE_INCOMPLETE`：回复流未完整结束，本次部分内容不会发送。
