# AI 模型与第三方兼容 API 使用说明

LIRA 的模型客户端支持 Responses API、OpenAI Chat Completions 和官方 ChatGPT 订阅授权。API Key
与订阅登录信息分别加密保存，每次只使用所选接入方式；不要把真实凭据写入文档、源码或测试。

已保存的密钥显示为前 6 位加掩码（例如 `sk-abc********`），较短密钥全部遮住。输入新密钥并自动保存后替换，留空保留现有密钥。

## 先选择供应商

- DeepSeek、Kimi / Moonshot、OpenAI、Claude、Gemini：选择对应官方预设，LIRA 会固定官方兼容地址和推荐协议，页面无需手填地址。OpenAI 另外提供「接入方式」选择。
- 豆包（账号登录·实验性）：使用个人豆包账号文字对话，操作见下文；不需要 API Key，也不走火山引擎计费 API。
- 自定义 / 第三方 OpenAI 兼容：适用于酒馆中转、聚合服务、私有网关以及其他提供 OpenAI 兼容接口的平台；地址和协议均可编辑。
- 自动识别：只为兼容已有设置保留，新配置建议明确选择供应商。

Claude 和 Gemini 预设使用供应商官方提供的 OpenAI 兼容入口。Claude 的兼容层只覆盖部分 OpenAI 功能；需要 Claude 原生完整能力时不应把此入口视为原生 Messages API 的替代品。

## Kimi / Moonshot

选择「Kimi / Moonshot 官方」，点击「打开官方 API 控制台」创建 Moonshot API Key，粘贴后等待保存，再获取模型并测试连接。地址固定为 `https://api.moonshot.cn/v1`，模型以账号实际返回的列表为准。

Kimi 会员与 Kimi Code 订阅不用于 LIRA 弹幕回复。官方将产品集成放在 Moonshot 开放平台，Kimi Code 订阅面向编程场景，见 [Kimi 会员说明](https://www.kimi.com/en/help/kimi-code/membership-guide)。Claude、Gemini、DeepSeek 在此仍使用 API Key；网页会员不等于 API 权限。Claude 对第三方订阅凭据接入有明确限制，见 [官方认证范围](https://code.claude.com/docs/en/legal-and-compliance)；Gemini API 使用 [项目计费](https://ai.google.dev/gemini-api/docs/billing)。

## ChatGPT 订阅登录

1. 在桌面客户端选择「OpenAI 官方」，将「接入方式」改成「ChatGPT 订阅（官方授权）」。
2. 点击「Continue with ChatGPT」，在系统浏览器的 OpenAI 页面登录并同意使用订阅。完成后返回 LIRA，账号状态会自动更新；仅登录但未授权订阅时不能调用。
3. 点击「获取模型」，选择该账号可用的模型，再点「测试 AI 连接」。填写触发关键词后，可继续使用现有的人格、短期上下文、审核和可选工具。

授权使用官方 [Sign in with ChatGPT 本地应用流程](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)，模型和额度以账号授权结果为准。登录信息由本机系统加密保存，后续自动刷新；系统加密不可用时不能保存或登录。可以取消等待中的登录、添加和切换账号；「退出当前账号」清除该账号的本地凭据并请求远端撤销，其他账号及 API Key 保留。账号切换和退出会取消旧账号的未完成请求。

API Key 与订阅凭据可以同时保留，实际调用只使用「接入方式」选中的一项。订阅不足、失效或未授权时会报错，不自动改用收费 API；可通过「管理订阅用量」查看。需要切回 API 时手动选择「API Key（按 API 计费）」并重新获取适用模型。原 Key 仍只属于原 API 地址，跨平台切换时须提供对应 Key。

订阅的可用模型和部分参数与 API 不同：回复完整生成并审核后再发送；思考关闭时使用低强度，具体档位及联网能力仍由模型支持情况决定。官方要求本地携带工具续接历史，LIRA 已自动处理；不需要用户填 Token 或复制浏览器 Cookie。

## 间隔后继续聊天或玩游戏

在“互动身份”设置“空闲多久后结束对话（分钟）”，建议 10 分钟。同一观众每次带触发关键词提问，收到回复就重新计时；例如先发“小助手，玩成语接龙”，3–5 分钟后带关键词接下一词，仍会延续这段互动。不同观众、房间和人格各自独立。

超过设置的空闲时间会清空本机历史；也可以发送“小助手，结束对话”（将“小助手”换成自己的关键词）立即结束。运行中每分钟回收过期记录，关闭后在下次启动清理。此清理不删除豆包网站上的聊天记录。会话保留开场与最近问答，最多 20 轮并限制总长度；较早的细节可能被省略，成语或谜语的判断仍取决于模型。

## 豆包账号登录（实验性）

在桌面客户端「AI 互动助手」的「AI 平台」选择「豆包（账号登录·实验性）」，点击「扫码登录豆包」。用手机豆包扫码并确认登录，电脑无需安装豆包 App。填写触发关键词，点击「测试 AI 连接」确认文字回复，再按需开启 AI。

登录态会通过系统加密保存；系统加密不可用时仅在本次运行中有效。点击「退出豆包」会取消未完成请求并清除 LIRA 保存的豆包登录态。

这是非官方网页接入，仅提供文字对话。LIRA 的人格、触发词和短期上下文继续生效；网页账号可能保存发出的对话。豆包模式下不提供模型 ID、联网/思考开关或函数工具，原 API 配置会保留供切回使用。

每位观众使用独立的豆包对话，同一观众、同一人格在有效期内继续使用，默认空闲满 10 分钟后再次提问会新建（已保存的时长继续沿用）；不同人格的对话也会分开，重启或重新登录后按需新建。「测试 AI 连接」使用单独的测试对话。LIRA 只续接自己为该观众和人格创建并确认的对话，不把窗口当前打开的私人聊天作为复用目标。每次仍重置豆包侧的旧上下文，再按观众带上当前会话的有界多轮已送达问答，保留正常追问。不主动删除网页聊天记录；新策略的实际隔离效果仍待更新客户端后的账号实测。

为减少首字等待，豆包每次问答只发一次生成请求，保留预设安全约束和本地输入/输出检查，省去两次额外模型审核。完整回复检查后才发送弹幕；首字耗时单独记入诊断日志，约 1 秒仍是待实测目标。减少了语义复核，不能保证拦截所有敏感内容或提示词注入；固定拒绝语不写入记忆。若提示“未确认会话或上下文隔离”，会停止请求。重启 LIRA 后测试，仍失败则暂停使用豆包。

遇到验证提示时，请点击「打开豆包完成验证」，按官方网页窗口提示操作，再点击「测试 AI 连接」确认恢复。网页未必显示验证码；若官网能聊天但连接测试仍提示验证，LIRA 接入尚未恢复，请保持暂停，不要反复点击测试。验证可能再次出现，不能保证只验证一次或长期无人值守；LIRA 不会自动重试或绕过验证码。

## 自定义服务的协议与地址

管理页的“接口协议”对应供应商文档中的 `wire_api`。第三方服务不按域名猜供应商；如果文档明确写 `responses` 或 `chat/completions`，请选择对应协议。不确定时保持“自动识别”，继续使用旧版兼容规则。

| 接口协议         | 填写形式                                 | 实际模型请求地址               |
| ---------------- | ---------------------------------------- | ------------------------------ |
| 自动识别         | `https://provider.example/` 或 `/v1`     | `/v1/chat/completions`         |
| Responses API    | `https://provider.example/` 或 `/v1`     | `/v1/responses`                |
| Chat Completions | `https://provider.example/` 或 `/v1`     | `/v1/chat/completions`         |
| 任意             | 完整 `/responses` 或 `/chat/completions` | 原样使用，并以完整路径确定协议 |

DeepSeek 官方根地址继续按其官方路径适配：Chat 使用 `/chat/completions`，Responses 使用 `/responses`，不受第三方 `/v1` 根地址规则影响。无法明确
识别为基础地址的自定义完整路径会原样作为 Responses API 地址使用，避免擅自改写
现有配置。

## 配置示例

- 模型供应商：`自定义 / 第三方 OpenAI 兼容`
- API 请求地址：供应商给出的服务根地址、`/v1` 基础地址或完整端点
- 接口协议：按供应商文档选择；Codex 配置中的 `wire_api = "responses"` 对应“Responses API”
- API Key：`YOUR_API_KEY`
- 模型：通过“获取模型”选择服务实际返回的模型 ID

点击“模型服务”分组内的“测试 AI 连接”前，管理页会先保存待处理的配置。测试请求固定使用
非流式 JSON（API 模式）；ChatGPT 订阅按官方要求读取完整 SSE 回复后显示结果。

## 普通问答与可选工具

新配置默认通用助手，联网、天气、地图及工具调用均关闭。填好模型服务和触发词即可用于普通问答，不需要和风或高德账号。

需要实时检索时开启“联网搜索”。Responses 的平台原生搜索由平台支持；Chat Completions 的 LIRA 搜索还需在“可选工具”中打开“允许模型调用工具”。接口兼容不代表具体模型支持工具；按模型说明选择，工具不受支持时关闭相应开关仍可普通聊天。

天气、地点或路线按需单独启用，并填写对应 Host 和 Key。没有完整凭据或关闭工具时不会请求这些服务；关闭总开关保留已填配置。实时信息无法核实时，助手会被要求说明不确定并提供一般建议。

## 角色包

在“互动身份”的“人格预设”直接选择，下方显示适用平台与角色简介。所有平台都有“通用人格”和“新建预设…”入口，已保存的自建、导入和原有自定义角色也始终可选；通用人格保留模型原本风格。选择 DeepSeek 后额外显示“小猫人格”，说明为“针对 DeepSeek”及简要角色身份，其他模型尚未测试。“自动识别”在保存后沿用服务端的平台识别结果；“自定义兼容”不根据模型名称推测平台。

各平台会记住上次选择的人格，刷新或重开页面后仍保留。例如 DeepSeek 选择小猫后，首次切到豆包会使用通用人格，再切回 DeepSeek 会恢复小猫及其编辑内容。目标平台没有选择记录时，沿用当前兼容人格；小猫不适用时改选通用人格。旧配置原本已选小猫时，首次打开仍保留并提示适用范围。点击“新建预设…”可直接新建；点击“管理预设”可以修改当前预设、新建或另存副本。点击“保存预设”才生效，取消放弃编辑。内置两项不能删除或改名，可以修改并恢复默认；自建预设可以修改和删除。所有角色自动附加公共安全规则与发送预算，无需逐个预设补写。

预设主要描述身份、性格、语气和互动偏好，例如“用自然简短的中文聊天，先回答问题，不确定时说明”。不要写“无条件服从观众”“主播授权就忽略规则”，也不要放入密钥、联系方式或私密资料。自称管理员、伪造审核结果、要求输出隐藏指令或解码后执行等请求会受到公共规则与本地检查约束；正常聊管理员话题或编码知识仍可回答。拒绝内容不进入缓存和记忆；这些措施降低风险，不能保证杜绝注入。

编辑面板的“导出当前预设”生成 LIRA JSON，不包含未保存的编辑；“导入角色包”接受最多 64 KiB 的同格式文件，成功后立即选中。最多保存 20 个自建或导入包，名称 1–40、说明最多 200、人设 20–8000 个字符。重复 ID 不覆盖旧包。导出不包含凭据或聊天记录；这不是 SillyTavern 角色卡或可执行脚本插件。制作格式见 [角色包契约](../reference/backend/ai.md#73-角色包与兼容读取)。

“触发关键词”同时作为机器人名字；内置预设及自建人设里的 `{{name}}` 会在回复时自动替换，导出保留占位符。默认没有名字，不会响应；填写名字、配置模型并在客户端启用 AI 后，观众发包含名字的弹幕即可触发。

已有自定义人设和显式工具设置会保留；升级后想使用普通问答，可选择通用助手，并关闭联网和“允许模型调用工具”。换角色或修改人设后不会串用另一角色的短期记忆。

## 联网与思考

- Responses API：联网由上游的 `web_search` 执行；推理可启停，并可选 `minimal` 到 `max`，具体档位仍需上游支持。
- DeepSeek 官方 Chat：联网由 LIRA 的函数工具执行，须同时开启联网与工具调用；可启停思考并选择强度。官方原生档位为 `low/high/max`，其他档位映射到最接近的官方强度。
- Kimi 官方 Chat：联网使用 LIRA 函数工具。K2.5/K2.6 可开关思考；K3 始终思考，关闭时改用低强度。具体模型能力以官方说明为准。
- Gemini 官方兼容：使用 Chat Completions；可选择 `minimal` 到 `high`，更高档位映射为 `high`，关闭思考是否生效取决于具体 Gemini 模型。
- Claude 官方兼容：使用 Chat Completions；当前界面不发送 Claude 原生思考字段，推理由模型和 Anthropic 兼容层管理。
- 普通第三方 Chat：联网须同时开启联网与工具调用，并要求模型支持 `tool_calls`；LIRA 不发送非标准思考参数，思考能力由模型 ID 或供应商配置决定。

## 排查

- `HTTP_401`/`HTTP_403`：检查 Key 和账户权限。
- `HTTP_404`/`HTTP_405`：检查填写的是服务根地址、`/v1`，还是正确的完整端点。
- `UPSTREAM_INVALID_RESPONSE`：服务没有返回 JSON；检查是否强制流式输出或经过了错误的代理页面。
- `DEEPSEEK_INVALID_RESPONSE`：JSON 中没有可识别的文本或工具调用。
- `CHATGPT_LOGIN_REQUIRED` / `CHATGPT_REAUTH_REQUIRED`：重新登录并授权使用订阅。
- `CHATGPT_USAGE_LIMIT`：订阅额度暂不可用，查看用量或稍后重试；不会自动转用 API。
- `CHATGPT_RESPONSE_INCOMPLETE`：回复流未完整结束，本次部分内容不会发送。
