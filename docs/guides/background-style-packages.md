# 制作带滤镜的横屏背景

本文面向给 LIRA 制作横屏背景的作者与 AI。普通背景包以「图片或循环视频 + 滤镜参数」的 ZIP 形式交付；使用客户端内置分层特效的成品见下方[窗映四时分层背景](#窗映四时分层背景)。主播导入并选用后，画布和直播画面会自动套用预设参数，之后仍可微调、保存或一键恢复作者默认。所有滤镜只作用于背景，人物仍作为独立来源放在直播软件里。

## 从示例开始

先复制 [lira-pack.json 完整示例](../examples/background-style/lira-pack.json)。里面包含一个写出标准模式全部字段的静态样式，和一个省去默认字段的动态样式——两者视觉效果一致，只在极亮处加了一点柔光，不额外偏暖或偏冷；如果底图本身已经调好色，建议从这组设置起步。两个样式的 `config` 互不影响，改动其一不会同步到另一个。分层美术制作与 Shoost 参数对照见[背景美术与滤镜来源](background-art-workflow.md)。

准备自己的 1920×1080 横屏素材，目录如下：

```text
soft-background/
├── lira-pack.json
└── assets/
    ├── background.png
    └── background.webm
```

只有静态或只有动态时，删除另一个 `styles` 成员及对应文件。前景装饰、雪、灯光等可以分层创作，交付前合成为一张 PNG 或一段循环 MP4/WebM。这个通用背景包的每个样式读取一个 `file`，不接受任意 `layers` 数组；同一张底图可被多个不同滤镜的样式引用。

普通素材支持 PNG/JPEG/GIF/WebP/MP4/WebM；透明静态图优先 PNG，动态可使用浏览器能解码的 MP4（如 H.264）或 WebM。视频默认循环、静音；循环接缝与已烘焙的雪花、反光属于素材本身，滤镜不会从静态照片生成这些运动。

## 参数接口

清单顶层包含 `schemaVersion: 1`、`id`、`name`、`version` 和 `styles` 数组；`styles` 里每一项包含 `type: "background"`、`name`、`file`、`width`、`height`、`config`。`file` 写相对 ZIP 根目录的路径（用 `/` 分隔且区分大小写）；宽高填素材设计尺寸（如 1920×1080 或 2560×1440）。`id` 与 `version` 命名规范见[组件样式包指南](component-style-packages.md#作者目录与清单)。

**全部滤镜字段平铺在每个样式的 `config` 内。** 参数名、类型、取值、步长、默认值、算法与顺序以[背景外观参数规范](../reference/frontend/overlays.md#背景外观参数)为准，源码定义在 [BACKGROUND_FIELDS](../../public/js/shared/background-appearance.js)。不要再创建 `filters` 子对象，也不要使用中文键名。

例如下面只是一个样式的 `config`，应嵌入完整清单，不能作为 ZIP 根清单直接导入：

```json
{
  "colorProcessing": "standard",
  "temperature": 0,
  "glowMode": "normal",
  "glowStrength": 0.12,
  "glowRadius": 12,
  "glowThreshold": 0.9,
  "glowSoftness": 0.1,
  "volume": 0
}
```

- 百分比参数在 JSON 里写成小数（例如 `glowStrength: 0.45` 对应面板 45%，`opacity: 1` 对应 100%）；像素（px）、色温/色调、LGG 系数、色阶和倍速直接填面板数值。
- 新作品请显式写明 `colorProcessing: "standard"`。如果漏写且同时填了非零的旧白平衡或分区染色参数，程序为了兼容老包会自动退回 `legacy` 模式；因此不要省略该字段却直接填色温。
- 缺省参数会补齐默认值。所有新增效果默认关闭或中性；只改辉光半径而不把强度设为大于 0，不会显示辉光。
- 颜色使用完整六位 `#RRGGBB`。`preserveLuminance` 是仅供旧模式的 JSON 布尔字段，标准模式不使用它；保持亮度也不等于保持原色。
- 白平衡是改色工具：正色温偏暖、负色温偏冷。希望保留蓝白原色时，`temperature/tint` 为 0、三个 `lift*` 为 0、三个 `gamma*`/`gain*` 为 1、颜色遮罩强度为 0；需要逐像素原图时同时关闭辉光等全部效果。
- 输入和输出黑场分别必须小于对应白场。色阶通道一次选择 `rgb/r/g/b` 之一，不是四套独立色阶同时叠加。
- 标准调色使用提升（暗部）/ 伽马（中灰）/ 增益（亮部）（Lift/Gamma/Gain，简称 LGG）的 RGB 数值控件：Lift 主要调暗部，Gamma 主要调中灰，Gain 主要调亮部，各区域会相互影响。`gammaRed` 等与色阶里的总 `gamma` 是不同阶段；不要把色轮位置、十六进制颜色或 `.cube` 内容填进这些字段。
- 旧模式的 `shadow*`/`midtone*`/`highlight*` 是兼容用的分区乘色，不是 LGG；新包不要再用它们设计效果。需要暖色灯光时，素材本身应已有对应光源和色彩。
- `backgroundDefaults`、`mediaStyle`、资源 ID、素材 URL 由导入器生成，作者不要填写。作者参数放 `config`，不要放 `media`。
- 这套参数适用于 LIRA 原生背景及其图片/视频样式。导入 HTML 作为网页组件时，不会自动转换成这套背景配置。

这套参数是 LIRA 自身的渲染接口，不支持直接导入 Shoost 工程、VTS `.effects.json` 或 `.cube` LUT，也不能给旧客户端安装新滤镜算法。已有调色成片可将 LIRA 参数全部置为中性，避免二次偏色；与 Shoost 的功能对照及 Unity PostProcessing v1 色彩公式出处见[背景美术与滤镜来源](background-art-workflow.md)。

## 打包和导入

在 `soft-background` 目录运行：

```powershell
Compress-Archive -Path .\lira-pack.json, .\assets -DestinationPath ..\soft-background-1.1.0.zip
```

ZIP 根目录必须直接是 `lira-pack.json`，不要包入多一层 `soft-background/`。完整包限制见[组件样式包指南](component-style-packages.md#打-zip-与检查)，普通媒体单文件不超过 512 MB。

1. 打开 LIRA 画布，在「添加组件 → 背景 → ＋ 添加样式 → 选择文件」选择文件。
2. 核对预览后添加样式，点击静态或动态背景卡片加入画布。多个背景变体属于背景样式包，使用背景分类入口。
3. 选中背景图层，在右侧展开白平衡、Lift/Gamma/Gain、辉光、周边模糊、暗角、色阶或颗粒，检查效果。旧模式显示旧分区染色，播放参数只在视频背景出现。
4. 点「保存并应用」，把画布生成的完整场景地址填进 OBS 浏览器源或哔哩哔哩直播姬网页来源（宽高与画布一致）。不要手写 `/background` 路径，也不要把滤镜参数拼在网址后面。

导入只会把卡片加入样式库，不会立刻改动直播画面。在画布里调参只影响当前背景图层；点「恢复样式默认」可还原作者预设，但同样需要「保存并应用」才生效。从样式库删除卡片不会影响已在画布里用上的背景；修改包内容须提高 `version`，导入新版后不会自动覆盖已有场景，主播需手动更换样式。

如需通过接口自动化导入，直接复用[组件样式库 API](../reference/backend/api.md#组件样式库)：先把 ZIP 传给 `inspect` 拿到预览和 ID，再调用 `install` 安装（须在已授权的桌面端或画布会话下调用；仅制作背景包不需要 API 凭据，也没有单独的滤镜上传接口）。

## 窗映四时分层背景

「窗映四时」提供晴天、黄昏、雨天、夜晚四张场景卡片，共用从房间左侧斜望右侧窗户的视角，窗台与桌沿斜向右下延伸，并叠加独立投光、虹彩、窗玻璃水滴和室内灯光。晴天与黄昏会在投光范围内呈现微动树影；夜晚保持台灯亮度稳定、反光缓缓流动；雨天水滴会折射窗外景物，停留汇聚后滑落并留下渐淡的水痕。素材与动效画布均为 1920×1080（风格参考[示例视频](https://www.bilibili.com/video/BV1nEHQ6iEkB/)重新原创绘制，并非原作者素材）。

在仓库运行以下命令，生成 `tmp/output/窗映四时-背景样式-1.3.0.zip`：

```powershell
node scripts/package-windowlight-background.js
```

按上方[打包和导入](#打包和导入)的背景入口导入 ZIP，选择任一卡片加入画布。四张卡片默认手动显示对应场景，均持续播放动效；手动与定时轮播只控制场景切换。四张卡片都是背景样式，因此使用「背景 → ＋ 添加样式」，不使用跨组件套装入口。

- **手动选择**：在右侧「场景切换」选择「手动选择」，再选择晴天、黄昏、雨天或夜晚。同一个图层可以切换全部场景。
- **定时轮播**：选择「定时轮播」，「场景」作为起点，之后依次循环晴天→黄昏→雨天→夜晚。间隔默认 300 秒，可设为 10～3600 秒的整数。
- 调整后点「保存并应用」。通用滤镜仍可调整；「恢复样式默认」仅恢复滤镜，不更改场景与轮播设置。页面隐藏时暂停运动与轮播，重新显示后继续；系统开启「减弱动态效果」（关闭动画效果）时特效停止运动，定时轮播仍有效。

更新旧版时需同时使用包含新版播放器的客户端；单独导入 ZIP 不会更新光影和水滴播放逻辑。

本包使用已有 `schemaVersion: 2` 受信资源格式和客户端提供的分层播放器，不向通用媒体包开放任意 `layers` 或脚本。四张卡片共享八张 WebP，各自保存所选场景与参数；场景字段、资源归属及生命周期以[窗映四时背景规范](../reference/frontend/overlays.md#窗映四时背景)为准。打包不重复复制四套资源，也不自动安装或修改当前直播画面。

## 验收与常见问题

先导入自己的 ZIP，检查静态和动态成员，再保存、重开并检查正式场景来源。边看视频边调参，播放应连续；与人物来源叠加时只有背景变化。用「恢复样式默认」核对作者预设。最后在实际使用的直播软件上检查 1080p/1440p 的流畅度；大半径模糊、多组滤镜叠加及高分辨率会增加 GPU 开销。

| 现象 | 检查 |
| --- | --- |
| 组件展示参数无效 | 检查字段拼写、JSON 类型、范围、步长、黑白场顺序及客户端是否支持这些字段。不要把 45% 写成 45。 |
| 有滤镜但不像参考图 | 底图光源、纹理、颜色和运动决定大部分观感；本示例只是起点，调参不会补出不存在的街灯或雪景。 |
| 亮部没有发光 | 提高 `glowStrength`，降低 `glowThreshold`；检查前面的调色/色阶是否已把亮部压暗。 |
| 完整显示时留白被颜色覆盖 | 新滤镜保留透明度；原有 `overlayOpacity` 是全画布遮罩，需要透明留白时设为 0。 |
| 同版本内容冲突 | 增加包的 `version`，重新打包。 |
| 导入后当前背景没变 | 从库中选用样式，再保存并应用。 |

仓库的 `test/scenes/component-styles.test.js` 会用合成媒体经真实 inspect/install 校验上述完整示例；`test/overlays/background-filters.test.js` 检查实际像素、透明度和滤镜节点清理。这些检查不代替具体美术素材和实际直播软件的验收。
