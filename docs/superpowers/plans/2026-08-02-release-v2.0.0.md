# Version 2.0.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Execute this plan task-by-task in the current session. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the current `main` worktree as GitHub Release `v2.0.0` by following `RELEASE_GUIDE.md`.

**Architecture:** Treat the existing tracked and untracked worktree changes as the release payload. Update only the release metadata, verify the complete test suite, commit and push `main`, then use the repository release script to build, tag, upload, and verify the Windows artifacts.

**Tech Stack:** Node.js, npm, Git, GitHub CLI, electron-builder.

## Global Constraints

- The package version is exactly `2.0.0` and the Git tag is exactly `v2.0.0`.
- Preserve all pre-existing worktree changes and include them in the release commit as required by `git add .` in `RELEASE_GUIDE.md`.
- Do not change `package-lock.json`; this repository's release guide updates only `package.json`, and the lockfile root version has intentionally remained at `1.6.0` across prior releases.
- The release is complete only when `.exe`, `.exe.blockmap`, and `latest.yml` are present in GitHub Release `v2.0.0`.
