# 礼物页「月底冲刺 × 盲盒盈亏榜」并列布局与美化报告

日期：2026-09-14

状态：实施前设计建议；本次交付报告，尚未修改产品界面

适用界面：LIRA Electron 客户端礼物页

## 1. 设计结论

将「月底冲刺」移动到「今日盲盒盈亏」下方，与「盲盒盈亏榜」组成同一行的两张卡片。建议左侧冲刺约占 40%，右侧盈亏榜约占 60%；两卡等高，顶部与底部对齐，内容保持紧凑、易读。

**正式实施应包含布局调整和视觉美化。此前对话中的示意图只用于说明位置、比例和内容分组，不能直接作为最终界面的外观验收稿。** 成品应延续现有 LIRA 的主题、卡片、数字和控件风格，并完善标题、间距、表单及操作区的对齐关系。

本轮用户明确要求的是：冲刺下移、两卡左右并列、等高、允许不等宽、减少无效留白，以及正式界面需要美化。40:60、冲刺统计 2×2 等是本报告提出的实施基线，不应描述为用户指定的精确参数。

## 2. 现状与调整理由

现状依据用户提供的截图和当前工作区源码。尚未对修改后的 Electron 界面进行实测；报告中的视觉效果和空间改善均为设计目标。

| 当前结构 | 带来的问题 | 本轮处理 |
|---|---|---|
| 冲刺、今日盲盒、盈亏榜依次跨整行排列 | 冲刺与投屏设置被统计区隔开，页面较长 | 今日盲盒之后安排冲刺与盈亏榜并列 |
| 冲刺的四项统计横排，目标输入框占据大部分行宽 | 内容较少，宽屏下出现大片横向留白 | 四项统计改为 2×2，缩短表单宽度 |
| 盈亏榜有标题、人数、两个筛选项和长链接 | 内容比冲刺更依赖横向空间 | 分配较宽的一列，标题输入宽于人数输入 |
| 盈亏榜标题上另有「观众画面」一行 | 两卡直接拼接时，标题高度和基线容易不一致 | 保留文字含义，调整为紧凑的辅助说明 |

## 3. 页面顺序与空间分配

```text
礼物检测                         礼物提示
最近礼物                                  整行
今日盲盒盈亏                              整行
┌ 月底冲刺 · 约 40% ┐  ┌ 盲盒盈亏榜 · 约 60% ──────┐
│ 目标       已收    │  │ 投屏标题          排行人数 │
│ 还差       水晶球  │  │ 盈利筛选          盒型筛选 │
│ 冲刺目标与操作区   │  │ 捕捉链接与复制操作         │
└───────────────────┘  └───────────────────────────┘
盲盒映射                                  整行
```

40:60 仅作用于这两张卡片所在的局部行，顶部「礼物检测／礼物提示」维持原有比例。两卡之间保留现有工作区约 14 CSS px 的间距，明确区分两项任务。

等高采用同一网格行自然拉伸，由内容较高的一侧决定整行高度。操作区靠近各自卡片底部，使视觉收口整齐。禁止用写死的高度、隐藏溢出或大量空白占位来凑齐底边。若短侧形成明显空洞，应先调整字段排布与内间距。

## 4. 正式实施的美化要求

### 4.1 共同视觉骨架

| 部位 | 成品要求 |
|---|---|
| 卡片外壳 | 使用相同圆角、相近边框与阴影强度；以现有盈亏榜卡片的轻量质感为参考，统一两卡的完成度 |
| 标题 | 两个主标题保持相同字号、字重与基线；沿用现有标题强调方式，不为冲刺新增一套图标或装饰 |
| 辅助说明 | 「观众画面」作为较轻的同行说明或紧凑说明行；「直播姬与 OBS 通用」保留，减少重复的纵向间隔 |
| 内边距 | 以当前盈亏榜约 18 CSS px 的内边距为起点，两卡左右内边距一致；标题区和内容区建立清楚的对齐线 |
| 文字层级 | 标题、金额、字段标签、帮助说明各有层级；重要数值不降为示意图中的普通正文大小 |
| 色彩 | 从当前生效主题取色；延续截图中的标题强调与青绿色辅助色关系，不把截图颜色写死为所有主题的颜色 |
| 按钮 | 「保存」「复制链接」沿用现有主按钮；「重置本轮」沿用次级样式；同类按钮高度和圆角一致 |

复用 [共享设计变量](/D:/Work/Live/public/css/styles-base.css:2)：标题使用 `--type-size-section-title`，数值优先使用 `--type-size-metric-md`，标签与说明采用已有控制／说明文字变量，圆角与颜色沿用当前组件和主题。列变窄时先调整布局，避免整体缩小字号来塞入内容。

这里的美化重点是清晰的主次、统一的表面质感和准确的对齐。保留适当呼吸空间；不增加无业务用途的插画、进度环、装饰指标或持续动效来填空。

### 4.2 左卡：月底冲刺

四项统计采用 2×2：第一行「目标／已收」，第二行「还差／≈ 水晶球」。保留现有浅底统计单元，统一内边距与高度；标签较轻，金额醒目，数字继续使用等宽数字特性以稳定更新时的排版。

「≈ 水晶球」沿用现有浅青绿色强调，使它容易被找到。其余三项保持中性背景，避免四块统计都抢占注意力。金额格式、单位和计算结果沿用现有逻辑，示意图中的示例值与千分位不是新的格式要求。

底部保留「冲刺目标（元）」、输入框、「保存」和「重置本轮」。空间足够时输入与按钮同排、底边对齐；空间不足时输入占一行，按钮在下一行靠右。缩短的是过长的输入区域，不是按钮文字或有效点击面积。

### 4.3 右卡：盲盒盈亏榜

按「标题与入口 → 参数 → 筛选 → 链接与复制」组织内容，保留全部现有功能。

| 内容 | 美化与排布 |
|---|---|
| 标题及入口 | 「盲盒盈亏榜」与左卡标题对齐，「打开画面」放在右上角，辅助说明以较轻层级呈现 |
| 投屏标题、排行人数 | 标题输入占剩余空间，人数输入按短数字内容收窄；标签、帮助入口和输入框对齐 |
| 两个筛选项 | 保留现有可点击筛选块与选中状态；能并排时同排，内容放不下时自然换行 |
| 捕捉链接 | 延续浅青绿色功能区，与参数区适当分隔；长地址在自身区域换行，可读取、可完整复制 |
| 复制按钮 | 宽度足够时放在链接右侧，空间不足时落到下一行靠右；不让长链接把按钮挤出卡片 |

现有筛选网格每列最小宽度为 220px，需要随新的卡片宽度重新核对，避免在中等宽度窗口横向溢出。保留 `lira-help` 帮助内容、默认标题、筛选含义和排行人数范围；本轮不把人数输入改造成另一套交互。

### 4.4 窄窗口与等高的边界

并列模式以卡片所在区域的可用宽度判断，而不是直接使用截图的物理像素。可以从内容区约 960 CSS px 作为并排试验线开始，在实际 Electron 字体与缩放下校准；这不是已验证的最终断点。

宽度不足时顺序为「今日盲盒盈亏 → 月底冲刺 → 盲盒盈亏榜 → 盲盒映射」。上下排列后各卡使用自然高度，不再要求等高。统计 2×2 在金额仍可清楚显示时保留，放不下时再调整。

实施须核对 [现有响应式规则](/D:/Work/Live/public/css/admin/responsive.css:15) 中 980px 的统计网格覆盖和 900px 的工作区单列规则。不能把示意图为对话容器设置的断点直接复制进产品。

保留现有统计、保存目标、重置确认、投屏链接生成、复制反馈、筛选和打开画面的行为，尤其保留排行人数 `-1`、`0`、`1–10` 的既有含义。后台、持久化格式、接口和 OBS 画面本身均不属于本轮设计修改。

## 6. 实施步骤与验收

1. **先完成结构与美化。** 按新的 DOM 顺序和局部网格实施，同时完成卡片、标题、统计、表单和底部操作区的样式，形成完整成品再评审。
2. **在 Electron 做一次集中检查。** 查看正常宽度与开始需要换行的窄窗口，使用测试数据检查长金额、长标题和长链接；在隔离测试状态中验证保存、重置确认、复制、筛选及打开画面，不修改真实直播数据。
3. **检查实际受影响的代码。** 核对页面结构与样式引用，运行直接相关的现有检查；若涉及页面组合或样式入口，使用对应的 `admin-page-composition`、`admin-style-ownership` 测试；投屏字段结构受影响时运行 `frontend-blindbox-admin` 相关测试。最后查看变更并运行 `git diff --check`。
