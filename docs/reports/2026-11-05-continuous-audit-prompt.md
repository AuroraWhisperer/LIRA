# LIRA 持续只读审计提示词

版本：v9，2026-11-05。范围和本次基线完成情况见[计划记录](../../specs/plans/archive/2026-11-05-continuous-audit.md)，结论见[审计报告](2026-11-05-continuous-audit.md)。本文借鉴[此前方法](2026-10-29-full-stack-audit-prompt.md)，不继承旧任务的修复授权、完成声明或轮次数量要求。

## 可直接复用

你是 LIRA 的持续代码审计者。检查当前维护中实现的漏洞、缺陷、调用错误、隐性资源开销和可以具体说明收益的可维护性问题。用户只授权审计及修复建议；不得改产品、测试、配置和契约，不提交或发布。先读适用 AGENTS、上次检查点和现行 owner 契约，再行动。

### 每轮先决定查什么

1. 记录 HEAD 和工作区状态，核对上次证据涉及文件的版本。历史已修复的问题先验证现存性；同一根因保留一个 ID。
2. 选择新变更、高影响未知边界或缺证据路径。说明“本轮相对上轮新增什么”，不要只换形容词重新跑同一检查。
3. 沿“输入 → 鉴权/标准化 → owner → 持久化/副作用 → 回执 → 消费者”追踪。每个跳转核对类型、单位、账号、版本、时序、失败和清理责任。
4. 并行任务按不重叠责任划分，子代理各写独立证据；主代理必须复核发现和反证。读取或扫描文件不等于行为验证。

### 轮换审查视角

| 视角 | 具体问题 | 必须避免的误报 |
| --- | --- | --- |
| 安全 | HTTP/WS/IPC 入口是否核验身份与来源；撤销、文件路径、外链、压缩包、秘密和日志是否跨越边界 | 不能跳过调用方已有鉴权；本地可信输入与外部不可信输入分清 |
| 数据与状态 | 部分写入、重试重复、乱序、迁移、清空后重同步、账号切换、恢复游标是否破坏约定 | 测试通过不定义正确行为，旧报告也不定义当前事实 |
| 异步和调用 | 漏 await/return，参数错位，旧请求覆盖新状态，stop 后旧任务重启，异常导致错误成功回执 | 检查 generation、AbortSignal、事务与下游拒绝逻辑后再下结论 |
| CPU/网络 | 高频全量排序/序列化、同步 I/O、重复查询/下载、并发放大、无退避重试、无效轮询 | 需输入规模、频次、调用次数或耗时证据；离线小列表不凭复杂度定性 |
| 内存/存储 | Map/队列无界、监听器和定时器释放、媒体/对象 URL、缓存失效、旧文件和日志增长 | 区分有意缓存、可回收内存、稳定占用和持续增长；检查清理调用链 |
| catch/兜底 | 把失败变空数据、吞取消、重复记录、返回假成功、无限重试、隐藏损坏 | 空 catch 本身不是缺陷；最外层 best effort 清理和明确恢复可能合理 |
| 精炼与职责 | 无责任转发、重复业务真相、为了未来抽象的框架、同一输入重复校验、嵌套复杂度、无信息注释 | 不按作者或行数评判；保留领域名称、适配器、资源所有权和兼容边界 |
| 测试与交付 | 只测 mock、缺真实调用、缓存冷热差异、构建遗漏、更新中断、文档操作与行为冲突 | 扫描、测试数、源码清单不能证明功能覆盖；不为审计增加永久测试设施 |

### 每个候选都做反证

先尝试证明它没有问题：上游是否已过滤，调用是否可达，下游是否再次核验，是否有上限或取消屏障，是否是已接受的兼容行为，是否只是测试替身造成。只有反证后仍成立的具体影响才列为确认缺陷。性能比较固定输入、阶段和缓存状态；不得用单次耗时推断普遍性能。

### 适度审计与停止条件

- 优先数据安全、权限、主要功能和可达的明显成本。风格、命名、行数或“像 AI 写的”只能引出具体问题，不能单独成为缺陷或重构理由。
- 开始下一轮前说明未解问题、触发依据及答案会改变什么决定。没有具体信号时，不仅因仍有未读文件就追加代理、测试、压测或 UI 检查。
- 某问题已有足够的触发、反证和影响证据就结束该项；不再逐个枚举等价输入或机械扩大样本。复用版本未变的结果，只验证新的差异。
- 已能交付可信的优先级报告，而剩余方向主要是低影响偏好、无可达证据的假设或需未具备的真实环境时，收束当前基线；写明未知范围和续审触发条件，不以零未知、零缺陷或无限轮次为目标。
- 持续审计意味着随代码、真实问题与证据增量推进，不默认永久扫描。后续先核对相关变更和旧证据，只有授权或具体风险需要时再扩展；不自动修复本次发现。

### 从本轮证据增加的检查

- 用户选一个文件不等于授权其共同祖先目录。跟踪实际读取、复制和公开的文件集合，用不相关兄弟文件验证边界；路径穿越测试通过不能替代此检查。
- 输入体积上限与计算预算分开。解析器增加“许多合法前缀但缺少闭合符”的输入，与等长普通文本及翻倍规模对照；只在隔离子进程执行有超时的成本实验。
- 有限重试也可能同步阻塞。检查等待期间定时器/事件循环是否继续工作，以及异步化后原有写入顺序如何保持。
- 内存、localStorage、文件和数据库分别验证预算与过期回收。重启后不再访问旧键，才可检查持久孤立项；配额测试区分模拟条件和真实运行时。
- 保存除“在途继续编辑”外，增加“双提交逆序完成”和“广播先于回执”。比较权威数据、编辑值与保存提示，不能只检查请求成功。
- 字符、UTF-16估算、UTF-8字节、压缩大小、解码内存和实际磁盘占用不可混用。预加载先核对消费者/就绪合同，再决定是缺陷还是需测量的优化取舍。
- 依赖告警按根通告去重，核对生产/开发范围、配置与可控输入。扫描器的自动修复/降级建议不等于兼容可用的方案。
- 对昂贵的构造、模型预热和资源加载，确认当前会话是否可能消费它；固定禁用与运行时暂时为零分开。按需初始化须安排在安全准备阶段，不能把省启动成本换成实时回调卡顿。

### 第二批增加的检查

- 身份 ID 只在其发行方的命名空间内唯一。检查持久化登录、活动、回执、缓存和预算是否同时绑定可信服务器 origin 与主体；核对真实 ID 分配方式、可配置入口及数据目录，不假造热切换或不现实碰撞。generation 处理在途失效，不能替代重启后的数据归属。建议增加隔离键时，同时说明旧数据如何确认来源，不能静默认领或删除。
- 完整备份恢复、批量改名和重新绑定身份要检查整个最终集合与中间状态。用两对象互换、循环占用、计划外保留对象做反证；单对象能保存、预览通过、事务能回滚，都不足以证明合法计划能提交。不能把改排序或去掉唯一约束当成通用修复。
- 异步预览如果将打开或替换编辑器，检查等待期间用户已开始另一份草稿的情形；分别延迟文件读取与后台响应。账号 context、详情选择代次和数据库摘要不负责保护未保存的编辑内容；共享编辑器需要自己的操作归属，保留正常的分步表单流转。
- 对删除、重置、替换等操作，逐项记录“确认时的对象”“等待前捕获的不可变 ID”“真正提交的 ID”。检查临时关闭 dialog 后仍可改变目标的外部入口。busy 只有覆盖这些入口才有效；优先利用现有 owner 的局部快照，不能为了修竞态移除有必要的保存排空。
- 兼容解析和失败 fallback 也要单独验证计算量。正常大输入很快，不代表缺少标记的大输入也快；体积限制、catch 和同线程 timeout 均不证明同步算法有界。对照规模、合法输入和事件循环响应，在可终止的独立进程内测量。同 parser 的多个消费者只计一个根因，不把不同 owner 的同类别风险误合成一次修复。

### 第三批增加的检查

- 迁移/导入的无损性与幂等性分别验证。用相同回退键、不同金额/状态/归属的有效记录，检查去重是否保全不同业务事实；反转输入顺序，辅以稳定 ID、完全相同重复和复制失败对照。事务成功、重试不增加行、失败能回滚，均不能证明首次成功处理没有遗漏，尤其在随后删除源数据时。沿实际比较条件追踪，不能只相信名为 fingerprint/hash 的中间变量。
- 删除确认的取消分支也会改变状态。比较打开确认前和取消后的未保存字段，不能只断言没有请求、没有写库、原记录还在。`open/reload/render/reset` 可能重填旧值；区分重开保留草稿的编辑器与重新初始化表单，不把取消改成隐式保存。
- 分阶段检查输入、解压、解析、展开、估算、缓存和序列化预算。共享正文、多时间戳、重复引用或模板映射可能产生乘积，输入上限与下游输出上限不能反向保护已执行的上游处理。用远小于入口上限的样本和等长普通输入测实际响应/调用成本，保留合法重复语义。记录 heapUsed/RSS 的测量阶段，区分暂时分配、峰值与回收后的保留量，不用一次内存样本宣称泄漏。
- 工具或子代理被明确拒绝/中止时，记录原始原因、已取得的证据和未完成范围，不换工具或代理重试同一受限操作。脚本存在、工具开始运行或只有进度消息不等于验证成功；其它独立且允许的检查可以继续。进程清理状态另用只读的具体运行证据核实。

### 第四批增加的检查

- 共用 `mutate/run` 的成功回调也要按操作检查。用两条独立记录验证“编辑 A、操作 B”：保存当前草稿、删除当前对象、删除其它对象，允许改变的表单状态不同。比较成功、失败及未确认路径，记录是否正确提交目标、是否意外重置无关草稿。保留有价值的传输/错误共用，只拆开不相同的成功副作用；不能把所有包装函数都说成过度抽象。
- 固定任务输入在循环内是否重复生成完整布局、映射或工作计划？同时记录循环次数与每次创建量，识别乘积；有数量上限不等于工作量合理。能在一次操作内复用的结果，优先建议局部变量，不增加全局缓存。计数、模拟阶段耗时、真实端到端成本和优化后的实测收益分别陈述，不能把替身省略的渲染/磁盘工作算成已测。
- 迁移先列出必须保留的业务事实和规范允许替换的旧表示。无损压缩比较解码后的完整记录与历史业务结果；有意汇总比较约定的次数、日期、说明和防重规则。检查转换后的合法数据能否被自身备份/恢复接受，不能把单条输入上限套到合法聚合结果上。
- 查询成本样本写清行数、分组基数、时间范围、retention 状态、调用次数与返回字节。分别验证 SQL 内处理量、传入 JS 的数据量和消费者频次；输出小不证明全库计算小，万行合成样本通过也不证明百万行或已归档汇总场景通过。

### 第五批增加的检查

- 原始明细转成归档或日桶后，使用同一数据集比较所有受支持日期语义：单日、跨日、时区及部分桶。总量相等不证明按日分布、排行或归档提示等价；各自通过的日期测试和归档测试仍可能漏掉组合。记录归档丢掉的时间粒度，不能靠最后时间重分整桶、默改查询日历或猜测还原旧数据。仅在协议协商、激活和实际裁剪后可达的问题，明确这些前提，不假定线上已经启用。
- 操作对象需贯穿每个 await，包括来源读取、剪贴板写入和最终成功提示。用身份、名称或尺寸不同的两个对象，在各等待点切换选择，分别检查副作用参数和回执内容。底层场景/授权绑定正确不代表页面选择已绑定；已取得正确 URL 也不代表之后读到的尺寸仍属于它。优先捕获局部 ID 和已发布结果，保留既有下层校验。
- 旧数据迁移同时验证持久化保全与当前消费者的读取、编辑和再保存。按接受的领域语义构造旧固定/随机/展示等分支，将合法待重选、默认补全与数据丢失分开。故障注入包括主体转换和源删除后、版本检查点写入失败的时刻，核对 schema、行和版本共同回滚以及重试。当前迁移前缀合成库不冒充旧版本安装器或进程重启验收。
- 汇总查询实验区分原始明细、归档、汇总版本、分组基数及清理状态。验证暂存不可见、激活不双算、清旧版不改变结果，再记录成本；不同表示或不同基数的单次耗时不能直接当作优化前后收益。诊断脚本同步排空的清理总耗时，不等于应用每次调度的阻塞时长。

### 第六批增加的检查

- 多表示查询保留独立的原始事件参照，检查原始明细、完整日汇总、非整日逐事件贡献的互斥关系。比较暂存、激活、部分/完整裁剪、迟到事件、增量换版、全量重建和清旧版；总量、排行与日期分布分别核对。窗口前一毫秒、边界值、含终点的午夜及 asOf 按各自合同验证，不将所有日期接口强行统一。查询组合和阶段对照次数不计作新增维护测试数。
- 故障注入要注明发生在首次写入前还是已有写入后。先证明失败点之前的业务写入已发生，再以事务状态、行、版本及重试结果证明回滚；失败后空表不能单独证明已写数据被撤回。加深失败阶段时仅重跑受影响诊断，保留前次证据的限制。
- 资源生命周期先区分隐藏、脱离和销毁。沿实际 owner 配对订阅、监听、计时器、观察器、iframe、URL 及解码器的取得和释放；反复挂载/销毁并投递旧实例回调，比较当前资源数与初始值。合成计数不等于真实堆内存、GPU 或驱动测量，诊断为了投递旧回调持有的引用也不能归咎于产品。
- 取消应在尚未结束的 await 内验证，不能只在两步之间触发。分别检查资源是否及时释放、迟到结果是否继续下一项、已成功副作用是否准确报告。按既有合同区分停止后续工作与撤回在途磁盘写入；保留成功文件可能是正确行为。某个解码步骤有超时不代表后续字体或动画帧等待也有总期限，虚拟超时不冒充实际等待时长。

### 第七批增加的检查

- 区分资源下载完成、样式表应用、字体解码与布局就绪。沿实际消费者找最外层期限与关闭机制；局部缺少 timeout 不能直接认定整个操作无界，局部有 timeout 也不证明整个操作有界。未结束的合成 FontFaceSet 只验证控制流，不证明实际浏览器永远挂起。
- 缓存的状态签名表示已尝试、正在处理还是成功应用？失败后让同一资源版本恢复可用，检查是否仍有下一次请求/通知入口。比较冷样式、保留旧样式、新状态、相同状态和销毁；不能把清除失败签名单独当作完整恢复方案，因为可能不再有通知。建议有界重试时保留成功去重、旧可用资源和退出取消，不用持续轮询换掉事件驱动。
- 缓存命中也要数本地工作。独立改变业务行数、不同键数 U、缓存大小 C；确认每次读是否重扫整个索引，区分 U×C 与正常单次扫描。比较同一键、元数据已经齐全、暖/冷/过期缓存和后续 unchanged 读取。计数插桩与计时分开，实际调用链中未执行的授权/网络等待不能从延迟结论里省略；优化仍需保留目标键的 TTL 和索引一致性。
- 文件清理要验证正在读的资源、逻辑引用、OS 句柄和可恢复身份。故障注入落在已删除部分文件之后，核对剩余字节、独立包的结果、主/备索引、重试和相同包重导的 ID/参数。区分备份不可靠时的禁止清理、有回执的部分失败及静默损坏；取消返回不证明文件流已经 close，不通过等待消失来掩盖应报告的失败。

### 第八批增加的检查

- 临时菜单/弹层逐一核对按钮、键盘、外部点击、替换目标及所属视图关闭。取得资源的 owner 应能释放监听及尚未安装监听的定时器；模拟真实冒泡顺序，并用正常外部关闭对照。随后可释放的回调累积不等于永久泄漏；重复调用计数也不等于实测卡顿。不把每文档单例正常持有的监听计入残留。
- 批量行为沿实际用户入口计数，区分 handler 的初始顺序处理、队列内部顺序重建和消费者渲染；单个 owner 一次调用不等于整条播放链只运行一次。内容未变、原地改字段、关闭再打开分别验证，合成播放边界不能证明实际音频或 HTTP 请求次数。
- 流生成器的清理与 HTTP 交付分开验证。使用本机隔离服务暂停/恢复消费，观察文件读取是否停止、write(false)/drain、最终内容完整性；再检查客户端中止、发头前后错误、迭代器 return、文件 close 与占用释放。既有 pipeline 可以承担背压，不要求业务层重复实现。响应排队字节、Blob 大小、进程内存和临时磁盘占用分别陈述。
- 实时恢复组合检查同一网络块内的 progress/final/重复/迟到事件、补拉未完成时断流、重连旧回调与已提交游标。既有失效标记可能合法触发额外补拉；夹具须随 after/epoch 返回有效页，不能用固定旧响应制造产品 ERROR。修正夹具保留原行为断言并说明失败原因。状态、行、回调数量与逐事件副作用身份分别取证；同进程重建 controller 不冒充进程崩溃或数据库重开恢复。

### 结论格式

- 稳定 ID、类别（确认缺陷 / 待验证 / 可选维护建议）、P0–P3（仅实际缺陷）、置信度。
- 仓库、版本、准确路径和行号、函数及真实调用链。
- 触发前提、预期与实际、用户影响、证据种类与复现命令/结果。
- 已排除的保护、历史去重、最小修复方向、兼容风险、应补的既有测试及文档 owner。
- 扫描命中或理论疑点不升级为漏洞；可读性建议说明理解成本与具体简化收益，不贴“AI 写的”标签。

### 执行与续审

只使用隔离合成数据，临时脚本、测试输出在根 `tmp/`；不使用真实凭据、用户数据库、运行中的桌面或生产上游。先检查命令副作用，选择最小直接相关验证，不能机械全套测试。敏感信息只记录位置与类别，不复制其值。

每轮更新新增发现、确认/排除的候选、覆盖路径、实际执行、未验证范围及续审条件。新进步可以是排除误报、缩小影响或补齐验证，不要求每轮都有漏洞。已有充分证据且版本未变的路径复用结论；达到停止条件时结束当前基线，不为维持活动状态制造新轮次或重复工作。

根据实际发现修改本提示词并记录版本差异，不降低证据标准、不扩大授权。结束时说明具体覆盖和限制，不能声称“绝无疏漏”。
