## C　实现遗漏

| 原项 | 证据与处理 |
| --- | --- |
| C1　管理页路径 | **遗漏成立。** HTTP 授权守卫改用 `ADMIN_PAGE_PATHS`。原四条手写路径与公共名单相同，能证明的是维护分叉，不能据此认定曾有路由绕过。 [路径名单](../../src/shared/admin-page-paths.js) |
| C2　富文本的三处遗漏 | **全部采纳。** 礼物答谢直接复用共享选区恢复。文本框插入标记改用编辑器实例内计数，不依赖安全上下文里的 `crypto.randomUUID()`。许愿编辑器直接使用恢复时返回的 Range，避免二次查询拿到空值。三个编辑器各自处理 token、粘贴、序列化与撤销。 [共享选区](../../public/js/admin/rich-text-selection.js) |
| C3　原子写入与响应流 | **采纳。** 写入或替换失败才清理临时文件，清理失败保留最初错误，成功后省去额外删除。对可注入的流 reader，即使 `cancel()` 缺省或同步抛错，也会释放锁。合成失败和本地 HTTP 流回归均已覆盖。 [桌面实现说明](../reference/desktop/main.md) |
| C3　更新器、登录、错误码及 IPC | **部分采纳。** 更新器先安装日志回调，再惰性加载依赖。生产启动先配置更新器，再安排启动检查，现有路径无法复现“启动前静默丢通知”，因此未引入通知队列。音乐登录失败日志补回平台，两处礼物互动错误码共用校验并保留各自回退，周表 IPC 用现有注册器限定一个参数。 [更新流程](../reference/desktop/update.md) · [桌面通信](../reference/desktop/preload.md) |

| C4　动态礼物说明与旧报告 | **采纳并勘误。** 导入样式卡的金额输入和内置卡共用同一段可访问说明。上轮报告称礼物审计输入占位和签到抽签段已精简，当时两项均未落地。本轮已实际修改，保留有效的操作步骤、草稿冲突和旧服务器限制。 [动态礼物卡](../../public/js/admin/gift-frame-styles.js) · [上轮勘误](2026-11-23-client-duplication-audit.md) |

## III、IV　复核稿认可和撤回的项目

第三节列举的是上轮已经采纳的项目。本轮从这些修改的真实入口复查，发现的遗漏已列在 A、B、C 和 II。主窗口 IPC 注册器的归口限于它负责的发送方、页面路径与参数校验，授权窗口、原生子进程和各业务自身的权限检查仍有各自职责。

第四节撤回的建议与现有实现相符，具体保留理由如下。

- 独立资源参数面板并未通过嵌入面板再挂载第二个计时器。播放器全屏仍用到唱片定位、圆形裁剪、图片和旋转。歌词注音、PK 分组、粉丝面板及按钮等选择器含有有效的尺寸、交互或视觉变体。
- 刷新和面板入场动画有按名查询或监听结束的 JavaScript，歌曲信息覆盖层有独立样式入口。授权续期按墙钟重新计算期限，以处理休眠。按码点与按 UTF-16 单元散列结果可能不同，另有渲染器受固定源码约定约束。
- 一维与二维拖拽在坐标、滚动、回滚和焦点上不同。富文本、头像容错、金额前缀、日期时区、两种审计表格和下载通知均保留直接服务其调用方的行为。不同导入阶段的提示、编辑器旁的变量和直播主持快捷键也有实际用途。
- 礼物效果来源确实可能带 `?giftStyle=`。歌单选择器的滚动列表、独立页面字体与重置、窗口控制及审计页紧凑控件各有独立布局。音频白名单、桌面本地目录重试、取色与播放输出、云端回复及子进程恢复继续按所属安全或生命周期约定处理。
