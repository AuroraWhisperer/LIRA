### 1.1 改写时必须遵守的 4 条硬约束

1. **章节编号是硬编码文本**（`<span class="usage-guide-section-index">01</span>`）。插入或追加章节都要改编号 —— 落地映射见 3.1。
2. **目录是手写的三组**。新增章节必须同步加目录项，确保章节可从目录访问并正确显示高亮；搜索索引本身按正文 section 建立，并不依赖目录条目。
3. **搜索支持章节标题、章节直属 `p` / `h4`，以及 `article` / `details` / `.usage-guide-steps > li` 的文本**。其他容器中的独立内容需检查是否被覆盖；不要为了搜索给每个段落强套 `article`。
4. **版式元件复用现有 class**：章节标题、特色卡、`usage-guide-grid`、`usage-guide-step-pair`、`usage-guide-notice`（warning / danger）、`usage-guide-chip`、`usage-guide-faq`；样式在 `public/css/admin/other-features/usage-guide*.css`。现有正文没有表格；优先复用卡片与短列表，比较类内容可按需要使用表格并检查样式和搜索覆盖。

### 4.3 数据边界（写数据保存说明用）

通用云同步控制器管理 `settings`、`songs`、`bilibili` 三个范围，但它不是全部云端数据的清单。弹幕姬样式、背景图、机器人等有独立接口；判断数据归属必须核对所属功能的读写路径。

**① 会跟着账号走的**

- 歌库（上限 **5000 首**，**整份覆盖**，不会自动合并）；
- 点歌行为设置：直播间号、接收弹幕和礼物、暂停点歌、最多排队歌曲数、点歌间隔、只允许歌库歌曲、允许重复点歌；
- 直播账号（B 站）登录状态；
- 盲盒设置（官方自动同步 + 自定义那部分）；
- 弹幕姬已应用的样式、各样式参数与全屏随机停留时间（服务器按主播保存；尚未应用的编辑草稿不等于已保存配置）；
- 弹幕触发礼物特效开关（`giftEffectDanmakuEnabled`）；
- 礼物页两个云端开关：**自动答谢礼物**、**弹幕查询礼物统计**；
- 歌单页背景图（每主播只保留最新一张，新的覆盖旧的）。

**② 只保存在这台电脑（换电脑要重做）**

- 点歌队列、播放队列和 LIRA 的本机播放历史；QQ 音乐、网易云的「我喜欢 / 收藏歌单」由对应平台账号提供，换电脑后需重新登录该平台，不要将其归为 LIRA 本机收藏数据；

- 投票与评分的外观设置（代码里明确「不参与云端设置同步」）；
- 礼物导出目录、**月底冲刺目标**、礼物提示开关；
- 音乐平台登录（QQ 音乐 / 网易云）、全民 K 歌缓存路径；
- 日历、备忘、待办、粉丝档案（本机数据库）；
- 小游戏历史、动态抽奖的本地记录（最近 50 场）。

**③ 跑在服务器上、关了客户端也在工作**

- 礼物记录（云端账本）；
- 自动答谢、弹幕查询礼物统计（界面原文：「由服务器持续运行，退出软件后仍有效。」）；
- 签到机器人、抽签机器人、PK 对手信息播报、进场欢迎。

**④ 要提醒主播的两个坑**

- 现有正文的「盲盒设置会同步」不能直接认定错误；应明确它指盲盒配置，不扩展为冲刺目标、礼物边框等所有礼物设置；

## 五、写作规范（面向主播）

### 5.1 三条硬规矩

1. **用「你」，不用「您」。**
2. **一个动作一句话，动词开头**：打开、点击、填写、勾选、粘贴、复制、等待、刷新、重试、确认。
3. **句子短、段落短**：一个动作一句话，通常一段 1–3 句；不硬性限制 20 字，避免截断完整按钮名或必要条件。

### 5.2 界面文案要「抄」，不要「转述」

| ❌ 不要写 | ✅ 要写 |
| --- | --- |
| 点击进入账号登录入口 | 点击「扫码登录直播账号」 |
| 在设置中开启弹幕接收 | 打开「点歌 → 设置」，把「接收弹幕和礼物」改成「启用」，再点「保存设置」 |
| 切换至直播间管理界面 | 点击右上角的「刷新直播」 |

### 5.3 术语翻译对照表

| 代码 / 后台里的词 | 文档里要写成 |
| --- | --- |
| 服务端 / 云端 | 账号云端、服务器（首次出现补一句「就是保存你歌单和礼物记录的地方」） |
| API Key | 密钥（API Key） |
| Token / 凭据失效 | 登录过期 |
| overlay / 浏览器源 | 直播画面链接、浏览器源 |
| 同步冲突 / 覆盖 | 会用这台电脑的歌库替换云端歌库 |
| 逐字歌词 | 逐字歌词（跟唱时字会跟着亮） |
| 大航海 / 舰长 | 大航海（舰长、提督这些） |
| 盲盒盈亏 | 盲盒盈亏（开盒花的钱和开出来的价值差多少） |
| 403 / 请求失败 | 提示「XXX」，说明…… |
| 初始化状态 | 准备中与完成分开写；「正在为你准备直播工具」只表示准备中 |

### 5.4 让人安心的四类句子

| 场景 | 模板 | 例子 |
| --- | --- | --- |
| 操作会失败 | 「如果 XX，就 YY；不用 ZZ。」 | 「失败时检查网络并点击「重试」，不用重新注册。」 |
| 会覆盖数据 | 「这只是替换云端，不会删除这台电脑的歌曲。」 | 「点击「同步到网页」并确认后，会用这台电脑的歌库替换云端歌库。」 |
| 不可恢复 | 「无法恢复，请确认后再操作。」 | 「清空全部记录」那段 |
| 不用管它 | 「保持默认即可。」 | 「安装位置不用修改，直接点击「安装」即可。」 |

### 5.5 禁用清单

- **禁用词**：旨在、致力于、强大的、一站式、助力、赋能、打造、极致、智能化、全方位、多维度、闭环、抓手。
- **禁用句式**：「需要注意的是」「值得一提的是」「为了更好地…」「综上所述」「如下所示」「本功能支持」→ 换成「提醒：」「另外说一句」「简单说」「这个功能能帮你」。
- **禁用被动语态**：「歌曲会被自动同步」→「会自动同步歌曲」。
- **禁用双重否定**：「不是不能…」→ 直接说可以的。
- **中英混排**：中文之间不加空格；数字与单位之间留一个空格（`5 MB`、`1–30 条`）。
- 破折号、省略号克制使用；不要用「～」卖萌，主播是要干活的。

**自检**：写完一段读出来 —— 像在跟人解释 → 过；像念说明书 → 重写。一段里出现两次以上「以及」「并且」「相关」→ 拆句。

### 5.6 可复制的模板

**功能说明**

```text
【这个功能是干什么的】（一句话）
【在哪】点歌 → 设置
【怎么做】
1. 打开「点歌 → 设置」。
2. 先扫码登录直播账号，并填写要连接的直播间号。
3. 把「接收弹幕和礼物」改成「启用」。
4. 点击「保存设置」，再检查右上角的直播间连接状态。
【你会看到】右上角显示实际连接状态。保存成功只表示设置已保存，不等于已经连上直播间。
【没成功】若显示「未设置直播间」，核对房间号并保存；若提示连接异常，按提示检查账号，再点击「刷新直播」。登录失效时重新扫码。
【提醒】服务器连接正常时，关闭客户端仍可继续接收礼物；要停止接收，将第 3 步改回「暂不启用」并保存，确认服务器设置已同步。
```

**FAQ（三段式：判断依据 → 一个动作 → 仍失败的下一步）**

```text
问题：用主播会说的原话当标题（不要写「连接异常处理」）
1. 先做最简单的检查（一句话）
2. 再给出对应入口（带完整路径）
3. 最后给「找谁」或「记录什么」（比如日志目录）
```

**改写示例**

> ❌ 系统会自动同步并覆盖云端歌单数据，用户需注意多设备并发修改可能造成数据不一致的问题。
> ✅ 歌库会自动同步到同一账号的其他电脑，不用手动上传。**但不要同时用两台电脑改歌库**——最后同步成功的那一份会替换掉之前的内容，LIRA 不会自动把两边合并。

> ❌ 清空操作不可逆，请谨慎执行。
> ✅ 点「清空全部记录」后，这个账号在这台电脑和云端的礼物记录都会永久删除，其他电脑同步后也会跟着清空。**删了就找不回来了**，确定要清再点。

- **观众点了歌没反应**——冷却时间可能静默拦截，但也应检查监听、暂停状态和指令，不能把无响应一律归因为冷却。这条要特别说明，否则主播会以为软件坏了。

### 7.3 FAQ 写法

三段式（判断依据 → 一个动作 → 仍失败的下一步），**问题标题用主播会说的话**（「歌单传不上去」「点了没反应」），正文第一句给出**界面上的原话**。示例见 5.6。
