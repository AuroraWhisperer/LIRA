# LIRA 文档

## 维护规则

- 架构文档保留必要的职责摘要并链接实现参考；不复制端点表、DTO、DDL、常量清单或配置模板。
- 技术参考可以解释局部协作上下文；跨系统的决策理由由 ADR 维护，尚未实施的步骤由计划维护。
- 修改事实时直接更新原章节；历史变化放到计划或报告。不要通过文末追加“本节替代前文”保留两套现状。
- 规格定义要求，代码与测试证明当前行为。发现两者冲突时记录差异，不为了整理文档擅自改变 Accepted 需求或产品行为。
- 已完成或被替代的计划移入 `specs/plans/archive/`。未补齐验收、明确延期和等待输入的工作保留准确状态，不能为了归档勾选完成。
- 移动文档时更新入站链接、owner 路由和校验清单；引用当前代码优先使用文件及符号名，历史报告保留基线日期。

`npm run verify:docs` 检查导航、路径和结构约束；语义一致性仍需对照 owner、契约与代码。检查通过不等同于真实账号、生产服务或正式安装器验收。
