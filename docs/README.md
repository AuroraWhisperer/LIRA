# LIRA 文档

**术语说明：** 本项目面向 B 站（Bilibili）直播；OBS 和哔哩哔哩直播姬都是支持的直播软件，通过「浏览器源 / 网页来源」加载 LIRA 直播画面。文档里提到的通用画面能力同时适用于两者；早期计划、报告和截图里只写到其中一款软件的，仅反映当时的使用场景，不代表产品只支持那一款，也不说明另一款当时已经实测过。

请先按要查的问题选入口。现状说明、需求规格和历史记录分开维护，不能只因为某份文档写得更新，就把它当成最新的需求或架构决策。

客户端以 Electron 桌面端为主：主进程内运行 Node.js 本地服务与业务逻辑，前端采用原生 ES modules 与 CSS，业务数据存于本地 SQLite；电音助手和可选的原生音频输出由独立的 C#/.NET 进程承担，通过受限 IPC 与管道由主进程管理；服务端负责礼物基准数据、云端机器人及登录后的同步。系统边界见[架构](architecture/README.md)，版本与依赖见[构建参考](reference/engineering/build.md)。

## 维护规则

- 每次代码变更按根 [AGENTS.md 的测试与文档同步规则](../AGENTS.md#test-and-documentation-synchronization)在同一任务内核对并更新受影响内容；应用内使用文档和交互式引导也属于检查范围。
- 更新应用内使用文档时，按[使用文档跳转维护规则](reference/frontend/pages.md#使用文档跳转维护规则)核对受影响的文档内链接和其他页面入口，确认目标内容对应、锚点唯一且首行不被目录条遮挡。
- 架构文档保留必要的职责摘要并链接实现参考；不复制接口表、DTO、DDL、常量清单或配置模板。
- 技术参考可以解释局部协作上下文；跨系统的决策理由由 ADR 维护，尚未实施的步骤由计划维护。
- 修改事实时直接更新原章节；历史变化放到计划或报告。不要通过文末追加“本节替代前文”保留两套现状。
- 规格定义预期要求，代码和测试反映现状。两者不一致时先记下差异，不要为了整理文档擅自改动已确认的需求或产品行为。
- 已完成或被替代的计划，只有具备决策依据、复盘、验收或引用价值时才归档到 `specs/plans/archive/`；已入库且成果明确的过程步骤与发布清单可以直接清理（规则见 [PLANS.md](../PLANS.md#locations-and-lifecycle)）。尚未验收、明确延期或等待确认的事项必须如实保留状态，不能为了图省事顺手勾成已完成。
- 挪动文档位置时，同步更新所有入站链接、归属路由和校验清单；引用现行代码优先写文件路径和符号名，历史报告保留当时的核对日期。
- 已被现行文档替代、且不再被其他文档引用的旧报告可以移出 `docs/`；只要仍用于支撑决策、未结项或验收，就应保留，不能单凭日期旧就删掉。（早先记录的 `tmp/docs-alignment-2026-10-27/` 目录已失效，不再作为原文归档，历史证据说明见[报告索引](reports/README.md)。）

`npm run verify:docs` 只校验导航链接、路径和文档结构，内容本身是否准确仍需对照归属文档、契约和源码；该检查通过不代表已经过真实账号、线上服务或正式安装包的验收。
