# 音频设备接入与易用性实施计划

Status: Awaiting Verification

## 目标与范围

按用户要求提供接近常见音乐播放器的设备使用体验，使用 LIRA 自有界面与名称，接入播放器音乐、麦克风、线路输入、声卡回送及指定播放设备的声音。普通操作只需选择来源与输出，格式自动匹配。后续用户明确要求实际播放接口选择，该部分由[原生输出计划](2026-10-20-native-playback-outputs.md)接续，本计划保留输入端点与声道职责。

当前电脑有两个播放端点与两个录音端点。内置播放器的“系统默认 + 两个输出”与系统一致，并非数量写死；真正缺口是电音助手只有进程采集与文件输入。处理核心固定为 48 kHz 双声道浮点，现有设备断开保护、播放器隔离与恢复必须保留。

不重写曲库、播放时钟或音乐服务，不安装驱动、不修改系统默认设备、不提交或发布。Windows 未暴露的硬件输入、仅 ASIO 的内部采集通道和独占回送不能宣称已支持。输入仍使用 Windows 共享音频路径，输出接口范围由接续计划定义，不伪造设备或格式选项。

## 决策与职责

1. **复用现有原生工作程序。** `native/audio-assistant/AudioDevices.cs` 枚举输入端点并读取所选设备格式；新 `DeviceCapture.cs` 负责设备输入/输出回送、声道映射、格式转换和释放。`AudioEngine.cs` 继续拥有处理与最终输出，不增加服务或运行时依赖。
2. **输入类别显式区分。** `source` 增加 `input`、`loopback`；设置增加 `deviceSource`、`inputId`、`loopbackId`、`inputChannels`、`inputMusic`。原 `auto/file/pid` 和 `external` 兼容。设备来源默认保留人声，只有用户启用“音乐处理”才使用声伴调节；设备输入不使用歌曲结束监控或播放器端点静音。
3. **路由保护按来源执行。** 播放器维持现有隔离/恢复契约。设备回送禁止最终输出指回被采集的同一端点；硬件回送仍需用户在声卡中排除最终输出，不以不同名字推定隔离。设备丢失停止，重接后由用户重启。
4. **界面延续现有设计。** `audio-assistant-controls.js`、两个助手页面片段及既有 CSS 展示设备选择、按实际声道生成的选项、输入/输出电平；设备模式使用“处理声音”。内置播放器输出继续由 `output-device.js` 负责，通过说明明确这里列的是播放设备。

IPC 扩展由 `src/electron/ipc/audio-assistant-ipc.js` 校验，原生会话核实当前设备与实际声道。主窗口、来源、路径、授权文件和恢复守护边界不变。设置只在本机保存，旧文件读入默认值，关闭或重载不会自动打开麦克风。

## 验证记录与剩余边界

隔离桌面使用现有 fixture，每次创建独立 profile/session/data 目录及随机本地端口，真实音频桥与预加载保持启用。第一次组合自动化调用超时导致 REPL 句柄丢失；核实并结束仅本次 fixture 进程后，以短步骤重跑通过，未修改用户运行的应用。

聚焦 Node 回归 64/64、文档门禁 10/10、架构门禁 27/27 通过，JavaScript 语法检查覆盖 1615 个文件；最终原生构建及 `test:audio-native` 通过。隔离桌面进程已关闭。清理仅本次 `run-zJk05Q`、`run-Y167HM` 测试目录的 PowerShell 命令被工具安全策略拒绝，目录保留于仓库 `tmp/`，没有尝试其他删除路径；不进入版本控制。

当前已实现 Windows 驱动暴露的输入/回送接入；实际麦克风听感、外接实体声卡线路与硬件回送、热拔插和 OBS/直播姬实播尚未用对应硬件验证，不能由合成 PCM 或本机枚举推定全部型号兼容。安装包未构建或替换，此计划保留 Awaiting Verification 以记录这些实机验收项。

## 失败处理与完成条件

采集初始化失败必须释放已创建对象，保留所选设备并显示可操作提示，不悄悄改用其他来源；播放器隔离任务仍通过现有守护还原。回退只撤销本计划拥有的变更，不使用批量覆盖或重置。

完成条件：四类来源有实际采集实现，默认格式和声道可用，输入模式不误触播放器恢复或自动消人声，既有音乐功能通过回归，文档与界面一致，验证范围和硬件限制如实记录。
