# 礼物导出补齐历史头像

Status: Awaiting Verification

## 目标与证据

同一位观众在北京时间同一天的历史记录中，舰长订单可能缺头像，同日普通礼物仍带有头像。安装版只读排查复现了这一数据差异。PNG 使用打开预览时的冻结快照，而现有卡片身份查询只覆盖今天。

## 实施与验收

- [x] Server 在现有 Device 礼物路由增加 `POST /api/device/gift-card-avatars`。每批最多 200 个已选公开事件 ID，DeviceBearer 决定租户。返回有证据的 `eventId` 和 `avatarUrl`。先用该事件自己的地址，地址缺失时按同一有效 UID 取同一北京时间日最新有效地址。用合成订单验证同日、重名、跨日、跨租户和未知 UID，并校验 HTTP 响应符合 OpenAPI。
- [x] 桌面在 `gift-export-runtime.js` 冻结预览前补齐缺少头像的已选记录。复用现有 Device 请求、头像 URL 校验和来源世代检查，最多等待四秒。已有地址和今日资料优先，旧服务器、离线或仍缺证据时正常导出。用导出 runtime 测试校验仅请求缺图记录及来源切换，用现有 Electron 脚本检查两条历史记录分别写入 PNG 并展示相同头像。
- [x] 更新两端契约与导出指南。运行 Server 受影响的 Device 合同及文档检查、桌面定向测试和 `npm run verify:docs`，再核对两仓差异和状态。

## 边界与失败处理

读模型只查询当前租户活跃、已终结的正价值记录，沿用 Device 鉴权与礼物读取限流。历史合并边界、原始流水、金额、等级、保留策略和 IPC 形状沿用现有契约。网络失败保留已有资料并允许保存，侦测到来源变化时沿用原重新选择流程。部署时可先更新服务器，旧客户端仍走既有协议。

## 完成条件

隔离合成数据通过 Device 查询、桌面快照和 PNG 检查，文档和契约一致。正式安装版与服务器配套上线后可以使用修复。

本地验证覆盖服务端 73 项、桌面 94 项、架构门禁 28 项以及隔离 Electron 实际 PNG。2026-11-20 使用 6.3.2 正式包内的导出模块和页面，以合成流水导出 PNG 并检查像素，历史舰长和人气票两行显示同一头像。配套服务器上线后，仍需用原账号在两台电脑重新选择同一批历史流水复核。
