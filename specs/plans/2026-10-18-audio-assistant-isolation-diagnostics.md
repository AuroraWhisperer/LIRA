## 目标与当前证据

截图中网易云原输出为 Virtual Out 1/2，隔离通道为 Analog Out 3/4。前端将通道无法静音、Windows 路由未应用、播放器未迁移三种原生错误合并成同一提示，无法据此确定硬件故障原因。本机无该声卡，不把本机检查当作对方机器验收。

- 脚本只处理自己启动的进程。测试前说明短暂切换声音的影响；默认最终输出跟随播放器原输出，处理输出音量设为零，测试完成立即停止。

## 验证记录

脚本检查入口为 `tmp/audio-assistant-diagnostic-checks/check.cjs`。初次假组件检查被继承的 PowerShell 7 模块路径阻断（Windows PowerShell 5.1 无法加载 Get-FileHash）；修正测试启动环境为双击入口的默认模块路径后 7 项通过。真实组件的只读运行使用独立新目录，未发送 configure/start/stop/recover，没有遗留测试进程。技术参考和应用内指南已同步；交互式引导未描述该设备选择与错误细节，无需改动。

用户随后在本机运行 v1，被全局恢复进程检查提前拦截；原有模拟测试错误地将这种全局拦截当作预期。本机唯一记录属于已退出的 QQ 音乐，`MutedEndpoint=null`，只剩应用输出设置延期恢复；网易云当前声音可正常播放。按用户要求备份记录后，正常启动记录对应的 QQ 音乐，既有原生守护完成还原并自行删除记录、退出。读取实际安装目录确认 `pendingRecovery=false`、Realtek 原输出；用户确认页面提示消失，且此前声音本就正常。未手工删除恢复记录或强杀进程。

v2 改为只报告现有隔离/恢复任务，将是否冲突交给既有原生播放器/端点所有权锁，避免脚本重复且扩大拦截范围。报告中的恢复记录计数明确只指诊断目录。8 项模拟检查通过；本机真实安装组件通过自动发现、读取设备和到达来源选择的路径，并在选择前主动取消，不启动真实音频处理。

最终检查采用 `npm run verify:docs`、`git diff --check`、触及差异与 `git status --short`；本轮未构建或发布安装包。

## 完成与失败处理

本轮交付条件是脚本可运行、错误不再合并、相关测试和文档同步、明确回传文本的位置。若停止后仍有恢复记录，保留脚本旁的数据目录和原生恢复进程，报告待恢复；不声称已经恢复成功。ROUTIST RS 实机失败原因与兼容性修复按下方回传证据继续定位。回滚只撤回本任务改动，不操作用户应用或删除恢复数据。

## 播放器退出后的正常收尾

用户要求关闭外部播放器后也能恢复正常使用，不应为了消除等待提示强制重新打开。隔离静音测试程序复现：保留进程句柄或音频 session 引用都不能让 Windows 的按 PID 路由接口在进程退出后继续工作（返回 0x80070057）；仅更改测试程序自己的注册表路由值也不会更新音频服务缓存。测试的 per-app 设置已通过原 API 还原，没有操作用户播放器或端点主音量。相关证据脚本位于 `tmp/audio-route-probe/`。

最小修正是由 `RouteSession` 区分安全的后台收尾与未恢复的通道/实际错误：恢复守护存活、已经开始恢复、端点静音已归还、记录有效且没有恢复错误时，允许标记为正常延期。保留全部持久撤销信息、播放器/端点互斥锁和自动恢复路径，不尝试注册表旁路、启动用户播放器或重启音频服务。

- `AudioSession` 在既有 `pendingRecovery` 之外增加 `recoveryDeferred`，只有剩余记录全部符合上述条件时为 true；停止时重新读取真实记录，避免旧 pending 状态污染后续播放。空闲重试继续运行，并检测延期状态变化。
- 处理期间按播放器 PID 与启动时间识别正常退出，先停止处理再检查通道静音，避免把恢复守护主动解除静音误报成外部干扰；音频停止回调同样区分播放器退出与实际异常。
- 前端把这种安全收尾显示为已停止处理，不自动弹出恢复警告；主动点击恢复时解释通道已恢复、播放器下次播放会自动收尾。真实错误优先；旧组件没有新增字段时保持保守兼容。
- 同步 owner 文档 `desktop/preload.md`、`desktop/main.md`、`backend/storage.md`、`frontend/app.md`、原生 README 与应用内指南；IPC 操作、设置键和路由记录格式不变。交互式引导不涉及恢复细节。
- 验证：扩展原生安装/延期恢复及空闲会话检查，覆盖安全等待、端点失败、失去守护、旧记录保留与状态完成；扩展既有前端反馈测试，覆盖停止/重试/轮询及真实错误。执行 `npm run build:audio-assistant`、`npm run test:audio-native`、受影响 Node 测试、`npm run verify:docs` 和最终差异检查。
- 完成条件：无需为了恢复提示而手动重开播放器，安全延期不被报为故障；未归还静音、损坏记录和真实恢复失败继续可见；记录未丢失、同一播放器的新接管仍等待旧恢复完成。安装版与实际播放器验证单独记录，不把源码/合成测试等同于安装版已更新。

- 移除所有输入提示，双击入口使用 `-NonInteractive`。最多自动刷新等待 10 秒，按原生音频清单的播放活动排序选择网易云；控制台显示中文进度，原始阶段、设备 ID 和错误保留在报告中。
- 清空诊断目录遗留的 `cableId` 与 `outputId`，通过既有 `configure`、`refresh` 复用原生组件的隔离通道识别。旧组件目前识别 OMEN Cam & Voice 与 VB-Audio CABLE；脚本不把普通声卡声道编号当成可隔离证据，也不新增设备白名单。

## 2026-10-19 ROUTIST 实机报告

Windows 10 Build 19045.4780 上，v5 正确枚举截图中的 Analog Out 1/2、Analog Out 3/4、Virtual Out 1/2，识别网易云原输出为 Virtual Out 1/2，并实际选择 Analog Out 3/4 执行启动。约 5 秒后返回「播放器未切入原声通道」。停止及恢复均成功，`pendingRecovery=false`，诊断目录没有恢复记录。

按 `RouteSession.RunGuard` → `AudioSession.Start` 的执行顺序，返回该错误表明通道占用检查、端点静音写入及读回、三个角色的应用路由写入及读回均已通过；失败在 `AudioDevices.WaitForIsolation` 未确认播放器全部活动会话迁移到目标端点，尚未进入处理引擎启动。该结果仅证明 Windows 报告的端点静音状态，不能验收声卡内部直通或实际听感。

报告没有播放器内部输出模式和等待期间的逐端点会话记录，不能据此断定 ASIO、驱动不兼容、硬件故障或等待时间不足。首先确认网易云自身输出为默认、非独占，完全退出后重新打开，再用现有 v5 复测。Windows 系统输出可保留原 ROUTIST 选择，无需全局重置其他应用。微软的[默认端点与流路由说明](https://learn.microsoft.com/en-us/windows/win32/coreaudio/getting-the-default-device-endpoint-for-stream-routing)指出，显式绑定设备的流不会获得与默认设备流相同的自动切换行为；这是验证方向，不是对本次播放器模式的事实认定。暂不放宽隔离条件、盲目延长等待或删除恢复机制。
