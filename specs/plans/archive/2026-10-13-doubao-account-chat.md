# 豆包账号对话接入实施计划

**Status:** Completed

用户已确认：在 LIRA 现有 AI 互动助手加入「豆包（账号登录·实验性）」；手机豆包扫码，电脑不额外安装豆包，只需要文字对话。

## 目标与验收边界

- 先在隔离 Electron 会话中验证官方二维码登录及一条真实文字回复，再完成供应商接入。
- 继续使用既有触发词、人格、观众上下文、回复队列和 B 站发送流程；连接测试不发送直播间弹幕。
- 不增加 Python 服务、浏览器安装包或运行时依赖；不接入火山引擎计费 API、图片/语音或函数工具。

## 当前行为与所有权

现有模型入口为 `src/ai/deepseek-client.js`，已承载多个 API 供应商；`config.js` / `config-store.js` 管理供应商和加密 API Key；`ai-assistant-service.js` 负责生成与队列。`src/server/ai-runtime.js` 负责装配，`api-context.js` / `routes/ai-routes.js` 为已有受保护管理 API。Electron main 与已有平台登录窗口拥有平台会话。管理页由 `public/pages/admin/toolbox/danmaku-ai.html` 与 `public/js/admin/ai-assistant-{settings,config-view}.js` 组成。

## 设计、约束与安全检查

- 新增独立豆包会话 owner，使用 Electron 自带 Chromium、严格隔离的 session、无 Node/preload 的官方网页窗口；对话只访问固定豆包 origin。权限请求和外部导航不能取得 LIRA 管理权限。
- Cookie 保留在主进程/隔离会话中，持久化使用现有 safeStorage 模式；管理页只获得可用性、登录状态及公开错误，不能读取或设置 Cookie。加密不可用时不写明文。
- 通过 main 注入本地后端，领域代码不依赖 Electron。新增登录/退出管理操作沿用现有授权边界；请求体不接受任意网址、脚本或凭据。
- 供应商标识为 `doubao`。豆包模式无需 API Key/URL/模型 ID，隐藏这些输入并说明仅文字对话；原供应商设置保留，禁止向豆包发送已保存的其他供应商密钥。
- 模型响应适配现有 `{id,text,functionCalls,finishReason,usage}`；不公开内部 SSE、账号信息或 Cookie。超时、取消、登出、退出应用均终止本 owner 的工作，旧会话回复不得进入新会话。
- 当前工作区已有大量用户修改；仅补丁修改任务所属行，不提交、分支、格式化其他文件或启动用户现有实例。
- 上游协议调查来源：<https://github.com/wangchuxiaoji-oss/doubao2api>，仅作协议参考；实际可用性由测试决定。研究文件和截图位于根 `tmp/`。

## QA 清单

- 供应商下拉选项与登录状态；扫码/重开登录窗口；登录后测试回复；退出后必须重新登录。
- 豆包模式隐藏 API 地址/密钥/模型与不支持的工具设置；切回原模式恢复现有配置。
- 取消登录/网页加载失败；生成中取消/退出；旧账号生成结果不能成为新账号回复。
- Electron 中检查本次新增区域的可见性、按钮状态、错误文案，不扩展到无关 UI。

## 失败与回滚

实测失败时先定位网络、登录或协议原因，不绕过验证码/安全拦截，不将未验证的方案标为可用。关闭本次创建的窗口与进程，取消请求/监听器；需要回退时仅逐项撤销本任务补丁，保留已有用户修改与真实账号数据。

## 完成条件

本功能可从现有 AI 互动助手选择、扫码登录并测试文字回复，聚焦与边界检查通过，受影响契约和指南一致，最终 diff 已检查；实际账号验证未通过或未完成时保留准确的未完成状态与原因。
