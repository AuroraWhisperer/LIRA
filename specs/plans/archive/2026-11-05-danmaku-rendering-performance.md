# 弹幕显示性能优化实施计划

状态：Completed（2026-11-05）

## 目标与范围

保留现有样式、文字清晰度、入场节奏、粒子数量和运动轨迹，减少密集消息下离屏卡片、沉笺重复计算与极光珠光重绘的开销。不改变设置、持久化、网络、服务器、桌面安全或公共接口，不提交或发布。

## 当前证据与所有者

隔离 1080p 浏览器源审查发现：每秒 10 条时圣诞来信保留 50 张卡片，其中 44 张完全离屏，等待列表移动结束才清理；沉笺密度 100 每张卡片 390 个气泡，每帧重复计算其出生位置；极光珠光循环改变 background-position。临时基线与测量记录在仓库 tmp/danmaku-performance-2026-11-05/，本轮修改前文件另存 tmp/danmaku-performance-optimization-2026-11-05/before/。

- 公共固定列表：public/js/overlays/danmaku-feed.js；消费者为全部固定弹幕与既有本地场景/预览。合同：docs/reference/frontend/danmaku-motion.md、docs/reference/frontend/overlays.md。
- 沉笺粒子：public/js/overlays/danmaku-sinking-feed.js；保持其等待、寿命、密度、resize 和减少动态效果合同。
- 极光珠光：public/css/overlays/danmaku/aurora.css；保持 11 秒周期、相位、宽度、颜色、裁切及持续动画开关。
- 现有覆盖：test/danmaku/danmaku-feed-motion.test.js、test/danmaku/danmaku-sinking.test.js；沿用现有 helper，不新建测试框架。

## 实施与验证

- [x] 公共列表：新增持续打断时的离屏淘汰回归，覆盖上下方向、缩放与部分可见卡片；在现有批量读取位置时判断旧卡片当前及目标是否都在退出边界外，再释放其动画和节点。保留 top 移动、同批间距和速度续接，不新增逐帧测量循环。
- [x] 沉笺：每个气泡仅在出生周期或布局变化时计算出生位置，避免隐藏粒子重复写透明度和稳定阶段重复写表面变量；保持原数量、路径和时长。复用既有生命周期覆盖，新增 resize 后粒子仍跟随卡片且不重置寿命的回归。
- [x] 极光试验已收束：平移独立渐变使软件渲染样本的主线程略降，但帧间隔变差，因此完整撤回这项 CSS 改动。最终交付不修改极光；不把该试验的收益算入成品。
- [x] 当前基线与相同合成消息对比常速、密集消息和沉笺最大密度；沉笺七个阶段（含区域缩放）卡片及全部 390 个粒子的位置、透明度逐项一致；固定列表密集实际画面及运动回归通过。
- [x] 拥有者参考文档同步；功能、参数与使用步骤不变，用户指南无需改动。相关 49 项测试分批通过，四个修改 JS 文件语法检查通过，detector 无发现。文档门禁与最终差异审查见下方完成记录。

## 验收与失败处理

可见内容不提前删除，持续密集时离屏旧卡片不积累到上限；沉笺粒子缓存不会在窗口改变或重生时沿用旧位置；珠光外观与节奏一致。性能对照证明目标开销下降且相关测试通过后完成。所有临时材料留在 tmp/，已有用户修改保持完整；若某项不满足视觉或性能条件，仅撤回本轮该项编辑，不重置文件或删除既有内容。
