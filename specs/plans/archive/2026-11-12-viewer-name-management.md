# 昵称管理实施计划

Status: Complete

用户要求：互动管理开关区增加昵称管理、分页、每 UID 一个当前昵称，以及默认开启的总开关。

## 目标与现状

观众“叫我…”由 Server `src/modules/danmaku/viewer-name-service.js` 处理，存入当前主播 `streamer.db` 的 `viewer_names(uid PRIMARY KEY, name)`。欢迎和礼物感谢共用解析；客户端尚无管理入口。保留现有十个字素簇长度规则和唯一键。

关闭总开关后不接受改名、不发送改名确认，新欢迎及感谢使用上游昵称；保存的数据保留，重新开启恢复。已提交或已冻结的欢迎/感谢文案沿用现有快照契约。管理入口在关闭时仍能查看、修改、删除已有记录。

## 所有权与兼容

- Server：现有 viewer-names storage 与 ViewerNameService 拥有设置、分页、更新、删除；DeviceBearer 选择租户，不接受请求中的主播身份。
- Client：既有 license transport → 主窗口 IPC → preload → 固定回复编辑区；不落本地昵称副本、不新增连接或轮询。
- 开关使用 streamer_settings 独立键，缺省 true；不改表结构或欢迎开关。管理只修改已有 UID，弹幕继续使用 upsert。
- 每页 20 条，按 UID 字符串升序稳定排序；服务端查询 LIMIT/OFFSET，返回总数和纠正后的页码。
- 旧服务器不支持时提示升级；账号切换丢弃旧列表、草稿与迟到响应。继续校验主窗口来源，桥接只返回公开字段。
- 范围外：重写上游昵称事实、公开 overlay 昵称、批量清空、部署与提交。保留双方仓库已有改动。
