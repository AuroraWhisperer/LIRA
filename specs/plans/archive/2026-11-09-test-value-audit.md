# 测试冗余与范围清理

Status: Completed

## Goal

审计当前客户端测试，清理仍存在的低收益用例、重复断言和过宽夹具。删除依据是独立故障检测价值及维护成本，不设用例数量或覆盖率下降目标。

## Scope And Ownership

- 当前工作区起始干净；范围为 `test/`、必要的运行登记与测试说明，不修改产品行为、服务器或用户数据。
- 测试规范 owner：`docs/reference/engineering/test.md`；发现与环境分组 owner：`scripts/run-tests.js`；业务 owner 按相关用例的真实 imports/callers 核对。
- 基线共 669 个测试文件、27 个业务目录。全局筛查测试名、断言、输入矩阵、源码读取与运行依赖，对候选读取完整场景和对应实现，不把关键词命中当作删除依据。
- 前几轮已清理静态库存及样式矩阵；本次复核残留的纯转发、整对象比较、等价输入、文案/装饰细节及跨层重复。

## Constraints And Synchronization

保留独立的安全、协议、持久化、身份隔离、并发、恢复和资源释放覆盖，以及用户设置、交互和信息完整性检查。不通过 skip、吞错或合并无关场景降低数量。不提交、建分支或发布。

临时审计索引和结果只放 `tmp/test-value-audit-20261109/`。删除场景时清理专属辅助代码；更换测试入口时同步运行登记与当前文档。产品契约和用户指南在产品行为不变时无需修改。

## Verification

- 聚焦命令：`node scripts/run-tests.js all --file=test/<domain>/<file>.test.js`，允许多个文件选择器；结果保留真实执行、失败与跳过数。
- 整文件删除以实际 owner、已有独立覆盖及测试规范为依据；保留用例改写前后运行同一文件，验证期间不编辑被测输入。
- 若删除显式登记的 browser/desktop 文件，更新 `scripts/run-tests.js` 并运行 `test/engineering/run-tests.test.js`。
- 代表性收窄检查可用隔离子进程验证普通文案/内部结构变化不再误报、实际功能损坏仍失败，不向产品源码写故障。
- 最后运行受影响集合、修改文件的语法检查、`npm run verify:docs`、`git diff --check`，审查 touched diff 与 `git status --short`。不为测试删减自动运行原生安装器或无关完整发布验收。

## Failure Handling And Done When

失败先区分原有缺陷、环境和本任务修改；不为全绿删有效断言。只撤销任务自己的改动，不使用破坏性回滚。完成筛查、确认的低价值项处理、相关验证、文档同步和最终差异审查后关闭计划；报告真实审计范围和限制，不宣称穷尽所有潜在重复。
