# 歌库、播放恢复和直播指令审计整改

**Status:** Completed

**目标**　用独立 Codex 对话及领域回归确认六项现象，修复可复现的用户数据丢失和功能中断。

## 范围与约束

在当前工作树复核桌面生产路径，以本地配套 Server 的歌曲字段契约校验往返。测试使用合成弹幕、隔离数据库、可控时钟和模型传输。保留本地歌曲原稿、既有同步协议、播放写入代次及同一弹幕跨来源去重。每个领域在其现有模块中修改，回滚单位为下表中的各组改动。

## 验证与交付

先保留旧行为复现，再运行相同场景及现有歌库、播放、点歌、导入、模型测试。核对技术参考与用户指南，运行 npm run verify:docs、git diff --check 及最终状态检查。以六项各自验收通过、独立复核结果已收取和最终差异已审阅为完成条件。

## 独立复核结果

同一独立 Codex 对话使用修复前工作树和修改后工作树运行合成实验。歌库采用桌面与服务端两套隔离 SQLite，播放器经实际队列存储读回。模型端点使用本地模拟传输。

- 普通歌名的 1001 码元歌切和前 200 码元相同的两个歌名在上传前得到对应字段错误，服务端版本保持原值。修正后三首歌通过一次上传、一次下载完整往返。旧版已确认的 201 码元歌名、1001 码元歌切仍在本机时，设备 GET 的实际响应经新版恢复保留原文并重新进入该账号待传。
- 启动读取返回 503 后直接关闭，退出确认一次，HTTP、IPC 和 Beacon 各写入 0 次。SQLite 中的原曲、待播项和 90 秒进度保留。回归另覆盖仅调音量、调进度和实际编辑队列。
- 播放十分钟、每 250 毫秒一次进度事件，产生 60 次常规保存。第 301 秒加入的歌曲在第 310 秒首次从 SQLite 读回，第 600 秒仍在队列中。
- 畸形 CSV 的预览与应用请求均为 0，原有三首歌全部保留。合法的多行引号字段完成预览与替换。
- UID 均为 0 的 Alpha 和 alpha 同秒发送同文，两个名字均派发。重放原始包、再从历史返回同条指令均被去重。
- DeepSeek 官方 Chat 工具续轮保留上一轮的 reasoning_content，工具调用与返回结果使用同一个 ID。两次离线请求完成一次工具调用并得到最终回复。

36 个相关测试文件共 484 项通过。架构检查 30 项通过，JavaScript 语法检查通过。歌库往返在锁定服务端版本和当前服务端工作树分别通过 5 项，锁定契约的 10 个夹具通过校验。
