# 客户端测试边界与低价值覆盖清理

Status: Completed

## Goal

审查客户端现有回归、用例与断言，删除低价值检查，收窄过宽夹具和跨层重复。普通设计或内部实现调整不应牵动无关测试；保留能够发现实际功能、数据、安全和资源故障的覆盖，不以用例数量或全绿代替质量判断。

## Scope And Ownership

- 范围为 `test/` 中客户端各领域、直接使用的 helper、`scripts/run-tests.js` 登记，以及测试说明；不修改产品行为或远程 Server。
- 规则 owner 为 `docs/reference/engineering/test.md`；测试路由、分组和文件选择由 `scripts/run-tests.js` 负责。
- 先审查源码/外观断言、共享规则矩阵和昂贵 UI 重复，再检查其他领域的默认快照、mock 转发、措辞和等价输入。
- 全局清单仅作定位。每项删除仍核对场景及实际 owner，不机械删除涉及尺寸、样式、错误或 mock 的测试。
- 原有 `2026-10-31-test-correctness-remediation.md` 涉及双端正确性，仍保留其独立范围和状态。

## Constraints

保留开始时所有未提交功能与测试修改，不提交、建分支、发布或启动用户应用。不降低安全、身份隔离、持久化、并发、错误恢复、资源释放、可访问性和明确导出尺寸的有效覆盖。临时清单、基线副本及结果仅存 `tmp/test-boundary-audit-20261108/`；不使用真实用户数据。

- [x] 清点执行器和各领域测试；定位外观/源码检查、跨层重复、范围过宽和无业务意义的用例。
- [x] 清理 UI 与样式矩阵，保留用户设置应用、内容完整性、交互与生命周期覆盖；运行受影响文件。

## Verification

- 改写场景前运行对应文件建立基线；删除纯低价值场景以代码及现有承接覆盖为依据。
- 聚焦运行 `node scripts/run-tests.js all --file <受影响文件>`，不因一个小改动运行整个业务域。
- 删除或移动 browser/desktop 文件时同步执行器，运行 `test/engineering/run-tests.test.js`。
- 跨领域最终验证采用受影响集合及有证据需要的环境组；记录原有失败，不靠放宽断言获得通过。测试运行期间冻结被测文件。
- Markdown 变更运行 `npm run verify:docs`；最终运行相关语法检查、`git diff --check`，审查任务差异和 `git status --short`。
- 若收窄有效行为覆盖，使用隔离输入证明代表性真实故障仍可被拒绝；不新增测试基础设施或截图库存。

## Failure Handling And Done When

失败先归因到工作区既有功能改动、环境、真实产品缺陷或本任务测试修改，只撤销本任务负责的改动。已发现问题完成处理或明确说明限制；完成已计划审查范围，受影响检查通过，文档与登记一致，未误删有效独立覆盖。用户指南与产品契约在行为未变时不需要修改。
