# 本房间粉丝牌欢迎与规则整理

**Status:** Completed

## 目标与决策

只欢迎佩戴本直播间粉丝牌的观众，并明确普通欢迎、文案替换、二次问候、PK 欢迎及黑白名单的关系。用户已确认本房间范围。

- 新增可选 V2 布尔字段 `welcomeOwnMedalOnly`，默认 false，省略保留；保存在已有租户 welcomeOptions。V1 保留而不返回，旧 V2 缺少字段时只禁用新增控件。
- 资格顺序：既有发送/直播准入 → 黑名单否决 → PK 独立规则或普通欢迎总开关 → 白名单豁免本房间粉丝牌及首次荣耀门槛 → 其他观众同时满足开启的粉丝牌筛选和荣耀门槛。
- 粉丝牌证据沿用进场解析器的 `medalRoomId`，与监控的真实 roomId 精确比较。未佩戴、其他房间或缺失证据不通过；不从大航海、荣耀、缓存资料猜测，不额外要求点亮。ENTRY_EFFECT 没有该证据时拒绝，但不占用冷却，后续合格事件可以欢迎。
- 文案继续只选一条：个人 → 多天未到 → 高荣耀 → 时段/普通。二次问候只在首次成功且满足自身条件后发送；白名单不豁免其门槛。PK 欢迎替代普通欢迎，不叠加二次问候；本房间粉丝牌筛选不阻止对面观众，黑名单仍生效。
- 沿用同一流程、去重、冷却和配置变更取消。不开新发送器、请求、连接或持久化结构；不改既有每次有效进场记录来访的规则。
- 页签整理为「欢迎规则」「欢迎词库」「欢迎对象」；对象页集中粉丝牌筛选和黑白名单。荣耀仍为首次欢迎阶段参数；补清楚二者共同约束。重点关注改名「高荣耀文案」，明确只换文案。

契约同步 Server viewer-welcome、Device OpenAPI/fixture、PK 引用、REQ-BILI-008 和 AC-BILI-007；Live desktop/main、frontend/pages 和应用内指南/相应截图。交互引导无详细欢迎步骤时不改。

两仓有大量既有修改；本任务基线在各自 tmp/welcome-medal-before。没有提交、部署、打包或真实账号操作。
