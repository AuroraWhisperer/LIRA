## Verification And Delivery

统一验证为 npm run verify，包含固定契约、语法和全量测试（含文档、架构及配置好的原生安装器场景）。不另行重复 check、verify:quick、npm test 或预打包。失败时用 npm test -- --file=实际失败文件 合并定向检查；并发问题需受控复现，不能仅凭原样重试判定修复。

准备通过后使用 UPDATE.md 摘要提交 v6.0.2，再 git push，最后 npm run release:win。发布脚本负责构建、生产依赖和完整安装包验证、创建/推送标签、GitHub Release 与附件确认；正常退出且输出 All expected assets uploaded 为发布完成证据。实际交付结果保留在 tmp/release-6.0.2/publish.log 与最终回复，避免发布后为重复记录再制造工作区修改。

## Failure Handling

验证失败时不提交或发布；构建失败时不手工创建标签或上传旧产物。保留日志和已有改动，定向修正，不使用 reset、整文件 checkout 或覆盖远端标签。若标签已指向其他提交，停止冲突发布并说明事实。
