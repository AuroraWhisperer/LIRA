# 按直播间人数切换大航海舰徽

Status: Implemented

## 目标与边界

当前配置直播间的大航海人数达到 1000 时，客户端和直播画面统一使用 B 站千舰舰长／提督／总督图标；不足 1000 或人数未知使用普通图标。千舰原图保存为透明 WebP。所有原有普通身份舰徽和上舰礼物图案通过公用接口选择，不按观众粉丝牌等级、历史消费或礼物数量推算人数。头像框、用户自选图片与其他主题装饰不属于本次切换。

## 现状与所有权

- 桌面 `src/server/bilibili-runtime.js` 拥有当前配置房间，已有状态广播；尚未提供大航海人数。房间查询在 `src/bilibili/danmaku/api-client.js`。
- Server 的 `src/modules/bilibili/room-monitor.js` 已周期查询 `getInfoByRoom`，可直接读取 `guard_info.count`；人数按租户 monitor 隔离。
- 普通舰徽散见身份渲染、点歌队列、粉丝档案、最近礼物、加班礼物选择、礼物许愿与文字组件，以及月渡／雾语／航海主题。
- 共用图片选择与已渲染图片更新由前端共享模块负责；各页面继续通过原有快照和事件入口接入，不为每张图片创建请求或监听器。

## 兼容与实现

1. 添加公用房间人数读取／状态生命周期模块；配置房间变化立即清空旧人数，取消旧请求，拒绝迟到结果；失败回退普通款，停止时释放资源。保持原有身份、鉴权、租户、账本和持久数据契约。
2. 在现有桌面状态和 Server overlay 快照／增量中投影最小房间人数信息；沿用现有连接，Server 复用原房间轮询。新字段为兼容增量，旧来源缺字段按未知处理。
3. 将已核对的千舰 PNG 转为无损 WebP，记录来源。共享舰徽接口覆盖普通图片使用点，并在人数跨越门槛和切换房间后更新已渲染内容；用户主动选取的非舰徽图片不替换。
4. 同步 owning reference、Server protocol/OpenAPI、受影响使用说明与测试；不新增框架、依赖、进程，不提交或部署。
