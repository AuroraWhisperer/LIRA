# v5.0.12 Release Validation Plan

**Status:** Completed — 发布准备与统一验证完成；提交及远端发布结果在最终回复中报告。

## Goal / Current Behavior

按 RELEASE_GUIDE.md 发布客户端 5.0.12，标签为 v5.0.12。用户已授权指南中的提交、推送、标签和发布。初始 main 为 0db24576（v5.0.11），与远端 main 一致；暂存区为空，工作区包含浏览器组件预览、统一画布、组件库与来源目录的待发布改动。远端 v5.0.12 标签不存在，最新正式 Release 为 v5.0.11。

## Ownership / Proposed Changes

同步 package.json 与 package-lock.json 的版本；UPDATE.md 记录相对 v5.0.11 的实际新增、优化和修复，提交正文与 Release 复用该摘要。scripts/publish-release.js 负责标签、构建、安装器验证、上传和附件完整性检查。本任务只新增发布元数据、验证记录及必要的发布阻塞修复。

## Compatibility Constraints / Non-goals

保留现有待发布改动及接口、安全和数据边界；不覆盖既有远端标签，不部署服务端，不操作真实用户数据或运行中的用户应用。测试使用隔离 fixture；LIRA_SERVER_ROOT 指向现有 tmp/release-5.0.9/server-contract，提交必须符合 server-contract.lock.json。临时日志与源文件摘要保存在 tmp/release-5.0.12/，不进入提交。

## Release Sequence

以 v5.0.12 为标题、本版更新摘要为正文提交并推送 main。运行 npm run release:win，由脚本创建并推送 v5.0.12、构建 Windows x64 安装器并发布。脚本输出 All expected assets uploaded 且正常退出即完成附件检查；最终回复提供 Release 链接和实际验证结果。Git HTTPS 连接已验证可用，必要时仅在当前命令进程中转换 origin 的 SSH URL，不修改仓库远端配置。

## Failure Handling / Done When

验证失败先保留日志并定位具体原因，仅修复阻塞本次发布的问题；不跳过失败检查，不重置用户工作。若标签已推送而源码必须修改，按指南报告新版本号需求，不移动远端标签。准备完成要求版本一致、验证通过及 diff 审阅完成；发布完成以脚本构建、安装器与附件校验的实际成功结果为准，远端结果在最终回复报告。
