# 客户端字体主题实施计划

**Status:** Completed

用户已明确，客户端一次只选一款同时覆盖中英数的字体。

## 当前目标与实施

从已核验的霞鹜文楷、小赖字体、悠哉字体中任选其一，在客户端正文、标题和控件上以同一字族绘制中文、英文与数字。「系统默认」恢复原排版。既有配色、素材字体和共享资源交付各自沿用现有入口。

- [x] `client-appearance` 的串行写入队列保存单个 `fontId`。读取旧记录时沿用有效的 `fonts.han`，仅在下次成功保存时写入新格式。已验证并发改色、重启、重置和 IPC 校验。
- [x] `page-assets` 在管理页与工具页注入 `data-client-font`。隔离 Electron 设置页实测一个选择器及混排预览，920px 宽面板并排、439px 宽面板上下排列。冷启动使用系统字体，资源就绪后自动恢复。模拟写入失败保留原选择，重试后同会话工具同步。重置字体保留配色。
- [x] ASAR 测试在同一文本节点里绘制 6,763 个 GB 2312 汉字、可打印 ASCII、混排标点和内置地名。对三款字体的常规和粗体逐一检查，Chromium 每次只报告一个属于所选字族的字体文件。已同步使用指南和前后端参考。

定向用例覆盖桌面外观、HTML 交付、管理页配色、字体加载及 ASAR 冷暖缓存，共 25 项通过。混排字形核验随 `node --experimental-vm-modules --test test/desktop/bundled-fonts-electron.test.js` 运行。

## 前一轮双选择方案的历史记录

### 目标与边界

在「百宝箱 → 设置 → 外观主题」独立保存配色与界面字体。中文选择须覆盖至少 99% 的 GB 2312 汉字、基本标点和界面样本文字。英文与数字可以跟随中文或单独搭配。沿用本机现有软件字体库、下载校验、缓存和授权边界，直播输出与导出内容保留自身排版。

### 现状与归属

`src/electron/client-appearance.js` 只存储配色。`src/server/page-assets.js` 将它交付到管理页和独立工具。`public/js/shared/font-library.js` 已支持按共享 ID 筛选已就绪的字体。实际文件核对发现霞鹜文楷、小赖、悠哉覆盖 CJK 基本区及内置地名。Nunito、Noto Sans、Poppins、Quicksand、Montserrat、Cinzel 有完整可打印 ASCII 且不占用汉字。

### 实施与验收

- [x] 本机外观记录增加可选字体对。已验证旧记录、无效 ID、写入失败、并行改色与改字以及重启回读。
- [x] 管理页和工具页随 HTML 收到已保存的字体 ID。隔离桌面设置页验证了两个选择、资源缺失期间恢复默认、重启时显示未就绪选项、资源就绪后更新选项及应用组合。已打开的同会话工具同步成功。
- [x] 在打包环境中实测三款中文与六款西文的配对及跟随模式，共 21 种。覆盖 6,763 个 GB 2312 汉字、界面里的繁体和扩展区地名、常用标点、可打印 ASCII、重音字母和货币格式。另在桌面设置页用常规与粗体抽查了 50 组内置词句、地名和英文数字。文楷与 Nunito 均由选定字族绘制。已同步使用指南、外观记录和桥接参考。

组合覆盖核验由 `test/desktop/bundled-fonts-electron.test.js` 随打包字体与离线缓存测试运行。字体、配色、IPC 与页面授权共 33 项定向测试通过。前端模块测试使用 `node --experimental-vm-modules --test`。验收命令还包括 `npm run check`、`npm run verify:docs`、`npm run verify:architecture` 和 `git diff --check`。保存失败时保留已提交的组合。恢复原外观时选择系统默认与跟随中文。
