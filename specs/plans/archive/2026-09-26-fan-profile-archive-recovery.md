# 粉丝档案归档与恢复：更改指南

状态：Completed（2026-09-26 完成前端交互、定向验证与隔离 Electron 验收）。
日期：2026-09-26。

> 面向实施者：按下列里程碑逐项完成并记录验证结果。本指南不授权提交、发布、操作真实用户档案或启动子代理。以仓库 `AGENTS.md`、`PLANS.md` 及目录规则为准。

## 1. 目标与决定

保留现有可恢复归档能力，解决“收起后不知道去哪里找、找到后不知道如何恢复”的问题。用户不阅读使用文档，也应能够完成“归档 → 找到 → 恢复”。使用文档与 FAQ 只解释用途和区别，不承担弥补入口缺失的职责。

采用现有前端状态、事件委托和保存操作完成改动，不增加后端接口或新的数据模型。技术栈沿用 Electron 桌面、原生 HTML/CSS 和前端 ESM。

### 不采用的方案

- **不删除整套功能。** 归档满足“保留历史、退出日常管理”的用途；已有归档数据也必须继续可找回。
- **不只补文档。** 用户应在档案页直接看见恢复路径，不必记住设置里的位置。
- **不重做档案模块。** 只修复本次操作路径，不重排资料、手记、音乐、大航海等内容。

## 3. 必须保留的边界

- 保留 `archived` 字段、档案 ID、revision、记录关联、备份格式与现有持久化语义；不做数据迁移。
- 保留 `archive`、`archived`、`back-profiles` 等现有内部 action；中文文案变化不要求内部字段改名。
- 不改变 HTTP/WebSocket/IPC 契约、认证归属、Electron 安全边界及数据隔离。
- 不改变永久删除、删除抑制名单、自动建档、名单同步、备份或恢复点逻辑。
- 不将手记的“收起”、音乐记录的“收起”或点歌记录归档一并替换；它们不是本次整份档案的归档操作。
- 不增加框架、依赖、独立页面、全局状态层、额外统计请求或新的通用组件。
- 不增加批量归档、自动归档、归档原因、保留期限、数量徽标或撤销系统。
- 保留现有主题、设计令牌、事件委托与键盘可访问性；复用按钮和反馈样式。

## 4. 目标交互

### 4.1 档案范围入口

在“档案”页现有搜索/筛选区域加入一个紧凑的**档案范围**按钮组，始终显示两个互斥选项：

```text
档案范围： [当前档案] [已归档]
搜索昵称、备注名或 UID
筛选：     [全部] [在舰] [曾上舰] [特别关注] [待补资料] [待核实]
```

这是信息层级示意，不要求固定增加三行或照搬间距。沿用现有布局，在实际桌面窗口里安排位置；不得挤掉搜索框或让筛选区域横向溢出。

- “当前档案”表示 `state.archived === false`；“已归档”表示 `true`。
- 使用原生 `button` 与 `aria-pressed` 表达当前范围，给按钮组可访问名称“档案范围”。不要复用页面 tab 的语义，也不要把归档范围塞入 `state.filters`。
- “全部”只表示**当前范围内不过滤分类**，不是混合显示当前与归档档案。搜索也只作用于当前范围。
- 实际切换范围时：取消尚未触发的搜索防抖任务，清空搜索、分类筛选和旧范围列表，更新选中态，清除详情选中项与展开状态，再按新范围加载一次列表。
- 新列表返回前显示加载提示，不保留可点击的旧范围条目；加载失败显示既有错误反馈，保留目标范围并通过现有重新加载重试。加载中或失败不显示为“暂无档案”，也不回显旧范围数据。
- 重复点击已经选中的范围，不清空用户当前条件、不重复加载。
- 在同一范围内搜索、勾选筛选、清除筛选时，不改变归档范围。
- 普通页签切换（切到“提醒/设置”再点回“档案”）、自动读取、手动重新加载，沿用现有上下文保留约定；不要借机重置搜索、筛选或范围。
- 从提醒点击“打开档案”属于定向跳转：按返回档案的 `archived` 值对齐范围；跨范围时复用上述清理和加载流程，再显示目标详情，不得在“已归档”范围展示未归档详情。同范围跳转保留原有条件，不额外重置。
- “新建档案”只在“当前档案”范围显示；“已归档”范围隐藏该按钮。新建仍按现有规则创建未归档档案，不新增“直接创建归档档案”的行为。
- 账号/归属变化继续走现有上下文失效处理，不因新增按钮保留失效数据。

### 4.2 当前档案：归档

- “更多”中的“收起档案”改为**“归档档案”**，仍是次要操作；“永久删除”保持原有确认流程。
- 在归档操作附近显示简短说明：**“保留资料与记录，归档期间不显示提醒。”** 不只依赖悬停提示。
- 复用既有 `save`，只切换 `archived`；不得以删除/重建档案模拟归档。
- 等保存成功后再把档案移出当前列表，并清除不属于当前范围的详情；不自动选中另一位粉丝。
- 成功反馈：**“已归档，资料仍保留。可在‘已归档’中恢复。”**
- 保存失败时保留可见档案与详情，显示既有错误反馈，不提前显示成功。
- 可恢复操作不新增确认弹窗；本次不增加“撤销”倒计时或额外恢复机制。

### 4.3 已归档：找回与恢复

- 进入“已归档”后，保留清晰的范围选中态，并显示：**“归档档案的资料与记录仍保留，归档期间不显示提醒。选中档案后可恢复到主列表。”**
- 选中归档档案时，在详情操作区直接显示**“恢复到主列表”**，不要再藏进“更多”。
- 同一份归档详情只出现一次恢复操作；“更多”不重复提供同一按钮。
- 复用既有 `archive` action 和 `save`，将 `archived` 改为 `false`，保留档案 ID 和所有记录。
- 保存成功后留在“已归档”范围，从该列表移除已恢复的档案并清空对应详情。
- 成功反馈：**“已恢复到主列表，可在‘当前档案’中查看。”** 用户点击“当前档案”即可看到恢复项。
- 不自动切换范围、不自动新建档案、不自动恢复全部归档档案。
- 列表中最后一份归档恢复后，显示归档空状态，而不是残留旧详情。

### 4.4 空状态与入口去重

| 情况 | 文案与行为 |
| --- | --- |
| 已归档范围，无搜索/筛选且无数据 | “暂无已归档档案。”；辅助说明“归档后的档案会保留在这里，可随时恢复到主列表。” |
| 已归档范围，有搜索/筛选且无匹配 | “没有找到符合条件的归档档案。”；复用“清除筛选”操作，并保持已归档范围 |
| 当前档案范围为空或无匹配 | 保持现有对应逻辑，不误用归档文案 |
| 未选中详情 | 沿用“选择一份档案查看详情”，不保留已移出当前范围的详情 |

- 删除设置里整块“已收起的档案 / 查看已收起”，只迁移入口，不删除底层能力。
- 原 `fanArchivedNotice` 可继续承担说明职责；移除其中与常驻范围切换按钮重复的“返回档案列表”按钮。
- 保留必要的状态说明；不在工具栏、详情、设置三个位置复制同一大段解释。

### 5.1 给实施者的具体落点

- **入口标记：** 当前范围按钮沿用 `data-fan-action="back-profiles"`，归档范围按钮沿用 `data-fan-action="archived"`。选中态在现有 `showPage()` 中同步，同时仅在 `state.page === 'profiles' && !state.archived` 时显示新建按钮；只保留现有事件委托，不额外绑定一套 click 监听器。
- **切换分支：** 在 `action()` 的 `archived/back-profiles` 分支里先判断目标范围是否真的变化。真实切换时先 `clearTimeout(searchTimer)`，清理条件、还原分类按钮的 `aria-pressed`、递增现有 `selection` 并清除详情和旧 `state.profiles`，显示加载提示，再加载一次。沿用现有 `sequence` 防止旧列表响应回写；只有当前请求成功取得列表后才按结果渲染空状态，失败走既有错误反馈。不要让旧详情请求的结果重新覆盖空详情，不增加新的状态管理层。
- **提醒入口：** 在 `open-reminder → select()` 路径中落实定向跳转的范围对齐；返回详情仍须通过现有选择/上下文有效性检查。跨范围清理和一次列表加载完成后再展示目标详情，避免刚打开就被清空，或异步完成后覆盖用户后续选择；普通页签点击不走这条重置路径。
- **空状态参数：** 在现有 `renderPeople(profiles, selected, filtered)` 后追加可选参数 `archived = false`。前三个参数语义不变，已有调用与测试继续有效；`renderList()` 的 `filtered` 只由搜索和 `state.filters.length` 决定，第四个参数传 `state.archived`。不通过检查中文文案来判断范围。
- **操作渲染：** 在 `renderDetail(profile, tab)` 内根据 `profile.archived` 决定“归档档案”还是直接显示“恢复到主列表”；复用现有 HTML 转义工具，用户昵称不插入未转义 HTML。
- **保存分支：** 将需要移出列表和清理详情的 `archive` 分支与 `favorite` 分开处理。现有 `action()` 末尾还有 `load()` 与 `renderSelected()`；若分支已完成自己的加载/清理，应及时返回，避免重复加载或重新绘制旧详情。
- **详情清理：** `renderSelected()` 在 `state.profile` 为空时不会自动替换详情 HTML。清空选中对象时，要像既有切换分支一样同时写入未选中提示、重置展开状态并刷新列表选中态。
- **帮助内容：** FAQ 沿用 `usage-guide-faq.html` 中的 `<details class="usage-guide-faq">`；搜索已有模块从标题和正文取文本，不新增硬编码搜索路由或关键词服务。
- **截图一致性：** 使用说明当前引用 `public/img/usage-guide/E/toolbox-fan-profiles.webp`，对应文档资产为 `docs/images/usage-guide/E/toolbox-fan-profiles.webp`。若正文配图展示的区域因本次入口迁移而失真，只更新这张相关配图并保持两处既有资产约定，使用合成档案，不批量重拍无关截图。

## 7. 使用说明与 FAQ 定稿

**使用说明：**

> 暂时不需要在日常列表中维护的档案，可以在详情的“更多”中选择“归档档案”。归档不会删除资料与记录，但归档期间不显示该档案的提醒。需要找回时，在档案页切换到“已归档”，搜索并选中档案，点击“恢复到主列表”，再切换到“当前档案”查看。归档与永久删除不同，不需要通过备份恢复。

**FAQ 标题：收起后找不到了，如何恢复档案？**

> 旧界面中的“收起档案”就是归档。打开“档案”，切换到“已归档”，选中对应档案，点击“恢复到主列表”。如果列表没有匹配结果，先清空搜索和筛选。恢复后可在“当前档案”中找到。此操作适用于归档档案，不适用于永久删除的档案。
