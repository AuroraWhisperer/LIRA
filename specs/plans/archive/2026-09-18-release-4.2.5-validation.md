# v4.2.5 发布验证修复

状态：修复与验证完成。用户要求修复发布验证问题，然后按 RELEASE_GUIDE.md 发布 v4.2.5；发布操作在修复提交后按指南执行。

## Goal / Current Behavior

全套测试 2428 项中，Windows 原生旧实例清理测试因 TCP 查询超过 5 秒失败，独立重跑可复现。实测 Get-NetTCPConnection 查询约 4.8 秒，加上进程查询超时；直接查询同一 MSFT_NetTCPConnection CIM 类约 1.5 秒。

## Ownership / Compatibility

src/server/local-process-owner.js 拥有原生端点归属查询；local-instance.js 与 lifecycle.js 消费其结果。契约归属 docs/architecture/backend/server-core.md。保持 IPv4 回环地址、精确本地/远端端口、连接状态、用户 SID、进程入口及创建时间核验；查询失败仍拒绝使用该证据，5 秒超时不变。保留全部既有工作区改动。

## Proposed Changes / Non-goals

仅将 TCP cmdlet 改为在同一 CIM 类上执行明确筛选，避免 cmdlet 加载开销；Win32_Process 与 GetOwnerSid 流程不变。更新真实 Windows 与 SID 测试，覆盖监听、已建立连接和不匹配端点。不同进程、用户和 PID 重用继续由既有测试验证。不修改清理策略、鉴权、数据格式或依赖。

## Milestones / Verification

1. 修复查询并运行 node --test test/local-instance-windows.test.js test/local-instance-security.test.js，真实端点匹配和拒绝行为均通过。
2. 使用既有锁定服务端检出作为 LIRA_SERVER_ROOT，运行 npm run verify:contracts、npm run verify:quick 和 npm test；修复实际出现的发布阻塞。
3. 检查最终 diff、git diff --check 和 git status --short；修复完成后按发布指南提交、推送、执行 npm run release:win，并核对三个附件。

## Failure Handling / Done When

失败时保留现场，仅修正本次范围内的增量；不跳过失败断言、不改变真实用户数据、不破坏性回滚。修复计划在全部验证通过、变更与更新说明一致后完成；发布是否成功以脚本及 GitHub 附件核验结果为准。
