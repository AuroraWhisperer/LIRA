# 粉丝曾用名补充与默认展示实施计划

Status: Completed。

## 目标与边界

实现已确认的单人补充、设置内批量补充、新建时获取三个入口。历史名字统一去重保存，以胶囊折叠、限高展示，不分来源和日期。折叠默认位置取最近一次可靠进房昵称，可手动替换或恢复自动；外部返回顺序不决定默认名字。不改账号实际昵称，不引入服务、依赖、自动后台补充或部署操作。

## 当前行为与归属

- `src/fans/validation.js`、`profile-service.js`、`profile-facts.js`：历史名字截为三项，昵称观察与手写记录保存于既有账号私有 JSON；保存使用 revision 和事务。
- `src/electron/fan-profile-controller.js`：主进程校验授权上下文，持有请求与取消；新增 UID 查询和当前档案补充，继续使用既有 IPC 通道。
- `public/js/admin/fans/` 与对应页面/CSS：资料、编辑、新建、设置入口；批量由当前页面串行发起，停止后不发下一人，已完成结果保留。
- `D:/Work/lira-server/src/storage/fan-fact-store.js`：最新身份事实会压缩进房与弹幕，需保留可选最近进房快照；客户端兼容旧服务器的进房 source。
- 现行合同：`specs/fan-profiles.md`、desktop preload、storage、frontend pages；用户说明：toolbox-work 指南。服务器事实合同按其文档入口核对。

## 决定、兼容与失败处理

1. 复用 `nameHistory` 格式，移除三项裁剪。新增可选 `lastEntry: {name,observedAt}`、`preferredFormerName`；旧数据缺字段时显示暂无，不猜测进房名。现有 v1/v2 备份可读，无 SQL schema 改动。
2. Aicu 请求仅由主进程发出，固定 HTTPS 地址，仅传 UID、不传 B 站凭证，设超时，不自动重试。校验 UID 与返回名字；同一上下文/UID 的在途请求合并。
3. 补充在事务内读取当前档案、核对身份、去重合入；不覆盖现有名字或默认选择。手动移除的名字不因补充重新出现。切换账号、授权失效和退出取消请求，迟到结果不提交。
4. 批量只处理当前账号未归档且有 UID 的档案，跳过黑名单，逐人请求并留间隔；显示进度、停止和结果，失败保留已有数据。
5. 新建查询结果仅写入当前表单，UID 改变后忽略迟到结果；创建时才保存。
6. 最近进房快照独立按时间前进，弹幕、名单和 API 查询不能覆盖；手动选择优先，清空选择恢复自动。备份校验这些可选字段。
