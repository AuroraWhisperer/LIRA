# v5.0.8 Release Validation Implementation Plan

## Goal / Current Behavior
按照 RELEASE_GUIDE.md 发布客户端 v5.0.8。开始时 main 与远端均为 v5.0.7，工作区已有桌面样式、代码精简、模块命名与测试目录迁移改动；用户已授权按指南提交、推送、打 tag 和发布。

## Ownership / Proposed Changes
package.json、package-lock.json 管理版本，UPDATE.md 提供提交和 Release 说明，scripts/publish-release.js 负责构建与上传。本任务更新发布元数据，复用既有验证与发布入口；不扩展发布脚本或产品功能。

## Constraints / Non-goals
保留已有用户工作，不修改服务器工作区，不访问真实账号或启动用户应用，不提交日志、运行数据或秘密。保持接口、持久化格式和安全边界。版本为 5.0.8，按现有脚本使用 tag v5.0.8，不移动已有标签。

## Milestones / Verification
- [x] 对照 v5.0.7 梳理变更，检查远端 main/tag 与发布入口，更新版本和说明。
- [x] 配置锁定的服务器 fixture 与 NSIS 工具，运行 npm run verify（包含指南要求的 npm test）；首次全量失败项单独复测后重新完整运行 npm test，全部通过。
- [x] 审阅发布元数据及提交范围，运行 git diff --check，检查 git status --short；记录验证结果并归档本准备记录。

## Release Sequence
创建标题 v5.0.8、正文含更新摘要的提交。检查提交无 Claude Co-Authored-By，git push；然后 npm run release:win。脚本校验干净工作区、tag 对应提交、最终 NSIS 内容、远端产物大小和 SHA-256。最后 gh release view v5.0.8 核对 exe、exe.blockmap、latest.yml、说明与正式发布状态，并核对 main/tag 和工作区。

## Failure Handling / Done When
验证失败时暂停依赖的发布步骤，定位并处理实际阻塞，不弱化测试、不强推、不破坏性重置。保留已有修改和诊断证据。准备完成需验证通过、元数据一致、差异审核完成；最终发布完成以远端 main/tag 正确、三个产物完整、说明正确且工作区干净为准，结果在任务回复中报告。
