# 死代码审计复核与修复

Status: Completed

## 目标与边界

对照 2026-11-27 工作区逐条复核外部审计。修复可复现的故障，移除已证实无消费者且满足退出条件的实现。判断依据包括直接与动态调用、生产接线、双仓契约、文档化入口及升级路径。保留用户未提交工作、现有数据库和设置、发布资产及其兼容地址。

## 实施与验证

1. 两个独立审阅者分组核实报告，将有争议的结论交给对方用具体调用链或反例复查。对公开接口和历史数据，需要拥有方的退役依据。
2. 按领域在拥有模块修复，使用已有的业务测试验证。将退出条件、测试路径和当前技术文档一起更新。需要外部用户、账号或发布信息才能确定的建议留在复核汇总中。
3. 固定最终改动集后运行受影响套件、`npm run check`、`npm run verify:docs`、`npm run verify:architecture` 和 `git diff --check`。涉及跨域变更时运行仓库测试。两个审阅者复查最终差异，发现问题后修复并复验。

## 回退与完成条件

相对任务开始时的工作区逐文件核对差异。失败时仅撤回或修正本次负责的改动。完成条件为已确认问题均有处理结果、实际验证可复核、双方认可的报告错误与仍需外部证据的事项均有记录。

## 复核结果

- `IdentityCache` 直接调用方已迁移，旧兼容投影与转发测试退出。生产门面覆盖数据过期、房间切换和在线观众变动。
- 清除了音频回调中无人读取的计时、播放器缺失控件的接线、粉丝旧点歌表单和 AI 黑名单的闲置写方法。已有黑名单继续限制回复。游戏来源只请求可选的 `games` 字段。
- 窗光脚本先校验随原图提供的生成记录。隔离目录中的合成图可生成 8 张 1920×1080 图层，缺少生成记录或请求 ID 时保全既有素材。
