# v4.2.6 Release Validation Implementation Plan

**Goal:** 按 RELEASE_GUIDE.md 完成 4.2.6 的发布准备，修复验证阻塞，并以 v4.2.6 发布 Windows 安装包。

**Architecture:** 沿用现有单仓版本、更新日志与 scripts/publish-release.js 流程。现有工作区改动作为本次发布内容；只有实际阻塞验证或发布的问题才增加修复。

**Tech Stack:** Node.js 24、Electron 43、npm、Git、GitHub CLI、electron-builder。

## Global Constraints / Compatibility

- 用户明确要求按发布指南执行并指定 4.2.6，包含指南中的提交、推送、打 tag 和发布。
- 保留现有用户改动；不部署 LIRA Server，不操作真实用户数据，不修改既有公共契约或安全边界。
- tag 使用项目约定 v4.2.6；package.json、package-lock.json 与 UPDATE.md 版本一致。
- 日志与构建产物保留在系统临时目录或忽略的 release/，不得进入提交。

## Current Behavior / Ownership / Non-goals

当前 main 与远端均为 7a57847（v4.2.5），存在粉丝档案名单同步、云端机器人直接开启、房主资料卡和礼物展示相关待发布改动。发布配置由 package.json 拥有，UPDATE.md 提供 GitHub Release 正文，scripts/publish-release.js 核对干净工作区、tag 提交、附件大小与 SHA-256。构建契约见 docs/architecture/engineering/build.md。不重构既有功能或更换发布基础设施。

## Milestones / Verification

- [x] 更新 package.json 与 package-lock.json 至 4.2.6，按 v4.2.5 以来实际 diff 编写 UPDATE.md。
- [x] 复用既有锁定服务端检出运行 npm run verify:contracts；运行 npm run verify:quick 和指南要求的 npm test。
- [x] 若失败，先复现并定位归属，仅修复阻塞点，重跑受影响检查；功能修复同步进入更新说明。
- [x] 检查最终 diff、git diff --check、git status --short，确认无敏感或运行时文件；记录验证结果，将准备计划归档。

## 发布后续

准备提交后按指南 git add、git commit -m "v4.2.6"；确认无 Claude Co-Authored-By 后 git push。运行 npm run release:win，核对 gh release view v4.2.6 中 lira-setup-4.2.6.exe、对应 .blockmap 和 latest.yml 均已上传，远端 tag 指向发布提交，附件与本地产物摘要一致。发布结果单独报告，不为回填此准备记录移动已发布 tag。

## Failure Handling / Done When

失败时保留现场和既有改动，不跳过失败断言、不移动已发布 tag、不破坏性重置。发布失败先检查当前 tag、Release 和附件状态，按指南重试同一提交并补齐产物。准备阶段在版本、日志、验证和 diff 检查完成后归档；提交与发布随后按上述步骤执行，实际发布结果由脚本、远端 tag 和附件核验确认并向用户报告。
