# 粉丝提醒计算优化

Status: Completed

## 目标与现状

将逐日寻找会员里程碑改成从有效区间与基线直接求候选日期；列表、提醒和日历复用同一档案的计算结果。上一轮 500 个档案仍需 8000 次会员摘要/查询，列表和提醒分别计算；本次以减少实际计算次数为验收，不只比较耗时。

## 所有权与兼容

`src/fans/membership.js` 拥有区间/基线与累计/连续语义；`reminders.js` 拥有窗口、稳定 key 和处理状态；`profile-service.js` 拥有账号范围内的读取。新增辅助文件仅承载候选日期推导和档案计算复用，不接管存储或授权。不改 HTTP/IPC、持久化、日期/到期规则和 UI 操作；保留前一轮及用户的未提交改动。

日期按北京时间，区间左闭右开、同日去重；基线只追加次日起的证据。连续周期、已处理历史、冲突暂停、当日尚未发生的区间、跨日/精确到期、回滚和账号隔离必须保持。

## 实施与验证

- [x] 直接求候选：累计按有效日序号定位，连续按区间起日/基线推导；只核对候选日与前一天，保留既有摘要 owner 的裁决。用确定性区间/基线样本与原逐日规则对照，并验证计算不随预测天数线性增长。
- [x] 复用计算：service 内有界缓存，以 scope/id、参与计算的实际输入内容、时间有效区间为依据；相同档案跨列表/提醒/日历共享，详情按需扩展预测。输入变化、午夜、有效期边界和时间倒退失效；返回副本防止调用方污染。无新定时器或数据库 schema。
- [x] 聚焦回归：`node --experimental-vm-modules --test test/fan-profiles/*.test.js`（PowerShell 用 rg 枚举）；临时数据仅仓库 tmp。新增算法对照与缓存失效测试；500 档案探针对比冷/暖读取、单人修改和跨日。
- [x] 同步 `docs/reference/frontend/app.md` 计算事实；用户操作不变，指南不改。执行 `npm run verify:docs`、相关语法及 `git diff --check`，检查本次增量与最终状态。

## 完成与失败处理

所有新旧行为用例通过，冷计算次数明显减少；未变化的重复读取不再执行会员摘要，单个档案的相关修改只失效该档案。缓存必须对真实输入而非易重用 revision/timestamp 判等，确保回滚和恢复不会返回旧结果。若候选算法存在差异，先定位规则而不削弱测试；只撤回本次拥有的改动，不覆盖前一轮成果。不提交、发布或访问真实用户数据。
