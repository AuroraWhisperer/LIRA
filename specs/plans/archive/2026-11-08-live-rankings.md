# Bilibili 实时四榜实施计划

Status: Completed

## Goal

在组件中增加实时榜单页：热门全站 TOP50、热门新人、人气全站、人气当前分区。使用当前授权账号配置的房间，高亮本房间，显示名次、原始分值、助力人数及差距；可将全部榜单或本房间附近名次发布为本地场景浏览器源。

## Current Behavior / Evidence

- 现有组件没有直播平台四榜；场景已支持独立组件外观、账号隔离、受保护浏览器源、变更通知及增量数据。
- 2026-11-08 实测官方 `getHotRankV3` 返回全站 / 新人各最多 50 行；`getPopularAnchorRank` 返回全站 / 分区最多 100 行；分类取 `getRankTabConfigWithList` 的房间推荐分区，不能在全站数据中筛选冒充分区榜。
- 官方建议刷新 15 秒。用户明确选择每秒两次真实查询（500ms），用于结榜前观察；不承诺上游每次都会更新，也不自动投票。

## Ownership / Compatibility

- 数据：`src/bilibili/live-rank-provider.js` 负责官方只读 HTTP 与字段投影；`live-rank-service.js` 负责账号 / 房间隔离、共享请求、500ms 调度、退避及闲置停止。
- 生命周期：`src/server/scene-runtime.js`；管理 API 沿用管理认证，场景数据沿用 capability 与 SSE，不新增远程服务器进程或权限。
- 外观：沿用 `public/js/shared/scene-extra-components.js` 与场景保存；实时榜单不落库，不进入设置云同步。当前房间由可信运行时读取。
- 展示：沿用组件库 / 画布 / 独立来源契约。组件标签页负责观察四榜及配置发布入口。
- 保留现有弹幕样式及文档的未提交修改，不提交、不发布软件或服务器。

## Acceptance Evidence

- 真实官方接口 3.5 秒有限采样：一次分类读取、七轮四榜（29 次发起，最后一轮尚未结束即取消）；完整六轮间隔约 510–513ms，响应头耗时 113–230ms。取得 50/50/100/100 行，四榜投影约 70KB，去掉原始响应的播放链接等无关字段。临时采样已经停止，不代表长期限流或 B 站每轮数据必变。
- 9 项初始数据 / 需求测试、62 项场景 / 管理页 / 独立来源回归通过；发现新数据版本不在场景白名单导致刷新闪空，已修复并补集成用例。数据 / 服务 / 场景 / 管理权限组 82 项通过。
- 预览 detach 保留编辑会话会使高频消费持续：增加兼容的 canvas `attached` 返回字段，榜单只在网页连接及图层可见时订阅。30 秒 browser 活动租约不改原编辑会话授权 / 草稿语义；正常关闭立即停订阅。64 项预览传输 / 控制器 / 榜单订阅测试通过。
- 隔离 Electron 使用真实 preload、管理认证及临时数据库；匿名 `/admin` 为 401。四榜与附近模式、本房间高亮、深色、榜单开关、保存后重载均验证。授权独立来源 HTTP 200，完整翻页及附近上下各一名可显示。模拟上游失败保留九行并标明数据年龄，恢复后继续；仅展示源活跃时 1.2 秒内约八次上游模拟调用，多窗口不倍增。关闭全部查看后和暂停后新增请求均为 0，重新打开同一编辑链接成功。
- 适配了客户端底部播放器占位与紧凑行距，默认完整榜每页五行。行数 / 一栏布局增加时需相应增高组件或调小字号。未在真实 OBS / 直播姬进程实播，也未修改用户当前运行应用。
- 最后 49 项编辑器重开 / 草稿恢复 / 身份续期 / 场景来源回归通过；1803 个 JavaScript 文件语法检查和 30 项架构检查通过。文档初次门禁仅因本计划使用中文状态前缀失败，按生命周期归档并改为标准状态后复验。所有自有 Electron / Chromium QA 实例已关闭，合成数据与截图留在 `tmp/`，未提交或发布。
- 测试与技术参考已同步；组件使用指南和应用内场景说明已更新。README、交互式导览、架构分层未改变操作或职责，无需重复说明；保持既有用户修改。

## Failure Handling / Non-goals

同一榜单请求不重叠；错误有界退避，保留最后成功数据并标记延迟。房间 / 账号改变清除旧状态并取消在途工作。停止消费者后到期取消。只撤回本任务修改，不操作用户数据或已有修改。不实现自动投票、B 站登录、直播间播放或远程部署。

## Done When

四榜可读取并共享 500ms 查询，客户端和场景展示可用，所需模式与持久化配置通过隔离运行验证；相关检查及文档完成，最终 diff 已审阅。B 站上游刷新、网络延迟和限流的限制在 UI 与交付说明中准确表达。
