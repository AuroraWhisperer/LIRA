# v5.0.7 Release Validation Implementation Plan

## Goal / Current Behavior
按照 RELEASE_GUIDE.md 完成客户端 v5.0.7 发布准备，随后执行提交、推送、标签和 GitHub Release。本记录归档已完成的发布准备与验证；实际发布结果由发布脚本和远端核验确认。任务开始时 main 位于 v5.0.6，工作区已有粉丝档案、客户端资源完整性、日志保留、契约和测试文档改动。

## Ownership / Proposed Changes
版本与变更说明由 package.json、package-lock.json 和 UPDATE.md 管理；发布入口为 scripts/publish-release.js。本任务只更新发布元数据，并在验证发现真实发布阻塞时修复其归属实现。

## Constraints / Non-goals
保留任务开始时所有用户改动，不部署服务端，不移动已发布标签，不操作用户正在运行的客户端，不提交运行数据、秘密或验证日志。只使用隔离测试数据和既有验证路径，不削弱测试或关闭发布完整性检查。

## Milestones / Verification
- [x] 对照 v5.0.6 总结已有差异，更新版本和 UPDATE.md；核对发布脚本、测试前置条件和远端标签。
- [x] 运行 npm run verify、npm run verify:modularity；测试失败时停止发布，先检查原因。
- [x] 审核发布元数据差异和待提交文件范围，检查 git diff --check；归档准备记录，提交前再次确认源文件摘要、文档门禁和工作区状态。

## Release Sequence
提交 v5.0.7，并在提交正文写入本版更新摘要；检查最新提交不存在 Claude Co-Authored-By 尾注，推送 main，运行 npm run release:win。完成后使用 gh release view v5.0.7 核对正式 Release 与 exe、exe.blockmap、latest.yml，以及远端标签、版本、摘要和工作区状态。不执行安装器，不部署服务端。

## Failure Handling / Done When
任何验证、构建、推送或上传失败都停止其依赖步骤；保留现有用户工作和已生成证据，禁止强制推送、破坏性重置或移动发布标签。准备完成条件为版本与说明一致、完整测试和静态门禁通过、提交范围已审核；发布任务最终完成仍需远端 main/标签一致、正式发布产物完整且版本正确、工作区干净，发布结果在任务回复中报告。
