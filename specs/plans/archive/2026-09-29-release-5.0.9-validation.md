# v5.0.9 Release Validation Implementation Plan

**Status:** Completed — 发布准备与验证完成；最终提交和远端发布结果在本任务回复中报告。

## Goal / Current Behavior

按照 RELEASE_GUIDE.md 完成客户端 v5.0.9 的发布准备与验证，再执行提交、推送和正式发布。用户已授权完整指南流程；开始时 main 与 GitHub main 均为 v5.0.8（0284d38f），工作区包含本次待发布的功能、测试及文档整理，暂存区为空。

## Ownership / Proposed Changes

package.json、package-lock.json 管理版本，UPDATE.md 提供提交与 Release 的变更摘要，scripts/publish-release.js 拥有 tag、构建、安装包验证及上传。仅新增本次发布元数据和验证记录；保留已有功能改动，实际验证失败若阻塞发布则定位拥有者并作最小修复。

## Compatibility Constraints / Non-goals

使用版本 5.0.9 和 tag v5.0.9，不移动已有 tag、不强推。仅发布 LIRA 客户端，不提交或部署 lira-server。使用锁定服务端 fixture 和隔离测试数据，不操作真实用户账号、数据或正在运行的应用。临时证据、日志与隔离 fixture 放在仓库 tmp/release-5.0.9/，不提交生成物或秘密。需配套服务器的功能在更新说明中明确注明。

## Milestones / Verification

- [x] 对照 v5.0.8 核对功能差异，更新版本和更新说明；核对远端 main/tag、测试及发布前置条件。
- [x] 准备 server-contract.lock.json 指定提交的独立 fixture 检出，验证哈希；复用已缓存 NSIS。执行 npm run verify，包含文档、语法、架构及指南要求的 npm test；记录实际结果，不弱化失败或跳过检查。
- [x] 审查完整待提交范围、发布元数据及敏感/运行时文件，核对验证期间源文件未漂移；执行 git diff --check 与 git status --short，记录结果并归档发布准备计划。

## Release Sequence

创建标题 v5.0.9、正文含 UPDATE.md 本版摘要的提交。按指南检查最新提交无 Claude Co-Authored-By 后 git push，再执行 npm run release:win。通过 gh release view v5.0.9 核对正式发布状态、说明和 exe、exe.blockmap、latest.yml；核对远端文件大小/摘要、更新清单版本、main/tag 与本地 HEAD 一致及最终工作区状态。

## Failure Handling / Done When

失败时停止依赖该结果的提交或发布步骤，保留诊断证据，修复实际阻塞后重跑相关检查；不绕过契约锁或安全校验、不删除用户工作。准备阶段在版本一致、完整验证通过且提交范围审阅后完成并归档。最终发布是否完成以实际远端核验为准，在本任务回复中报告，不能用本记录代替发布证据。
