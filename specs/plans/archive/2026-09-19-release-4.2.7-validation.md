# v4.2.7 Release Validation Implementation Plan

**Goal:** 按 RELEASE_GUIDE.md 验证并发布当前代码，修复实际阻塞，以 v4.2.7 提供 Windows 安装包。

**Architecture:** 沿用 package.json、UPDATE.md 和 scripts/publish-release.js 的单仓发布流程。现有工作区改动纳入本次版本；修复仅覆盖验证和发布阻塞。

**Tech Stack:** Node.js 24、Electron 43、npm、Git、GitHub CLI、electron-builder。

## Global Constraints / Compatibility

- 用户明确要求按 guide 执行并指定 4.2.7，包含提交、推送、tag 和 GitHub Release；按既有约定使用 v4.2.7。
- 保留当前用户改动；不部署服务器，不读取或修改真实用户数据库，不改变已接受的公共契约和安全边界。
- package.json、package-lock.json、UPDATE.md 版本保持一致；测试日志和安装包放在系统临时目录或忽略的 release/。
- 不移动已发布标签，不以跳过失败断言或破坏性 Git 操作绕过发布门禁。

## Current Behavior / Ownership / Non-goals

当前 main 为 be335ce（v4.2.6），工作区包含弹幕屏蔽、粉丝档案与大航海资料、数据库查询、礼物展示及管理界面改动。版本由 package.json 拥有，UPDATE.md 提供 Release 正文，scripts/publish-release.js 校验干净工作区、标签提交与附件大小/SHA-256；构建契约见 docs/architecture/engineering/build.md。本任务不重构已有功能或更换打包设施。

## Milestones / Verification

- [x] 对照 v4.2.6 的代码差异整理更新说明，设置 package.json 与 package-lock.json 的版本为 4.2.7。
- [x] 核验 Node/Electron、GitHub 登录与目标标签状态，定位契约锁指定的服务器检出。
- [x] 运行 npm run verify（契约、文档、JavaScript 语法、架构和指南要求的 npm test）；仅修复实际失败并重跑相关检查。
- [x] 审查最终 diff、git diff --check、git status --short，确认提交内容与发布范围相符，记录准备阶段结果并归档计划。

## Release Steps

准备完成后按 guide 提交 v4.2.7，检查最新提交无 Claude Co-Authored-By，推送当前 main；随后运行 npm run release:win。用 gh release view v4.2.7 核对 lira-setup-4.2.7.exe、lira-setup-4.2.7.exe.blockmap、latest.yml，确认远端 tag 对应发布提交且上传摘要与本地产物匹配。发布结果在最终回复报告，不为回填计划移动 tag。

## Failure Handling / Done When

失败时保留现场、日志和用户改动。先定位失败归属，再做最小修复；网络或附件问题先检查已存在的 tag/Release，再按指南重试同一提交。准备阶段在版本、更新日志、门禁和差异审核完成后归档；整个任务在提交推送、发布脚本成功、三个附件和标签核验完成后结束。
