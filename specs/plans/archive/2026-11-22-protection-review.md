| 阶段 | 修改归属与判断 | 完成依据 |

## 七项优先修正

| 触发情形 | 修正结果 |
| --- | --- |
| 旧醒目留言中两条内容相同，只有一条带平台 ID | 两种迁移顺序都保留两条记录。平台撤回只命中带 ID 的一条。 |
| 退出时播放快照的 IPC 与 HTTP 写入均失败 | renderer 保留待存快照，主进程按既有超时和告警路径退出。成功写入或确实没有待存内容才发送完成回执。 |
| 服务端设置、歌库、B 站凭据的版本行损坏 | 旧库缺行时仍可推导初始版本。已有行解析失败或修订号非法时停止写入。凭据变化引起的设置重置遵循同一规则。 |
| 官方盲盒接管时原归档 JSON 损坏或类型不对 | 本次接管停止，原归档、活动映射和版本保留，也不会发布成功通知。 |
| 粉丝备份只给出日期精度的会员区间 | 恢复写入预览认可的起止时间，会员摘要可读，原始依据和人工修订均保留。 |
| 单独清空歌库时无法补建默认曲风 | 默认曲风、歌曲删除和云端待传快照在同一事务中提交。任一步出错都可回滚。 |
| 礼物特效金额留空后触发预览错误 | 预览错误只提示本次输入问题。保存和重试共用校验，明确输入 `0` 仍可保存。 |

## 其余取舍

- 手动云歌库确认只计数，提交时检查账号归属，排到上传时再取最新快照。相同歌词内容复用已有发布结果。盲盒在重连首帧补读一次，默认按事件和跨日刷新，正数 `r` 才启用轮询。舰徽仅在房间或档位变化时更新已有节点。
- 豆包网页退出后可在同一会话代次重试删除加密快照。桌面关停注销授权 IPC。唤醒后分别恢复云同步和礼物游标。队列先显示已收到的快照，再补点歌人资料。管理页区分数据库提交结果和本机清理结果，打开画布前等待本轮保存完成。
- 身份门面接管的缓存只向旧入口提供最终投影。旧格式的独立调用沿用原签名，复用同一份等级来源和昵称质量规则。组合运行验证覆盖了礼物证据、旧榜单回写、切房后清除房间身份和最近观众。见[身份门面契约](../../../docs/reference/backend/bilibili/danmaku.md#10-用户信息门面与房间运行边界)。
- 已收回无现役调用的点歌板包装方法、三个播放提供方方法和内部冗余分支。原生音频将同一次命令的状态用于事件和回执。服务端合并重复建表、租户目录及小游戏校验和首轮通知，公开事件流复用握手后的设置读取，同步保留准入检查。
- 已发布字体 URL、缓存、独立字体适配器、旧粉丝导入、运行时工厂形式和音乐注册表有现行兼容约定。合成工坊的 `validateProgress` 仍由网页全局导出。保留这些入口及其必要校验，外部调用范围需在正式退役时确认。见[字体存储契约](../../../docs/reference/backend/storage.md)。
