# Feature: 多组件工作区与本地场景

## Goal

按用户 2026-09-30 的后续要求逐阶段完成组件方案。P2 同时查看和调整四种组件；P3 将布局和独立外观发布为真实本地浏览器来源；P4 增加本地编辑效率能力。用户已确认先完成本地模板、撤销重做等能力；跨设备、云端输出与 OBS 控制另议，不纳入当前实施。

## Context

P1 已有四个共享草稿控制器、单组件沙箱预览、原领域保存路径和只读展示投影。原始设计与学习路线位于 tmp/component-preview-design.md 和 tmp/component-preview-references.md。P2 工作区、P3 场景文档与组合输出、P4 本地编辑能力均已实现并验证，证据见 [归档计划](plans/archive/2026-09-30-component-workspace.md)。

## Constraints

沿用 Electron、原生 ESM/CSS 和模块化单体，无新依赖或服务。OBS 和哔哩哔哩直播姬均消费浏览器来源。所有验证使用合成数据和隔离存储，不操作真实直播或生产账号。

## Architecture

P2 由 Admin 组合根加载现有组件 owner。组件注册可创建预览描述的工厂，描述绑定确切 controller，不通过全局 currentComponent 解析业务目标。单组件和工作区共用展示实例的沙箱、消息验证与释放代码。窗口互斥，关闭视图不销毁草稿。

保存全部在提交前同步校验所有已修改目标并冻结提交；每个领域自行确认保存。分别显示成功、失败、未提交，失败保留草稿。只重试失败项，不重提成功项，也不回滚其他领域。保存中编辑保留，账号 reset 后旧结果无效。

P3 的场景 owner 持有画布、稳定 item ID、组件类型、配置引用/独立外观、位置尺寸、层级、可见性和版本。编辑视口/选中态与业务运行数据不入文档。持久化、只读场景能力和弹幕真实数据接入遵循 [场景规格](component-scenes.md) 与 ADR-0022；完整输出已通过实际 renderer 和隔离 Electron 消费验证。

## Security And Compatibility

预览只消费允许的展示配置/数据；不取得管理员或设备凭据。父级验证精确 iframe source 和 opaque origin，子级验证直接父级和本站 origin。继续保护单页 URL、设置键、领域写入授权和已有草稿。模板不包含能力 URL 或账号凭据。

## Acceptance Criteria

1. P1 契约在锁定 Server 提交上通过，保留现有检出和用户修改。
2. P2 一次显示四类 renderer，每类一个；选择组件仅切换参数面板，其余草稿和预览保留。工作区明确编辑当前组件默认配置，组合排布不标记为直播布局。
3. 页面、单组件窗口、工作区使用同一控制器；两向编辑/保存一致，关闭重开保留草稿。
4. 保存当前/全部、失败结果和只重试失败项可用；全部提交预检失败不产生任何写入；提交快照不会混入提交过程中新增编辑。
5. 未授权/未加载、迟到响应、账号切换、外部配置更新按 P1 边界处理。重复打开只有一个窗口，关闭释放全部 frame、监听、数据回调与计时器。
6. P3 保存场景布局与实际组合输出一致；只读范围认证、版本确认、重启恢复和旧单页来源兼容均有针对性证据。多个实例可共享业务数据但独立外观。
7. 整套发布由场景 owner 持久化完整版本；输出准备新版本失败继续显示上一版，成功整体切换。业务数据持续更新，不参加外观发布事务。
8. P4 本地能力覆盖对齐/吸附、组合移动、锁定/显隐、撤销重做、展示模板导入导出。一次拖动为一个历史操作，业务数据与保存回填不进历史；导入资源需要显式重新绑定。

## Done When

逐阶段记录真实命令、测试和隔离 Electron/来源验收。未完成项保留未勾选；全部必要交付均有直接证据后才结束目标。远端可选范围依用户答复补充。
