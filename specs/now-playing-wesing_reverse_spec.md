# Now Playing 全民 K歌歌词链路逆向说明

## 分析范围

本说明只覆盖 `now-playing-service` 的全民 K歌歌曲识别与歌词获取链路。证据来自：

- `WeSingService.cs`：窗口标题与 UI Automation 播放进度。
- `wesing/WeSingService.java`：本地日志、QRC 定位与索引。
- `LyricService.java`：本地歌词优先和在线回退策略。
- `QQMusicService.java`、`SongMatchingUtil.java`：在线候选匹配与安全阈值。
- 本机运行实例 `127.0.0.1:9863` 的只读 API：当前《失控》歌词来源为 QQ。

## 观察到的数据流

1. `WeSing.exe` 的播放子窗口标题提供歌曲名，格式为 `全民K歌 - {歌名}`。
2. UI Automation 在该窗口后代文本节点中查找 `MM:SS | MM:SS`，提供当前进度和总时长。
3. 本地歌词优先读取用户选择的 `WeSingCache\WeSingDL\Res`：
   - 优先从 UTF-16LE 日志的最新 `StartKSong` 记录获取 `mid`；
   - 其次扫描、解密 QRC，并按规范化歌名和版本修饰词匹配。
4. 本地 QRC 不可用时，歌词服务退化到在线匹配：
   - 开启“智能匹配最佳歌词”时并行请求 QQ 和网易云；
   - 每个平台对搜索候选计算歌名、歌手与版本相似度；
   - 候选通过阈值后，比较普通歌词、翻译和逐字歌词完整度；
   - 内容完整度相同时使用用户配置的默认歌词源。

## 《失控》真实数据验证（2026-08-13）

- 参考程序在全民 K歌播放《失控》、总时长 255 秒时，`GET /api/lyric` 返回 `source=qq`、`hasKaraokeLyric=true`。
- 参考程序返回的 `karaokeLyric` 有 76 个非空原始行，包含 XML 包装、QRC 元标签、制作信息和正文。
- 本项目对 QQ 曲目 `003N2hzR4511Hh` 解密和解析后得到 64 条可展示歌词行；首行是“井迪儿 - 失控”，包含词、曲、编曲、制作人等信息，末行时间为 247519 毫秒。
- 本项目的全民 K歌在线解析器在 QQ/网易云并行选择后仍选中 QQ，时间轴规范化后保持 64 行，没有 9 行上限。

## 观察到的需求（EARS）

- 当全民 K歌播放子窗口出现时，系统应从窗口标题提取当前歌名。
- 当 UI Automation 提供进度文本时，系统应解析当前秒数和歌曲总秒数。
- 当匹配的本地 QRC 存在时，系统应优先使用本地逐字歌词。
- 当本地 QRC 不存在或无法匹配时，系统应尝试在线歌词，不应因缓存目录为空而停止歌曲识别。
- 当一个在线平台失败时，系统应允许另一个平台独立返回歌词。
- 当候选歌名不可靠时，系统应返回空歌词，不应展示明显不匹配的歌词。

## 本项目实现差异

本项目通过 `src/music/wesing-online-lyrics.js` 隔离在线回退，采集状态机只依赖
`resolveFallbackLyrics()` 接口。在线策略保持 QQ/网易云并行与完整度择优，同时额外使用
UI Automation 得到的歌曲总时长，对同名翻唱、现场版和原版进行消歧。若歌词类型质量、
歌曲匹配度与时长都相同，本项目再以可展示行数择优，避免 9 行的局部结果压过完整时间轴。

## 播放进度与暂停语义（2026-08-13 补充）

证据来自参考项目的 `WeSingService.cs`、`Program.cs`、`NowPlayingService.java`，以及前端 `playerService.ts`：

1. 参考采集器默认每 100 毫秒读取一次全民 K 歌的整数秒进度。
2. 当整数秒发生变化时状态为 `Playing`；连续 1500 毫秒没有变化时状态为 `Paused`。
3. Java 端在整数秒变化时把连续计时器强制校准到实测进度，在暂停确认时冻结连续计时器。
4. 前端每次收到进度同步时加 130 毫秒固定补偿，然后仅在非暂停状态继续推进歌词计时器。

修复前，本项目的采集间隔为 250 毫秒、没有 130 毫秒补偿，并在确认暂停时回退到最后一个整数秒采样值。这会让进度与参考程序产生固定偏差，也会让暂停瞬间出现先推进、再回跳的视觉错位。修复后，本项目采用相同的 100 毫秒采样、1500 毫秒暂停判定、130 毫秒补偿和连续时钟冻结语义。

观察到的需求（EARS）：

- 当 UI Automation 的整数秒进度变化时，系统应使用该实测值加 130 毫秒重新校准歌词时钟。
- 当整数秒连续 1500 毫秒没有变化时，系统应发布 `playing=false` 并冻结当前连续位置。
- 当 UI Automation 没有返回进度文本时，系统应立即发布 `playing=false`，不应继续使用本地时钟猜测播放状态。
- 当歌词消费者收到 `playing=false` 时，系统应取消动画帧，不再推进逐字高亮或歌词时间轴。

已知限制：全民 K 歌只向 UI Automation 暴露整数秒文本，因此进度文本仍存在但停住时，暂停确认最多会有约 1.5 秒检测窗口；进度文本消失时则立即冻结。确认后歌词必须保持冻结。

## 已知不确定性

全民 K歌窗口标题通常不包含歌手。若多个版本歌名和时长都相同，任何纯在线匹配都可能
无法完全消歧；此时本地 `StartKSong` 的 `mid` + QRC 仍是最可靠来源。

但参考软件仍能返回《失控》的 QQ 逐字歌词。这证明该次成功来自在线回退，而不是本地 QRC。
