# Feature: 完整桌面歌词时间轴预览

## Requirements (EARS Format)

- 当在线播放或全民 K 歌捕获到完整歌词时，系统应只在时间轴变化时发布完整歌词。
- 当管理页收到时间轴时，系统应立即渲染全部歌词、翻译、罗马音和歌词内的制作信息。
- 当播放位置变化时，系统应高亮当前行、显示逐字进度并自动跟随。
- 当当前歌词行切换时，系统应以逐帧弹簧动画将当前行移动到中央阅读锚点，并同步过渡相邻行的缩放、模糊和透明度。
- 当用户滚动歌词列表时，系统应暂停自动跟随 6 秒，允许查看上下文。
- 当长间奏后的下一句剩余不超过 3 秒时，系统应在对应位置显示三拍倒计时。
- 当收到不受信任的时间轴负载时，系统应限制字段、条数和总字符预算，并清除控制字符。

## Architecture

### Frontend

- `LyricService` 新增低频时间轴发布；以曲目身份和歌词对象引用去重，当前行仍沿用高频 `lyric-state`。
- 管理页状态服务接收 `lyric-timeline` 快照和增量消息。
- 预览页一次性用 DOM 文本节点渲染全部行；播放帧只更新 active 类、逐字 CSS 进度、倒计时和弹簧跟随位置。
- 空、加载和网络失败继续使用明确状态文案；时间轴发布失败不阻断当前行和独立歌词窗口。
- 歌词滚动区可键盘聚焦，支持鼠标滚轮、触摸和键盘浏览；遵守减少动态效果设置。
- 自动跟随使用稳定的中心锚点和阻尼弹簧，不依赖浏览器一次性的 `smooth` 滚动；页面不可见时暂停帧，重新可见后继续收敛。

### Backend

- 新增 `normalizeLyricTimeline()`，规范化标题、歌手、状态和歌词行。
- 新增 `POST /api/playback/lyric-timeline`，保存浏览器播放端的当前时间轴并广播 `lyric-timeline`。
- 服务端快照新增 `lyricTimeline`，新连接可立即得到整首歌词。
- 全民 K 歌捕获在歌词重置/加载完成时调用低频 `onTimeline` 回调，不在每个进度采样中复制歌词。

### Security

- 路由复用现有本地会话令牌校验，不新增公开入口或敏感字段。
- 服务端最多接收 500 行，并实施 48 KiB 字符总预算；时间、状态和文本字段均规范化。
- 管理页不使用歌词拼接 `innerHTML`，所有外部文字通过 `textContent` 写入。
- 此接口只更新易失的当前播放状态，不写数据库；无需 SQL，也不存在资源所有权变化。
- 保持现有统一 400 错误响应；发布失败在前端被隔离，不影响音频播放。

## Visual direction

- 主题：LIRA 的”歌词跑道”，单一任务是边调样式边检查整首实时歌词。
- 色彩：Night Vinyl `#15171b`、Grid Slate `#202328`、Lyric Mist `#f5f7fa`、Playback Gold `#ffcf4a`、Control Rose `#ff6f91`。
- 字体：歌词继续使用用户选择的字体；标题和控制沿用现有界面字体；倒计时使用窄幅数字感字形。
- 布局：

  ```text
  ┌──────────── 现有标题与控制 ────────────┐
  │                                        │
  │   制作信息 / 已唱歌词（雾灰）           │
  │   ●  ○  ○   三拍倒计时                 │
  │  ┌ 当前歌词（金色逐字 + 半透明底板） ┐ │
  │   下一句与后续歌词（低对比，可滚动）     │
  │                                        │
  └──────────── 播放总进度 ────────────────┘
  ```

- 标志性元素：倒计时作为时间轴中的真实一行移动到下一句之前，而不是覆盖整块预览。

## Acceptance criteria

- 给定包含制作信息和正文的时间轴，打开管理页后无需等到第一句播放即可查看所有行。
- 给定播放位置早于第一句，预览不再只显示“前奏中”。
- 给定超过 6 秒的歌词间隔，距离下一句 3/2/1 秒时依次点亮三拍倒计时。
- 给定逐字歌词，当前行的字级高亮随插值后的播放位置推进。
- 给定恶意超长或带控制字符的负载，广播结果保持在预算内且 DOM 不执行内容。
