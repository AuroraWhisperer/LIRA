# Feature: 全民 K 歌歌词同步控制

## Requirements (EARS Format)

- 当用户调整全民歌词时间偏移时，系统应保存 `-1500ms` 至 `1500ms` 的值，并立即用该值选择歌词行和计算逐字进度。
- 当偏移为负值时，系统应延后歌词；当偏移为正值时，系统应提前歌词。
- 当全民 K 歌显示歌曲加载状态时，系统应保持歌词时钟暂停。
- 当全民 K 歌仍显示歌曲加载状态时，系统应保持歌词时钟暂停。
- 当加载状态消失时，即使 UI Automation 没有提供进度文本，系统也应启动本地单调歌词时钟。
- 当 UI Automation 提供有效进度时，系统应使用最新采样位置校准歌词时钟。
- 当权威进度向后校正时，歌词渲染器应接受该校正，不能继续保留较快的本地估算值。

## Architecture

### Frontend

- 在全民 K 歌捕捉面板增加时间偏移滑块和数字输入框。
- 通过专用接口保存偏移，使用接口返回的捕捉状态刷新两个输入控件。
- 输入范围为 `-1500～1500ms`，步长 `50ms`，并提供负值延后、正值提前的说明。

### Backend

- 在设置存储中增加 `weSingLyricOffsetMs`，默认值为 `0`。
- 全民捕捉服务负责校验、持久化和应用偏移，原始播放进度保持不变，只有对外的 `lyricState` 使用偏移后的时间。
- UI Automation 采样增加 `loading` 标记；捕捉状态机在加载期间暂停，加载结束后沿用 Now Playing 的乐观本地计时兜底。

### Security

- 复用现有本地 API 鉴权。
- 服务端只接受有限数值，拒绝非数字和超出 `-1500～1500ms` 的输入。
- 不增加文件访问、外部请求或敏感数据输出。

## Acceptance Criteria

- 偏移设置重启后仍然保留，并且三个歌词界面使用相同的偏移后状态。
- 新歌曲在加载样本期间保持暂停，加载结束后无需等待进度文本即可开始播放。
- 有效进度样本到达后，歌词从该采样位置校准。
- 进度小幅向后校正时，渲染位置立即向后校正。
- `npm run check` 和 `npm test` 均通过。
