# 粉丝档案

状态：In Progress（首发实现已完成，仓库收尾门禁有无关失败）。2026-09-18 用户要求按调研文档开始实施，采用其第一、二阶段及 A01–A30 作为首发目标；第三阶段不在本次范围。实现及实际验证结果见 [实施计划](plans/2026-09-18-fan-profiles.md)。

## 目标与依据

行为以 [调研与设计](../docs/reports/2026-09-18-fan-profile-research-and-design.md) 的第 5–14 节为依据：私密关系记忆、人工修订、会员证据与基线、稳定提醒、成功点歌归档、可恢复的服务器事实同步。未知到期日不估算；农历不自动换算。

## 所有权与边界

- `src/fans/` 拥有验证、会员日期/冲突/周期、提醒与档案应用流程。
- `src/storage/fan-*.js` 拥有持久化；使用现有 songDb，保证点歌与档案快照在同一 SQLite 事务内提交。只追加迁移，档案没有指向可清理曲库/队列的外键。
- `src/electron/fan-profile-controller.js` 从 licenseManager 的已认证服务器 origin 和 streamerId 生成归属；renderer 不提供授权归属。异步操作固定归属和授权代次，完成前重新检查。
- `fan-profiles:invoke` 是主窗口、主 frame、精确本地 origin、Admin 路径限定的私有 IPC；通用 HTTP、WebSocket、OBS、AI、settings 同步不包含私人档案。
- Server 新增 device 认证的 `/api/device/fan-facts` 只读增量协议，租户从 `req.device.streamer_id` 解析。只同步可靠身份观察和会员事实，不上传手写资料。无经核实期限的数据输出观察事实。
- `public/js/admin/fans/` 拥有列表、共用详情、编辑表单和提醒；百宝箱只负责导航。

## 持久化契约

身份为 `[serverOrigin, streamerId, platform, identityType, externalId]`，UID 与 open_id 不互换。档案 ID、记录 ID、成功请求标识使用不可复用 UUID。手写字段与自动资料分开；原始事实和每次人工修订均保留。归档可恢复，删除可以保留身份抑制标记。

日期采用 Asia/Shanghai；有效期开始包含、结束不包含，人工有效至日期包含该日。当天已发生的有效日计一天，未来日只用于预测。基线只追加截至日之后有证据的有效日；未知历史不计零、不反推连续。冲突不静默采用，依赖该证据的提醒暂停。

提醒身份由档案/规则/事项组成；生日按年度，连续里程碑按稳定周期和阈值，累计按阈值。日期修订不重置处理状态。

完整备份格式 `lira-fan-profiles`、version 1，保留 scope、档案、原始事实、修订、稳定来源键、提醒处理与删除抑制。恢复先预览并保存恢复前快照；跨归属拒绝自动并入；冲突需明确选择。CSV 是字段可选的列表导出，不能恢复。

## 兼容与完成条件

### 登录续期与页面状态（2026-09-19）

同一服务器、同一主播持续授权期间，后台续期或无身份变化的状态通知保留页面上下文、当前选中详情及已打开的编辑操作。续期仍更新内部授权代次并取消旧异步请求，旧代次结果不得落库。更换服务器/主播、退出或失去授权后，旧页面上下文失效，即使重新登录同一账号也不能复用；页面提示“登录状态已变化，请重新选择档案。”，不把所有状态更新都描述为换账号。

### 点歌展示与归档（2026-09-19）

点歌队列的点歌人一行恢复为“昵称 · 来源 · 时间”，不显示档案入口。随机点歌（含带筛选条件的随机点歌）正常入队，但不新增粉丝档案点歌记录；普通点歌仍按已有规则归档。已有档案记录不自动删除。

### 名单展示（2026-09-19）

列表先按最近一次大航海名单确认的当前身份依次排列为总督、提督、舰长，当前不在舰或身份未知的档案排后；每组内再按本房间粉丝灯牌等级降序排列，同等级沿用最近记录时间排序，未取得等级的档案排后。灯牌等级与总督、提督、舰长的会员等级分别处理。等级只读取房主 UID 匹配的灯牌，并以可选 `medalLevel` 字段保存在名单观察记录的原始依据中；旧记录缺少该字段时仍可读取，重新同步后补齐。同日灯牌变化可追加观察，不覆盖人工修订；完整备份保留该依据。

页面省去重复标题和宣传性说明，列表不展示 UID、最近互动或空资料占位；UID 保留在详情。列表和详情填满工作区并分别滚动，工作区外层不滚动。百宝箱入口沿用其他卡片的箭头。

最新同步确认的舰长、提督、总督分别显示蓝、紫、红色姓名及对应身份图标，列表与详情使用同一身份；图标复用礼物页面已有的三种大航海图片，悬停和替代文本说明身份，不再显示姓名旁的身份文字。不以资料完整程度或是否取得到期日期为条件。“在舰”筛选包含最近名单确认的成员。已有档案不在完整且身份可识别的同房间名单中时，姓名恢复普通文字颜色并隐藏身份，保留档案、原始记录和人工修订；重新出现在名单中时恢复对应身份。含神秘人等未知身份的名单不据缺席清除此前身份。

当前名单快照存入档案的可选 `guardRoster`，列表及详情返回 `currentGuardLevel`。旧档案或旧备份缺少该字段时，使用已有名单原始观察；只有历史上舰事件而没有名单或有效区间依据时，不显示当前身份。名单身份与会员有效期分开处理，到期日期、累计／连续天数和提醒仍按已确认依据计算，不从名单推算。

### 手动同步大航海名单（2026-09-18）

最初只提供手动一键同步；2026-09-20 增加下述可选每日自动同步。手动入口为“设置 → 同步大航海名单”，展示当前配置房间，点击“同步并预建档”后读取该房间房主的完整当前名单。房主 UID 从 B 站房间解析结果获取；来源为 `room_init` 与 `guardTab/topListNew`，分页合并 top3/list 并按 UID 去重（[平台接口字段参考](https://github.com/pskdje/bilibili-API-collect/blob/main/docs/live/guard.md)）。

主进程新增私有 `sync-guard-roster` action，并在现有 IPC 结果中附加 `roomId` 供表单显示。只接受操作意图，忽略 renderer 的房主、房间、归属和成员数据；使用当前认证归属及主进程配置房间。`expectedRoomId` 仅用于检查表单打开后房间是否变化，不用于选择来源。完整读取并重新核对账号、授权代次和房间后，在一笔本机事务中预建档案。失败不导入半份名单；同时只允许一次读取；账号变化或退出会中止读取，退出时等待读取结束再关闭存储。

手动同步独立于自动更新开关，预存可靠 UID、可获取的昵称/头像、带同步时间和来源房间的大航海观察记录。保留私人字段、原始记录和人工修订；跳过归档及删除抑制身份。同房间/UID 在北京时间同一天连续同步到相同等级时不重复追加观察；真实等级变化保留新的观察，来源键包含房间/UID/观察时间/等级以支持重放去重。名单不用于推算到期日、累计或连续天数；缺席只更新当前身份展示，不删除档案、不生成虚构到期日期。完成反馈新增、更新及跳过数量，可继续通过已有表单补充基础和私人信息。

按钮不可选中文字，正文选中同时保持可读前景色。隔离回归见 `test/bilibili-guard-roster.test.js`、`test/fan-profiles-guard-roster.test.js`、`test/fan-profiles-ipc.test.js`；执行与验收见 [实施计划](plans/archive/2026-09-18-fan-guard-roster.md)。

### 每日自动同步名单（2026-09-20）

“设置自动更新”新增“每天自动更新大航海身份”，默认关闭。重点核对当前是否仍在大航海及舰长／提督／总督等级；完整且身份可识别的名单中已不在舰者取消当前身份显示，保留备注与历史记录。开启后，按北京时间每天 12:10 在客户端主窗口存在时同步当前配置房间；12:10 前启动则等到该时间，错过后当天首次打开客户端时补同步。最小化仍视为窗口存在；无需停留在粉丝档案页。现有 15 秒事实同步和手动名单同步保留。

设置保存为当前认证归属的可选 `autoSyncGuardRoster` 布尔字段；旧数据缺少时关闭，旧 configure 调用省略该字段时保留现值。名单导入成功时在同一事务内保存 `lastGuardRosterAutoUpdate: {date, roomId}`，同归属、同房间当天不重复自动更新，重启仍有效。失败不保存成功日期，同一会话当天不反复重试；可手动同步或下次启动重试。自动与手动共用单次读取、完整名单导入及账号/代次/房间检查；关闭设置后尚未完成的自动名单不导入。

Admin 初始化时及每 15 秒通过受限 `auto-update-status` 获取通知，与粉丝档案页是否可见无关。定时和启动补更新分别 toast 提示已同步最新大航海身份；失败显示对应原因。通知按当前页面上下文取走一次，账号变化后不显示旧归属结果。controller 拥有定时器及异步操作，退出时取消并等待；renderer 在 pagehide 清理轮询。

### 档案设置（2026-09-19）

“提醒”右侧新增“设置”页签，替代“更多”菜单。原有操作按“同步与更新”“导出与备份”“档案管理”分组，每项配有用途说明。原“刷新”移入设置，改称“重新加载档案”，只重读本机档案与提醒，不触发大航海名单同步；页面仍在打开时及停留期间每 30 秒自动读取。自动读取与手动重新加载保留当前页签，查看已归档后可从列表直接返回未归档档案。

保持现有礼物 DTO、所有公开快照和授权行为。普通歌曲/全部业务流水清理保留粉丝档案，在清理界面明确说明；档案另有专用删除流程。无额外框架、服务、依赖或构建步骤。

按隔离临时数据库/虚构资料验证 A01–A30；完成点歌原子性、UID 命名空间、会员日期/冲突、提醒稳定性、恢复、IPC 来源与账号切换测试。通过相关测试、语法、架构和全套测试，审查 diff 后才标记 Implemented。具体进度见 [实施计划](plans/2026-09-18-fan-profiles.md)。
