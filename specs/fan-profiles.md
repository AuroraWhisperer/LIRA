# 粉丝档案

状态：In Progress（首发实现已完成，仓库收尾门禁有无关失败）。2026-09-18 用户要求按调研文档开始实施，采用其第一、二阶段及 A01–A30 作为首发目标；第三阶段不在本次范围。实现及实际验证结果见 [实施计划](plans/2026-09-18-fan-profiles.md)。

## 目标与依据

行为以 [调研与设计](../docs/reports/2026-09-18-fan-profile-research-and-design.md) 的第 5–14 节为依据：私密关系记忆、人工修订、会员证据与基线、稳定提醒、成功点歌归档、可恢复的服务器事实同步。未知到期日不估算；农历不自动换算。

## 所有权与边界

- `src/fans/` 拥有验证、会员日期/冲突/周期、提醒与档案应用流程。
- `src/storage/fan-*.js` 拥有持久化；使用现有 songDb，保证点歌与档案快照在同一 SQLite 事务内提交。只追加迁移，档案没有指向可清理曲库/队列的外键。
- `src/electron/fan-profile-controller.js` 从 licenseManager 的已认证服务器 origin 和 streamerId 生成归属；renderer 不提供授权归属。异步操作固定归属和授权代次，完成前重新检查。
- `fan-profiles:invoke` 是主窗口、主 frame、精确本地 origin、Admin 路径限定的私有 IPC；通用 HTTP、WebSocket、OBS、AI、settings 同步不包含私人档案。
- Server 新增 device 认证的 `/api/device/fan-facts` 只读增量协议，租户从 `req.device.streamer_id` 解析。只同步可靠身份观察和会员事实，不上传手写资料。无经核实期限的数据输出观察事实。
- `public/js/admin/fans/` 拥有列表、共用详情、编辑表单和提醒；百宝箱只负责导航。

## 持久化契约

身份为 `[serverOrigin, streamerId, platform, identityType, externalId]`，UID 与 open_id 不互换。档案 ID、记录 ID、成功请求标识使用不可复用 UUID。手写字段与自动资料分开；原始事实和每次人工修订均保留。归档可恢复，删除可以保留身份抑制标记。

日期采用 Asia/Shanghai；有效期开始包含、结束不包含，人工有效至日期包含该日。当天已发生的有效日计一天，未来日只用于预测。基线只追加截至日之后有证据的有效日；未知历史不计零、不反推连续。冲突不静默采用，依赖该证据的提醒暂停。

提醒身份由档案/规则/事项组成；生日按年度，连续里程碑按稳定周期和阈值，累计按阈值。日期修订不重置处理状态。

完整备份格式 `lira-fan-profiles`、version 1，保留 scope、档案、原始事实、修订、稳定来源键、提醒处理与删除抑制。恢复先预览并保存恢复前快照；跨归属拒绝自动并入；冲突需明确选择。CSV 是字段可选的列表导出，不能恢复。

## 兼容与完成条件

### 手动同步大航海名单（2026-09-18）

用户确认只做手动一键同步，不新增定时同步。入口为“更多 → 同步大航海名单”，展示当前配置房间，点击“同步并预建档”后读取该房间房主的完整当前名单。房主 UID 从 B 站房间解析结果获取；来源为 `room_init` 与 `guardTab/topListNew`，分页合并 top3/list 并按 UID 去重（[平台接口字段参考](https://github.com/pskdje/bilibili-API-collect/blob/main/docs/live/guard.md)）。

主进程新增私有 `sync-guard-roster` action，并在现有 IPC 结果中附加 `roomId` 供表单显示。只接受操作意图，忽略 renderer 的房主、房间、归属和成员数据；使用当前认证归属及主进程配置房间。`expectedRoomId` 仅用于检查表单打开后房间是否变化，不用于选择来源。完整读取并重新核对账号、授权代次和房间后，在一笔本机事务中预建档案。失败不导入半份名单；同时只允许一次读取；账号变化或退出会中止读取，退出时等待读取结束再关闭存储。

手动同步独立于自动更新开关，预存可靠 UID、可获取的昵称/头像、带同步时间和来源房间的大航海观察记录。保留私人字段、原始记录和人工修订；跳过归档及删除抑制身份。同房间/UID 在北京时间同一天连续同步到相同等级时不重复追加观察；真实等级变化保留新的观察，来源键包含房间/UID/观察时间/等级以支持重放去重。名单不用于推算到期日、累计或连续天数；未出现在名单中的已有档案不删除、不自动判为下舰。完成反馈新增、更新及跳过数量，可继续通过已有表单补充基础和私人信息。

“更多”采用原生 popover，点击外部、Esc 或执行操作后关闭；按钮不可选中文字，正文选中同时保持可读前景色。隔离回归见 `test/bilibili-guard-roster.test.js`、`test/fan-profiles-guard-roster.test.js`、`test/fan-profiles-ipc.test.js`；执行与验收见 [实施计划](plans/archive/2026-09-18-fan-guard-roster.md)。

保持现有礼物 DTO、所有公开快照和授权行为。普通歌曲/全部业务流水清理保留粉丝档案，在清理界面明确说明；档案另有专用删除流程。无额外框架、服务、依赖或构建步骤。
